## 判定范围

每个符号只评价所引论文的设计，或所引官方文档明确描述的组件与配置。它不代表整个研究领域、厂商全部产品或任意第三方扩展。✓ 表示该机制提供该项能力，✗ 表示该机制不提供该项能力。

核对使用五篇论文的完整 PDF，逐项检查方法、算法、数据结构、更新流程和适用边界，并对容易混淆的段落检查了原始页面。产品能力使用官方文档；MAVRA 同时对照稿件与当前实现。否定项是根据这些机制的范围作出的归类，不把作者没有逐项写出否定声明，伪装成作者明确声明“不支持”。

## 各行依据

### AgentSM

来源：[作者原文 arXiv:2601.15709v1](https://arxiv.org/pdf/2601.15709v1)，9 页；主要依据 PDF 第 3–6 页，§3.1–3.3。

- **知识提取 ✓**：§3.2 对历史或合成轨迹进行步骤分类、语义标注和结构化，再按同库问题相似度检索。§3.3 使用反复出现的工具序列构造复合工具。
- **派生数据检查 ✗**：§3.1 的 schema linking 可以探查列、验证候选连接；SQL 工具也有失败后的自我修正。这些是任务执行中的操作，并未形成从复用定义派生的数据谓词集合。
- **共享检查结果 ✗**：§3.2 保存和检索的是轨迹片段；检索条件是数据库标识与问题相似度，不是数据谓词及其依赖版本。
- **快照对齐 ✗**：上述检索流程没有把轨迹内容绑定到消费查询的数据库快照。
- **数据更新处理 ✗**：轨迹复用流程不包含基表更新后对既有轨迹的依赖失效或重验。§3.1 关于共享记忆一致性的未来工作讨论是补充背景，不能单独当作所有数据库维护能力的否定证据。

措辞校正：第 4 页说明合成问题的答案没有经过评价，不能把 AgentSM 写成“只保存经过验证的成功轨迹”，也不能将轨迹复用写成学习可执行指标定义。

### G-Memory

来源：[NeurIPS 2025 正式论文 PDF](https://papers.neurips.cc/paper_files/paper/2025/file/136a45cd9b841bf785625709a19c6508-Paper-Conference.pdf)，31 页；主要依据第 3–6 页 §3–4.3，以及第 28–30 页的洞见提取和合并提示。

- **知识提取 ✓**：§4.2–4.3 从交互轨迹提取、合并洞见，并向角色分配相关记忆。
- **派生数据检查 ✗**：三层图的对象是交互、问题和洞见；洞见提取产生任务经验，而非数据库粒度或连接检查。
- **共享检查结果 ✗**：支持集合记录哪些问题支持某条洞见；它不是按数据库依赖版本索引的谓词检查结果。
- **快照对齐 ✗**：§4.1–4.2 的检索和记忆分配没有数据库快照绑定步骤。
- **数据更新处理 ✗**：§4.3 的更新由任务完成及环境反馈触发，更新图节点、边和洞见。这里的 memory update 不能归类为基表变化后的维护。

使用会议正式版的作者信息；不能用早期预印本的署名覆盖正式版。

### DataLab

来源：[作者原文 arXiv:2412.02205v3](https://arxiv.org/pdf/2412.02205v3)，14 页；核对 §IV–VI（第 5–8 页），包括 Algorithms 1–3。稿件引用 [ICDE 2025 正式发表记录](https://doi.org/10.1109/ICDE65448.2025.00326)；本次实际阅读全文的是公开作者版本 v3，没有把它称为 IEEE 排版终稿。

- **知识提取 ✓**：§IV-A、Algorithm 1 从 schema、SQL/Python 脚本历史和数据血缘提取元数据与业务计算逻辑。
- **派生数据检查 ✗**：Self-Calibration 使用 LLM 对提取内容评分；§IV-C 检查 DSL 的 JSON Schema。DSL 的 ConditionList 是筛选条件，不是从定义派生的粒度或连接不变量。
- **共享检查结果 ✗**：§V 的共享信息缓冲区存储角色、动作、描述、内容和时间戳；没有按数据库依赖版本复用此类谓词结论的结构。
- **快照对齐 ✗**：缓冲区时间戳记录任务信息；不能据此认定存在数据库事务快照协调。
- **数据更新处理 ✗**：§VI 的 DAG 在 notebook 单元创建、修改、删除后维护；§V 根据执行反馈替换过期信息。这两种更新都不能改写为基表 DML 驱动的业务知识维护。

因此可以保留四个 ✗，但不能在正文中泛称 DataLab“没有验证、没有更新”。

### dbt Semantic Layer / MetricFlow

来源：[About MetricFlow](https://docs.getdbt.com/docs/build/about-metricflow)、[Validations](https://docs.getdbt.com/docs/build/validation)、[Joins](https://docs.getdbt.com/docs/build/join-logic)、[Cache common queries](https://docs.getdbt.com/docs/use-dbt-semantic-layer/sl-cache)。以 2026-10-28 访问的官方文档为准。

- **知识提取 ✗**：本行评价声明式语义模型、查询引擎与缓存组件，输入是指标和实体定义；不将其他 AI 建模工具算入本行。
- **派生数据检查 ✗**：Parsing、Semantic syntax、Data platform 分别检查结构、语义图与生成 SQL 的可执行性；连接规划依赖声明的实体类型。它们不检查实际数据是否满足键唯一性等谓词。
- **共享检查结果 ✗**：缓存对象是查询结果，并非上述数据谓词的依赖版本化结论。
- **快照对齐 ✗**：所述声明式缓存按模型运行元数据判断新鲜度并选择缓存或源数据；这是失效策略，不是协调缓存与后续查询的数据库事务快照协议。不能进一步声称每次缓存命中都会读到不一致数据。
- **数据更新处理 ✓**：声明式缓存会失效并通过保存的查询作业重建。此项属于 dbt Semantic Layer 配置后的能力，因此行名明确写出平台；不能只写独立 MetricFlow 引擎却将平台能力直接归给它。

### Databricks metric views

来源：[Model metric views / Model star schemas](https://docs.databricks.com/aws/en/uc-semantics/metric-views/basic-modeling#model-star-schemas)、[Materialization for metric views](https://docs.databricks.com/aws/en/uc-semantics/metric-views/materialization)，访问日期 2026-10-28。

- **知识提取 ✗**：本行评价声明的指标视图及其物化组件。
- **派生数据检查 ✗**：`rely.at_most_one_match` 是被信任的声明，文档明确说该属性不在运行时验证；此结论不能扩大为“所有连接属性均不验证”。
- **共享检查结果 ✗**：物化数据不等于共享粒度／连接谓词的检查证据。
- **快照对齐 ✓、数据更新处理 ✓**：分别依据非聚合物化的一致快照能力与定时刷新；表下注明配置。这里的快照能力作用于该指标视图的数据，不能扩大成对任意跨视图查询的保证，也不等于保证每次查询都读最新数据。

### Semantic Data Caching and Replacement（Dar 等，1996）

来源：[VLDB 1996 正式论文 PDF](https://www.vldb.org/conf/1996/P330.PDF)，12 页，对应印刷页 330–341。

- **知识提取 ✗**：§2.4、§3（印刷页 333–335）保存的是区域描述及数据元组，不从执行轨迹提炼业务知识。
- **派生数据检查 ✗**：区域的 constraint formula 用于描述缓存内容、划分 probe/remainder query；不是粒度或连接有效性谓词。
- **共享检查结果 ✗**：§3.4 的状态是缓存区域、元组和替换优先级，没有此类谓词结论。
- **快照对齐 ✗、数据更新处理 ✗**：§2.1 使用只读查询；§4.2（印刷页 335）明确排除更新；§8（印刷页 341）将更新处理列为后续研究。

§7 还讨论了研究更新处理的其他缓存工作。因此表中必须标明“Dar et al., 1996”，不能把这行当作整个 semantic caching 领域的总结。

### TxCache

来源：[USENIX OSDI 2010 原文 PDF](https://www.usenix.org/legacy/events/osdi10/tech/full_papers/Ports.pdf)，14 页；重点核对 §2.1–2.2、§3–5.3（PDF 第 2–6 页）。

- **知识提取 ✗**：开发者标注纯函数，系统缓存函数结果；不是从历史轨迹学习指标定义。
- **派生数据检查 ✗**：系统自动计算结果有效时间区间、追踪失效标签；这些机制不等于生成粒度／连接数据谓词。
- **共享检查结果 ✗**：缓存保存的是应用计算结果及其有效区间；不提供本表限定的谓词结论共享机制。
- **快照对齐 ✓**：§2.2、§3、§4.1 把缓存访问和数据库访问限制到同一时间点；允许应用指定可接受的陈旧程度。
- **数据更新处理 ✓**：§4.2、§5.3 通过依赖标签和有序失效流，在写入后截断受影响缓存项的有效区间。

快照复用适用于只读事务；读写事务直接走数据库并绕过缓存。不能把 TxCache 的快照保证写成“始终最新”。
