# 共享记忆主线：贡献与证据定位

> 2026-10-04：本轮重构已回退，论文回到 `60d0783` 的主线（指标定义的有效性维护与使用时强制）。本文件保留为重构稿与补充实验的记录；重构稿源码见 `../exp/2026-10-03-shared-memory/overleaf-restructure-2026-10-03.tar.gz`，补充实验的去向见 [research-status.md](research-status.md)。

核心问题是：同一数据库与业务空间的用户侧智能体，能否复用其他智能体已经得到的知识，减少重复摸索，同时知道知识何时还适用，以及何种执行经验值得采纳为策略。当前原型把画像、关系与反例、业务指标和验证排序经验连接起来。

## 三项可评审贡献

1. 面向新用户侧智能体的共享知识接口。内容包括结构画像、字段的有来源元数据、已验证的隐含连接和反例、业务指标实现；不是每次重新附加完整对话。
2. 受证据约束的生命周期。事实发布、验证策略采纳和数据更新维护使用不同证据；最强的指标使用契约限定业务前提、已建模条件、声明修订及同快照执行。
3. 分离贡献来源的实验。主比较提供相同业务定义，生产者前缀匹配、消费者新会话、写回重置；另检验验证排序；原实验用于检验变化后的结构有效性、歧义修复和维护代价。

“给用户侧 agent 提供信息，节省前期摸索”应是核心消费者收益；能否成为差异化贡献，需要对照现有记忆与语义层，证明具体表示、维护规则及实验得到的效果。只证明缓存省数据库时间不足以支持整个主张。

## 论文需要保留的限制

- 来源学习的正确性判定依赖独立参考，部署仍需可信的业务依据或反馈；模型自信和多数意见不替代它。
- HTTP 工具直接积累画像和关系；指标发布由生产者评测程序调用，尚未接入无人参与的实时学习服务。
- 当前“更优策略”仅指验证检查顺序。正式策略实验匹配了测试集回顾最优固定顺序，尚未证明优于事先选好的强固定策略；完整审计采集成本也未摊入部署收益。
- 类型、注释和取值统计不等于每个字段独立的业务语义模型。目录诊断保留了注释更新和新增列的负结果；完整实时目录及业务词表同步仍需实现。
- 已建库消费者收益不含最初学习、提炼和准入；三流及重复题不支持宽泛显著性或其他领域、模型泛化。
- 普通版本缓存与定义级重验在配对维护中给出同样正确性和大量相近效率。本文应把类型化条目的解释、来源、失效责任和消费者约束写清楚。
