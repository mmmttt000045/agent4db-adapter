# 共享知识与策略记忆：补充研究协议

固定日期：2026-10-03。此协议在新增实验运行前写定；修改须保留原因和时间。旧指标实验保留，它们检验有效性维护，不代表整个共享记忆层的全部能力。

## 研究主张与范围

MAVRA 位于用户侧数据智能体与 PostgreSQL 之间，把多个智能体已经探查、验证或获得业务依据的数据库知识记录为带来源、依赖、适用条件及修订的共享状态。它提供表画像、隐含连接及反例、指标口径，并根据执行反馈选择验证策略。知识积累和数据库变化分别触发发布与维护。

“所有用户侧智能体”指接入同一数据库和业务空间且有权读取对应对象的智能体。字段的业务定义必须有显式题面、词表或确认依据；列名、共现或多数智能体的一致意见不构成业务真值。当前自适应策略仅为三类关联检查的顺序选择，不能写为一般 SQL 推理策略或任意工作流自动进化。表目录启动加载，DDL 后刷新整个目录目前不属于已实现保证。

## S1：相同生产者前缀下的时序积累

主比较：**隔离 / 冻结共享 / 持续积累 / 轨迹检索**。同一个重复内，生产者真实模型轨迹只生成一次，所有方法从相同轨迹前缀取知识，避免把学习随机性混入维护或表示的效果。

- 数据：合成零售，主实验 100,000 行销售；M1/M2/M3/M5，三个独立生产者流。指标引入顺序按重复循环轮换。每个指标最多使用原有两道学习题，首个定义成功发布后停止该指标的学习；失败、澄清和服务错误保留，不能按消费者表现重跑生产者。
- 每个前缀评测已引入指标的参数留出题；最终前缀额外评测全部题型留出题。所有主分析题面明确给出相同业务定义，用于探索成本比较；最后另运行仅报指标名的参数题，单独作为口径传递结果。
- 每道消费者题均为新的 agent/session。消费者答案和留出判题 SQL 不进入生产者提炼或发布；消费者写回在每次探针前恢复为既定生产者快照，故这是**生产者积累的配对实验**，不是消费者自训练。
- 隔离方法使用相同基础中间层工具与验证，但不能读取生产者条目；冻结方法始终读取首个前缀；持续积累方法读取当前前缀；轨迹检索读取当前结构知识及判题成功的原始任务轨迹，不提供指标检索接口。
- 各组同模型、相同步数上限、只读数据库及基础工具；关闭答案缓存和检查顺序自适应。方法顺序按前缀与重复轮换。
- 保留生产者逐任务模型、提炼及发布成本，按前缀报告，不能把已建库后的消费者收益写成包含首次学习的收益。生产者统一采集成本、方法实际所需提炼成本和消费者成本分别计量；未建立完整部署成本模型前不宣称精确盈亏平衡点。

主结果：正确率、每次尝试的模型往返、输入/输出 token、工具调用、明确的结构探查调用、SQL 探查调用、完整会话时间；同时报告每个正确答案的成本。按独立生产者流报告配对差，不把大量相关题当作独立重复。三个流只提供描述性证据。

此实验可以说明跨智能体共享及新知识覆盖是否减少后续任务的探索；**不能仅凭知识覆盖增长说明策略优化**。原始轨迹、全部失败、实际返回模型、配置、源码摘要和清理结果存档。

## S2：反馈驱动的验证策略选择

对当前已有 `Feedback` 实现单独检验。候选策略只改变 KeyUnique / RowConservation / SampleFanout 的顺序，验证结论和修复需求相同。训练候选、采纳证据候选、最后测试候选按时间分离且签名不重叠；评分器冻结后才能读取后来的采纳证据。

使用数据库实际执行的检查结果与计时做配对回放，比较默认顺序、反馈选择顺序及全部固定排列。报告采纳/拒绝次数、节省或增加的检查代价，以及为取得完整审计观测实际付出的成本。修复仍需键唯一性结果时，额外补查成本必须包含。回放不能宣称实时完整会话加速。有效候选与失败候选均保留，数据变化前后分别报告。

成功标准是未见候选上的成本改善且结论一致；若未采纳或不改善，就报告负结果，不另改负载挑选正结果。

## S3：共享状态的维护

复用现有配对回放、数据库更新场景、并发快照和修复歧义实验，重新解释为共享记忆的维护证据。表结构不变时也可能使关系和指标假设失效。对字段取值含义、未声明的知识使用、全面 DDL 目录刷新等未实现能力明确标注边界。

验收交付：重构后的英文和双语 LaTeX、PDF 与源码包；新增实验实现和分析脚本；原始记录、研究状态及结论—证据对应关系。任何未运行或失败的实验不得填入成功数值。

## S1 服务恢复重复（2026-10-03 18:30 UTC，运行前记录）

原三流按协议记录了完整 264 次消费者尝试，但末段按量额度耗尽：19 次主分析与 9 次命名题因 HTTP 402 失败。主分析中所有 197 次实际返回的答案均正确，因此 47/54 与 42/54 不能解释为推理准确率低；错误尝试的累计 token 也因当前错误路径而缺失。保留原始完整矩阵、全部错误和按全部尝试的统计，并另报事后服务完成配对的敏感性分析，不能用后者替代主分析。

只因服务不足启动一次完整的三流恢复重复，目录为 `results/shared-memory-recovery`。可用的既有 ClinePass 线路请求 `cline-pass/deepseek-v4.1-flash`，小试实际回报 `deepseek/deepseek-v4.1-flash`；继续强制接受这一准确模型名。仍用同一 API 端点、同一中间层二进制、high、100,000 行、四指标、20 轮、最多两次提炼及原有轮换顺序。生产者与全部消费者均重新生成，不能只重做答错题，也不把两轮的知识前缀、耗时或 token 混合。恢复重复的全部结果均保留，不因表现继续择优重跑。原轮与恢复轮分别报告；原轮额度失败不能算作方法优势，任何恢复轮服务失败仍计入。

该恢复重复在观察到原轮完整统计后决定，故不是事前声明的第二轮。其触发原因是可核查的 HTTP 402，而非消费者正确率或成本方向；恢复小试与完整清单一并归档。启动脚本新增运行前自动源码归档，不改变评测代码。

## 实验后代码与论证审计（2026-10-03 20:08 UTC）

最终原型补上事实表到一侧的连接方向约束，并使条件身份、定义比较及编译时过滤去重保留字符串值。真实 PostgreSQL 反例覆盖反向引用的金额放大，以及大小写／内部空格不同总体的唯一性。S1 两轮最终前缀共 25 个指标条目全部满足新方向约束；所有前缀的相关过滤均不含被旧规范化合并的这类字面量，审计记录单列。补丁发生在实验完成之后，原始二进制和源码归档不改写，不能把它们声明为用最终修正版重新运行。

论证明确左连接的空值补齐、多个聚合的组合、非空粒度键、业务总体与非时间内连接完备性前提，以及全表覆盖检查的范围。SQL 扫描仍是有限的执行前审查，不证明任意智能体 SQL 与指标定义等价。计时说明区分进程内模型工具循环和实际 HTTP 诊断。集成测试开发中的阶段预期错误及缺失批次表保留日志，修正的是测试程序；最终验收依赖修正版的完整测试，而非过滤失败记录。
