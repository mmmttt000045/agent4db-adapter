# 固定定义库的会话耗时分解（2026-10-03）

分析方案在计分运行前写定。对应 SMetric 阅读讨论后提出的问题：维护数据库工作减少，是否让完整 Agent 任务更快、更便宜地完成？

## 预定设计

- 固定库：场景主实验三个有效 MAVRA 运行 `dsv41flash-r1-b`、`dsv41flash-r2-b-rerun`、`dsv41flash-r3-a` 保存的 `cell-r1-metric-global-named.json`。排除已被替换的 r2-b；候选状态的条目按既有加载规则跳过。只导入被测 M1/M2/M3 及其全部同名变体；各库在全部方法中使用完全相同的有效定义，不重新学习、提炼或改变定义。每个方法的全部导入条目都须准入通过，否则中止该单元并报告。
- 方法：不共享 `no-share`、定义级重验 `definition`、通用版本缓存 `definition-cache`、MAVRA `condition`。不共享保留相同基础中间层工具，但不加载指标库；其余三组只改变维护方式。全部方法关闭答案结果缓存，固定候选级审计种子。
- 模型：继续使用项目当前已配置的订阅模型 `cline-pass/deepseek-v4.1-flash`，不更换模型。每次任务是一个全新 LLM 会话，题面仅给指标名。
- 数据：1,000,000 行合成门店销售。每个库一个隔离实验数据库，实验结束删除；不触碰已有实验库或模板库。
- 题目：M1、M2、M3 各一道参数留出题 P1。相同库、方法和阶段使用相同题目顺序（固定种子打乱）；各库轮换方法顺序。
- G8：默认用已保存 Agent 的示例 SQL（`--oracle example`）作为部署可得的修复参照。任务正确性仍由独立手写判题 SQL 判定；判题在计时之外，不送给模型。
- 阶段：`cold` 固定库加载/准入后的首次 Agent 使用；`warm` 在同一中间层再次使用；`after-append` 正常追加后首用；`after-status` 状态流水破坏后首用；`burst-status` 同一破坏后同时提交六个请求（每题两份），最多三个 LLM 会话同时执行，其余排队。
- `cold` 不是操作系统或数据库冷缓存，也不是重新学习定义。库启动/准入时间单列，首次任务耗时单列；正常与破坏性更新各自从内容指纹核对过的 v1 恢复后施加。所有写入在任务到达之前完成，与现有场景实验一致；本实验不评测并发写入和快照绑定。
- 完整矩阵：3 库 × 4 方法 ×（4 个串行阶段各 3 题 + 突发阶段 6 题）= **216 个会话**。最多两个库进程并行，因此总模型会话并发不超过六；具体运行并发和时间记录在运行日志中。

## 计量和分析

1. 主指标：任务完成时间（含突发阶段的入场排队）、正确率、每个正确答案的实际输入/输出 token 成本，以及 30/60/120 秒三个预先固定时限下的有效任务吞吐量。吞吐量分母为该方法该阶段的完整服务窗口，串行阶段逐题到达、突发阶段全批同时到达。
2. 耗时分解：LLM 调用（包括接口重试与退避）、探索工具、条件验证、受限修复（含回归）、在途合并等待、业务 SQL 执行、连接池等待、元数据与其他开销。采用请求局部的嵌套 span；按优先级切分为互斥时间区间，分解总和必须等于实测服务时间。不把同一段修复、其子查询和外层维护重复相加。
3. 数据库工作：SQL 按实际执行者计量；合并等待者只记等待，不重复计入领导请求的数据库工作。每阶段请求局部计量之和必须与全局阶段计量一致，否则运行报错。
4. 失败规则：保留所有运行请求、耗时和已完成 token，错误、澄清和无法解析的答案均不计为有效完成。接口失败单列；不以“服务端失败”为由删除慢请求或重跑计分题。基础设施导致单元没有完成时，原始部分输出保留，另行报告完整重跑。
5. 全部报告：分阶段与分库结果全部保存。固定库配对消除学习差异，但不消除 LLM 作答随机性或共享服务的时变延迟。仅三个独立库，P95 使用明确的经验分位数；不把多题当成独立库、不宣称统计显著。
6. 预先比较：MAVRA 对不共享的完整任务收益；MAVRA 对定义级的维护节省是否体现在任务完成时间；MAVRA 对通用版本缓存的剩余差异。若 LLM 主导时间或通用缓存接近 MAVRA，如实报告。

## 输出

`session-bench` 输出 `manifest.json`（方法与来源）、`sessions.jsonl`（逐请求结果、局部 SQL 工作、原始 span）、`trace-*.jsonl`（工具参数与结果摘要）、`report.json`（启动和阶段统计）。`tools/session-latency-stats.py` 生成汇总、互斥耗时分解、逐库结果、token 成本、三个时限下的有效吞吐与可独立导出的图。

完整结果见 [report.md](report.md)，原始数据与输入库在 `raw/`；大文件采用无损 gzip，分析脚本直接支持读取。主结果是：三个共享方法均答对 54/54（不共享 16/54）；MAVRA 更新后首用较快，但整体平均耗时和有效吞吐没有领先通用缓存。

已写入论文 Q5 的 [会话完成时间小节](../../overleaf/sections/evaluation/session-latency.tex) 与 [对照表](../../overleaf/tables/session-latency.tex)，英文和双语入口共用。`--tex-out overleaf/gen` 从相同原始记录生成正文数值宏与表格数据，不在论文中手抄结果。

论文两种入口已编译通过：英文 15 页（正文 13 页）、双语 23 页；增补前同环境的英文也是 15 页、正文 13 页。新实验为第 7.6.1 节、表 9；交叉引用正常，新小节与表格无越界排版。详见 [paper-check.json](verification/paper-check.json)。当前仍需整体压缩正文到项目的 12 页目标。
