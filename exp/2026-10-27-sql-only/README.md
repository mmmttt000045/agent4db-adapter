# RelBench：SQL-only 与 MAVRA 同批配对重跑

## 目的和设计

补充 [10-22 SQL-only 消融](../2026-10-22-sql-only/README.md)，检验只保存同一任务上一期成功、通过泄漏审计的完整 SQL，能否解释 RelBench 的复用收益。10-22 的 SQL-only／rel-stack 已完成，但其余组因网关异常中断；为避免混用不同代码和批次，这次四个单元全部从空记忆重新运行，旧结果保留且不并入本轮结论。

设计沿用 10-22 固定的协议：rel-stack 和 rel-trial，各三项任务、五个时间截点；每库一条到达顺序相同的时间序列，每截点三次会话，两个方法共 60 个会话。两组均使用 happycoding 的 `deepseek-v4.1-flash`，要求响应模型为 `deepseek/deepseek-v4.1-flash-1017`；thinking enabled，low。SQL-only 不运行提炼器，不提供结构化定义或跨任务组合；底层表描述、连接、查询缓存作用域、执行性检查、验证及泄漏审计与 MAVRA 相同。学习、提炼及失败成本按各方法实际发生计入。

两组遵循同一个停止**规则**，但从第二截点起的达标值由各组该任务自己的上期方案在本期重新拟合得到，不一定相同。每会话最多 40 次模型调用、8 次验证或连续两次无提升；达标后可再尝试一次改进，最多再用 5 次模型调用。验证使用 50,000 个训练种子，逐次泄漏审计使用 5,000 个种子；测试标签不反馈给智能体或记忆。

## 执行与证据

服务器为用户提供的 `root@10.10.2.31`（主机名 noctis）；独立目录 `/root/agentdb-sql-only-20261027`。复制 10-22 冻结的代码和二进制，替换为 10-22 已测试的网关空回复恢复版 `harness.py` 及其测试；两组使用完全相同的恢复代码。数据库原始文件和模板只读复用，结果写入独立目录 `results/sql-only-20261027/`。先运行 rel-stack 的两个单元，再运行 rel-trial 的两个单元；每阶段最多两个单元并行、每单元内存上限 24 GiB，空间低于 20 GiB 不启动新单元。每个阶段只有两个单元均完整、匹配并得到测试分数后才继续。

`run.sh` 在启动前测试 SQL-only 信息边界，检查数据库模板及模型工具调用往返，记录模型实际响应、依赖与源文件哈希，并归档执行源码。`gate.py` 只对完整的两个单元生成数据库级报告；`tools/relbench/sql-only-stats.py` 仅在两个数据库均完成后生成全量报告。任何中断、错误或缺失测试分数都不能作为完整实验结果。各阶段状态和原始日志保存在远端运行目录中。

报告需同时给出全部截点与截点 2–5 的 token（含学习）、调用次数、质量，以及逐截点和各任务数值；记录两组实际达标目标、泄漏和学习错误。共享服务器上的墙钟时间应单独解释。每库只有一条连续序列，不是五次独立重复，不能据此宣称统计显著性或统计非劣。

2026-10-27 预检：机器可访问、数据和模板目录存在，空回复修复的 8 项测试通过；实际网关地址为 `https://happycoding.xyz/v1`，短调用和工具往返返回预期模型。实验于北京时间 20:29 启动，20:30 进入 rel-stack 配对阶段。[preflight.json](preflight.json) 保存实际模型响应与模板检查，[run-provenance.json](run-provenance.json) 保存本次代码、输入和二进制哈希。运行前的源码归档保存在远端结果目录；本 README 随运行状态更新，因此其当前内容与归档中的启动时版本不同。正式结果以本目录后续同步的运行记录及原始单元为准。

[legacy-diagnostic.md](legacy-diagnostic.md) 单独核对了已完成的旧 SQL-only／rel-stack 和历史 MAVRA 数据；由于跨批次、跨网关，它们只作为描述性诊断，不并入本次配对结果。

[verified-results.md](verified-results.md) 列出两个时间范围、逐截点成本、全部任务质量与事后敏感性；[verified-results.json](verified-results.json) 另保存逐会话数据与目标。用 `python -X utf8 exp/2026-10-27-sql-only/analyze-results.py` 可从本机原始文件重新核验并生成报告，不写入论文。分析核对 60 个会话和 4 个运行文件的哈希、58 个源码归档文件及 4 个输入清单／时间线的哈希，检查实际模型、两组设置、截点、审计、测试分数和 token 账目。
