## 事后敏感性分析

rel-trial 的 site-success 截点 4：SQL-only 使用 2,600,137 token（38 次 LLM 调用、8 次验证）；上一期 SQL 两次重拟合均因 600 秒 SQL 超时，故该会话无目标。对应 MAVRA 使用 97,006 token（7 次 LLM 调用、1 次验证），且有目标。
事后仅为衡量这一对会话的影响，若从各自 12 个复用会话中暂时排除此对，SQL-only 为 2,190,227 token，MAVRA 为 2,273,223 token，MAVRA 相对+3.8%；这不是替代主结果的预设分析。

## 核验与解释

核验 64 个已归档哈希（60 个会话和 4 个 run.json），以及 58 个源码归档文件和 4 个输入清单／时间线；所有会话的模型标识、成本账目、干净审计和测试分数均通过检查，未发现学习错误。两组各自在上一期方案上设定目标，规则一致但目标值不一定一致。

- rel-stack：12 个复用会话中，12 个两组目标均存在，其中 12 个目标值不同；0 个至少一组目标缺失。
- rel-trial：12 个复用会话中，10 个两组目标均存在，其中 10 个目标值不同；2 个至少一组目标缺失。

每库每组只有一条随时间推进的序列；数据展示描述性成本与质量差异，不能视为独立重复、统计显著性或统计非劣。该对照比较完整 MAVRA 与只保存任务 SQL 的方案，未单独隔离结构化定义、跨任务共享和维护各自的作用。与论文原有 DeepSeek 官方 API 主实验分开报告。
