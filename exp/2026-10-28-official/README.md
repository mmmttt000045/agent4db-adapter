## 开发、冻结与公平比较

所有配置见 `protocol.json`。开发集是 rel-amazon/user-churn 的前两个截点，两个候选在看到结果前确定：原实现与更紧凑的复用策略。候选先验证已有完整方案，再按需取跨任务定义；对已发布且SQL逐字相同、当前再次通过验证和审计的方案不重复提炼。它仍执行所有验证与泄漏检查。

开发过程不计算或使用测试分数，测试标签不会暴露给智能体或配置选择器。公共种子加载器会在宿主进程读入测试文件，但传给数据库的测试种子只保留实体和时间列；开发专用评估只计算验证集。只有开发任务全部完成、审计均通过、各截点验证AUC不低于原实现0.01且总 token 更少时，才采用候选；否则保留原实现。选择结果写入 `selection.json`，正式测试中不再调参。开发数据不算主实验结果。

正式比较：无记忆参照、MAVRA、ACE、AWM、G-Memory，rel-stack/rel-trial 各三个任务、前三个截点、每方法一条独立序列。共90个计划会话。三种已有记忆方法沿用 `tools/relbench/harness.py` 和10-20复现说明中的官方代码/提示词适配，不使用 `src/agentmem.rs` 中早期不完整的重实现。DeepPrep、FeatPilot 的原结果仍独立保留；本轮不宣称已重跑它们。

所有方法统一24次模型调用、5次验证、达标后最多3次调用/一次改进，5万个训练种子、**600秒特征SQL语句上限**、5000种子泄漏审计；工具调用HTTP超时为180秒。22:14源码核验发现，Python函数默认参数在导入时绑定为600秒，修改模块常量不会同步改变该默认值；早先把特征SQL上限记录为180秒有误，实际所有组都使用600秒。只修正记录并新增运行值核验，不在正式实验中途切换上限。模型调用/验证预算比旧实验紧，因此新旧结果不能混用。学习和记忆操作均计费、计入 token。正式测试标签不反馈给智能体。

本轮修复了公共框架中“审计报错却当作无泄漏”的漏洞，对所有组均要求审计明确为clean才可成为最佳验证方案。官方DeepSeek的推理内容回传由provider判断，保证经过本机费用闸门时仍正确回传。现有8项SQL-only边界测试及5项费用计算测试已通过；SQL-only不纳入本轮外部基线。
