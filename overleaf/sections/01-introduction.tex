\section{\bt{Introduction}{引言}}
\label{sec:introduction}
\bi{A data agent answers an analytical question by exploring the database: it lists tables, inspects values, tests joins, and settles on SQL over many LLM turns. Exploration is where the time and tokens go, and it is repeated. Agents on the same database rediscover the same knowledge in every session: which fact rows a metric aggregates, which records count as one business event, and how tables join. In our traces, 93\% of the lookups of new agent sessions repeat a fact that an earlier session had already obtained, while none of the repeated SQL probes repeats its text, so a query cache serves none of them (Section~\ref{sec:workload-characterization}).}
{数据智能体通过探索数据库来回答分析问题：在多轮大模型调用中列出表、查看取值、检验连接，最后确定 SQL。时间和 token 都花在探索上，而且探索是重复的。同一数据库上的智能体在每个会话里重新发现同样的知识：一个指标聚合哪些事实行，哪些记录算作一次业务事件，表之间如何连接。在我们记录的会话中，新会话 93\% 的查找都在重复此前会话已经得到的事实，而重复的 SQL 探查没有一条文本相同，因此查询缓存一条也服务不了（第~\ref{sec:workload-characterization} 节）。}

\bi{Agent memory does not remove this repetition, because it is organized per agent. Memory systems keep an agent's conversations and facts~\cite{chhikara2025mem0,packer2023memgpt}, induce workflows and strategies from its own trajectories~\cite{wang2025awm,zhao2024expel,ouyang2026reasoningbank}, or evolve its context~\cite{zhang2026ace,xu2025amem}; for text-to-SQL, AgentSM turns a system's past trajectories into semantic memory and leaves shared memory to future work~\cite{biswal2026agentsm}. With per-agent memory, every new agent pays for the same exploration again, so the cost grows with the number of agents rather than with the amount of knowledge. Yet the agents of an organization query the same tables and ask about the same metrics, and agent-first data systems call for a persistent memory that serves many agents~\cite{liu2026agents}.}
{智能体记忆并不能消除这种重复，因为它是按智能体组织的。现有记忆系统保存一个智能体的对话与事实~\cite{chhikara2025mem0,packer2023memgpt}，从它自己的轨迹中归纳工作流与策略~\cite{wang2025awm,zhao2024expel,ouyang2026reasoningbank}，或演化它的上下文~\cite{zhang2026ace,xu2025amem}；在 Text-to-SQL 上，AgentSM 把一个系统过去的轨迹整理成语义记忆，并把共享记忆留作未来工作~\cite{biswal2026agentsm}。在单智能体记忆下，每个新来的智能体都要为同样的探索再付一次代价，代价随智能体数量增长，而不是随知识量增长。然而一个组织里的智能体查询的是同一批表、问的是同一批指标，面向智能体的数据系统也呼吁一种为众多智能体服务的持久记忆~\cite{liu2026agents}。}

\bi{We argue that the memory of data agents belongs with the database and is shared by every agent that queries it: one agent explores, and every later agent, whatever it asks, reuses what was learned. Figure~\ref{fig:example} shows the idea on one metric, store revenue. One agent learns its definition once (step~1); \system\ publishes it (step~2), and every later agent answers questions about any month, difference, or ranking with the generated SQL instead of exploring (step~4).}
{我们认为，数据智能体的记忆应当放在数据库一侧，由查询它的所有智能体共享：一个智能体探索，之后的每个智能体无论问什么，都复用已经学到的东西。图~\ref{fig:example} 以一个指标——门店营业额——说明这一点。一个智能体学一次它的定义（第 1 步）；\system\ 发布它（第 2 步）；之后每个智能体回答任何月份、差值或排名的问题时，都用生成的 SQL 代替探索（第 4 步）。}

\bi{Sharing on a database raises three problems that per-agent memory does not face. \emph{Transfer:} agents ask different questions, so what is shared must be knowledge, a definition separated from question parameters, not queries or results. \emph{Correctness under change:} a definition that one agent learned is correct only while unstated data properties hold. The SQL learned in step~1, \code{SUM(ss\_net\_paid)} over a month's sales, is correct because each ticket--item key identifies one sale; when a restatement later keeps old sales as non-current rows (step~5), no table or column changes and the SQL still runs, but it counts restated sales twice and returns 14,300,525.64 for September instead of 12,932,888.04. The agents that reuse it never saw the data it was learned from: only 16\% of the sessions in our traces check key uniqueness, and every wrong answer came from SQL that ran without error, so a memory that only stores and retrieves turns one stale definition into a wrong answer for every agent. \emph{The cost of correctness:} if every agent verified what it reads, sharing would lose what it saves; a retrieval agent told to verify grain, joins, and date keys spends \AmVerifyExtraS\,s and \AmVerifyExtraTokK\,k tokens more per question even on unchanged data, and still answers only \DsTrajVerifyModeled\% correctly under breaking changes. Checks, repairs, and optimizations must therefore run once, when the data changes, and serve every agent.}
{在数据库上共享带来单智能体记忆不会遇到的三个问题。\emph{可迁移：}智能体问的问题各不相同，因此共享的必须是知识，即与题目参数分开的定义，而不是查询或结果。\emph{变化下的正确性：}一个智能体学到的定义只在一些未写明的数据性质成立时才正确。第 1 步学到的 SQL（对一个月的销售求 \code{SUM(ss\_net\_paid)}）之所以正确，是因为每个小票--商品键对应一笔销售；之后一次更正把旧销售行保留为非当前行（第 5 步）：表和列都没有变，SQL 照常执行，却把被更正的销售算了两次，9 月返回 14,300,525.64，而正确值是 12,932,888.04。复用它的智能体从未见过它赖以成立的数据：我们记录的会话中只有 16\% 检查键唯一性，所有错误答案都来自执行成功的 SQL，因此只负责存储和检索的记忆会把一个过期的定义变成每个智能体的错误答案。\emph{正确性的代价：}如果每个智能体都核验自己读到的内容，共享省下的就会被抵消；被要求核对粒度、连接与日期键的检索智能体，即使数据不变，每题也多花 \AmVerifyExtraS\ 秒和 \AmVerifyExtraTokK\,k token，在破坏性变化下仍只答对 \DsTrajVerifyModeled\%。因此，检查、修复与优化必须在数据变化时只做一次，并服务所有智能体。}

\bi{\system\ (\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents) is a shared memory layer between data agents and a SQL database that solves the three problems once for all agents. For transfer, it shares numbered revisions of metric definitions that it learns from the agents' own successful sessions; a revision is published only after the publication checks replay the generated SQL that other agents will read, and it answers any period, difference, or ranking. For correctness, each revision carries executable conditions derived from its structure, which we prove sufficient for the generated SQL to count each business event once in its period (Proposition~\ref{prop:sufficiency}); a failed condition leads to a unique repair that is regression-tested as of learning time (steps~5--7) or to invalidation, and a query uses a revision only on a snapshot on which its conditions hold. For cost, check results are keyed by the condition and the versions of the tables it reads, so one check serves every definition and every agent that needs it (Lemma~\ref{lem:reuse}), and because every agent reuses the same SQL, a cheaper equivalent revision speeds up all of them (step~3, Proposition~\ref{prop:rewrite}). To our knowledge, \system\ is the first memory that independent data agents share and that is kept correct against the changing database it describes.}
{\system（\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents，面向智能体的指标感知验证与复用）是位于数据智能体与 SQL 数据库之间的共享记忆层，为所有智能体一次性地解决这三个问题。针对可迁移，它共享指标定义的带编号版本，这些版本从智能体自己的成功会话中学来；只有在发布前检查重放了其他智能体将要读到的生成的 SQL 之后才发布，并能回答任意期间、差值或排名。针对正确性，每个版本带有从其结构推出的可执行条件，我们证明这些条件足以让生成的 SQL 把每个业务事件在其期间内只计数一次（命题~\ref{prop:sufficiency}）；条件失败则导致唯一的、按学习时刻做回归测试的修复（第 5--7 步）或失效；查询只在版本条件成立的快照上使用该版本。针对代价，检查结果按条件与其所读表的版本索引，一次检查服务所有需要它的定义与智能体（引理~\ref{lem:reuse}）；由于所有智能体复用同一份 SQL，一个更省的等价版本让所有智能体都更快（第 3 步，命题~\ref{prop:rewrite}）。据我们所知，\system\ 是第一个由相互独立的数据智能体共享、并针对其所描述的不断变化的数据库保持正确的记忆。}

\bi{We evaluate the cost of sharing directly. When \PpAgents\ agents arrive at one TPC-DS database and ask a mix of questions, \system\ uses \PpMavraTokSaveNone\% fewer tokens than agents without memory and its agents finish \PpMavraSpeedupNone$\times$ faster; against single-agent memory built with the same learning and checks, it uses \PpMavraTokSavePrivate\% fewer tokens and is \PpMavraSpeedupPrivate$\times$ faster, because each metric is explored once instead of once per agent. Once a metric is learned, an agent answers with \PpMavraLateTokXNone$\times$ fewer tokens and \PpMavraLateSpeedupNone$\times$ faster than exploring alone, and more answers are correct (\PpMavraAcc\% against \PpNoneAcc\% and \PpPrivateAcc\%). Sharing examples of past sessions saves as much on unchanged data but hands stale SQL to every agent after an update: after a restatement, \system's agents answer \PpMavraChangeAcc\% correctly and those of example retrieval \PpTrajChangeAcc\%, and under the breaking changes the conditions cover on two schemas, \system\ keeps \DsCondModeled--\GeCondModeled\% of answers correct against \GeTrajModeled--\DsTrajModeled\%. Each part of the design is needed: replacing any one of them with the usual alternative costs tokens and time or serves wrong answers (Table~\ref{tab:ablation}). The evaluation covers four schemas, including a real bank database, with \PpSessions\ agent sessions in the population study, \ScenValidTasks\ scored questions end to end, and the replay of \RpLibs\ learned and \TrSeeded\ plus \GnSeeded\ benchmark-derived libraries.}
{我们直接测量共享的代价。当 \PpAgents\ 个智能体陆续使用同一 TPC-DS 数据库、提出各种问题时，\system\ 比无记忆的智能体少用 \PpMavraTokSaveNone\% 的 token，其智能体快 \PpMavraSpeedupNone\ 倍；与用同样的学习与检查构建的单智能体记忆相比，少用 \PpMavraTokSavePrivate\% 的 token、快 \PpMavraSpeedupPrivate\ 倍，因为每个指标只探索一次，而不是每个智能体探索一次。指标学会之后，智能体每题比独自探索少用 \PpMavraLateTokXNone\ 倍 token、快 \PpMavraLateSpeedupNone\ 倍，答对的也更多（\PpMavraAcc\%，后两者为 \PpNoneAcc\% 与 \PpPrivateAcc\%）。共享以往会话的示例在数据不变时省下同样多的工作，但更新之后会把过期的 SQL 交给每个智能体：一次更正之后，\system\ 的智能体答对 \PpMavraChangeAcc\%，示例检索为 \PpTrajChangeAcc\%；在两种模式上条件覆盖的破坏性变化下，\system\ 保持 \DsCondModeled--\GeCondModeled\% 的答案正确，示例检索为 \GeTrajModeled--\DsTrajModeled\%。设计的每一部分都是必要的：把任何一部分换成常见的替代做法，要么多花 token 和时间，要么给出错误答案（表~\ref{tab:ablation}）。评估覆盖四种模式（包括一家银行的真实数据库）：群体实验 \PpSessions\ 个智能体会话，端到端 \ScenValidTasks\ 道计分题，以及对 \RpLibs\ 个学到的定义库和由基准导出的 \TrSeeded\ 加 \GnSeeded\ 个定义的回放。}

\bi{This paper makes the following contributions:}
{本文的贡献如下：}
\begin{itemize}
\item \bi{We show that data agents repeat knowledge rather than queries, so that neither query caches nor per-agent memory remove their repeated exploration, and we identify the three problems that sharing on a database must solve: transfer, correctness under change, and the cost of correctness (Section~\ref{sec:background}).}
{我们表明数据智能体重复的是知识而不是查询，因此查询缓存与单智能体记忆都无法消除它们重复的探索；并指出在数据库上共享必须解决的三个问题：可迁移、变化下的正确性与正确性的代价（第~\ref{sec:background} 节）。}
\item \bi{We design \system, a memory shared by all agents of a database, which learns metric definitions from the agents' sessions and publishes them only after checking the SQL that other agents will read (Sections~\ref{sec:overview} and~\ref{sec:shared-object}).}
{我们设计了 \system：一个由数据库的所有智能体共享的记忆。它从智能体的会话中学习指标定义，只在检查其他智能体将要读到的 SQL 之后才发布（第~\ref{sec:overview} 与~\ref{sec:shared-object} 节）。}
\item \bi{We keep shared knowledge correct and cheap once for all agents: executable conditions proved sufficient for a definition's aggregate, check results shared under a reuse rule proved sound, unique repair regression-tested as of learning time, same-snapshot validation at query execution, and optimization revisions proved equivalent wherever their conditions hold (Section~\ref{sec:model}).}
{我们为所有智能体一次性地让共享知识保持正确且便宜：经证明足以保证定义聚合正确的可执行条件，在经证明可靠的复用规则下共享的检查结果，按学习时刻做回归测试的唯一修复，执行时的同快照验证，以及经证明在其条件成立时等价的优化版本（第~\ref{sec:model} 节）。}
\item \bi{We measure what sharing saves and what keeps it correct (Section~\ref{sec:evaluation}): across a population of agents against no memory, single-agent memory, and shared examples; per question on two schemas; under eleven data changes end to end; by replaying fixed libraries on four schemas; under concurrent writes; and by removing each part of the design.}
{我们测量共享省下了什么、又是什么让它保持正确（第~\ref{sec:evaluation} 节）：在一群智能体上与无记忆、单智能体记忆和共享示例比较；在两种模式上按每道题比较；端到端经历十一种数据变化；在四种模式上回放固定定义库；在并发写入下测试；以及逐一去掉设计的各部分。}
\end{itemize}
