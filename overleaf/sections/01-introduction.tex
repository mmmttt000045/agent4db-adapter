\section{\bt{Introduction}{引言}}
\label{sec:introduction}
\bi{A data agent answers an analytical question by exploring the database: it lists tables, inspects values, tests joins, and settles on SQL over many turns. Agents on the same database repeat this exploration, and what they rediscover is knowledge rather than queries: which fact rows a metric aggregates, which records count as one business event, and how tables join (Section~\ref{sec:workload-characterization}). Much of it cannot be recovered from the data alone: enterprise warehouses name columns in terms only domain experts understand~\cite{floratou2024nl2sql}, and expert-annotated evidence raises GPT-4's execution accuracy on BIRD from 34.9\% to 54.9\%~\cite{li2023bird}. Systems therefore keep what one agent learned for later agents: metric layers let engineers declare definitions~\cite{databricks2026metricviews}, business-intelligence systems derive them from script histories~\cite{weng2025datalab}, and agent-first data systems propose a persistent memory that serves many agents~\cite{liu2026agents,biswal2026agentsm}. In our study, agents that reuse shared definitions answer \DsCondHoldout\% of held-out questions instead of \DsNoShareHoldout\%, \AmHoldSpeedup$\times$ faster.}
{数据智能体通过探索数据库来回答分析问题：多轮列出表、查看取值、检验连接，最后确定 SQL。同一数据库上的智能体反复进行这种探索，而它们重新发现的是知识而不是查询：一个指标聚合哪些事实行，哪些记录算作一次业务事件，表之间如何连接（第~\ref{sec:workload-characterization} 节）。其中很多知识无法只从数据中恢复：企业数仓的列名使用只有领域专家才懂的术语~\cite{floratou2024nl2sql}，专家标注的证据使 GPT-4 在 BIRD 上的执行正确率从 34.9\% 提高到 54.9\%~\cite{li2023bird}。因此，系统开始把一个智能体学到的东西保存给后来的智能体：指标层让工程师声明定义~\cite{databricks2026metricviews}，商业智能系统从脚本历史中推导定义~\cite{weng2025datalab}，面向智能体的数据系统提出为众多智能体服务的持久记忆~\cite{liu2026agents,biswal2026agentsm}。在我们的实验中，复用共享定义的智能体答对 \DsCondHoldout\% 的留出题（独自探索为 \DsNoShareHoldout\%），而且快 \AmHoldSpeedup\ 倍。}

\bi{Sharing, however, turns what one agent observed into a premise for other agents. Figure~\ref{fig:example} follows one shared definition, store revenue. The SQL learned in step~1, \code{SUM(ss\_net\_paid)} over a month's sales, is correct because on the data the agent explored each ticket--item key identifies one sale and each date key joins one date; the SQL states neither, and the schema enforces neither. When a restatement later keeps old sales as non-current rows (step~5), no table or column changes and the SQL still runs, but it counts restated sales twice and returns 14,300,525.64 for September instead of 12,932,888.04. The agents that reuse the definition never saw its evidence and learn nothing from a successful execution. Such data-only updates are routine~\cite{kimball2013toolkit}, and even a hand-declared join property in a commercial metric layer ``is not validated at runtime''~\cite{databricks2026metricviews}. A memory that only stores and retrieves hands every consumer the same wrong answer.}
{然而，共享把一个智能体的观测变成了其他智能体的前提。图~\ref{fig:example} 跟踪一个共享定义：门店营业额。第 1 步学到的 SQL（对一个月的销售求 \code{SUM(ss\_net\_paid)}）之所以正确，是因为在智能体探索的数据上，每个小票--商品键对应一笔销售，每个日期键连接到一个日期；这两点 SQL 没有写明，表结构也不强制。之后一次多版本更正把旧销售保留为非当前行（第 5 步）：表和列都没有变，SQL 照常执行，却把被更正的销售算了两次，9 月返回 14,300,525.64，而正确值是 12,932,888.04。复用这个定义的智能体从未见过它的证据，从一次成功的执行中也看不出问题。这类纯数据更新是日常操作~\cite{kimball2013toolkit}；即使是商用指标层中人工声明的连接性质，也“不在运行时验证”~\cite{databricks2026metricviews}。只负责存储和检索的记忆，会把同一个错误答案交给每一个使用者。}

\bi{This memory differs from the conversational, factual, and procedural memories of agent systems~\cite{chhikara2025mem0,wang2025awm,zhang2026ace}: it describes an external database that changes without anyone editing the memory, its producers and consumers are different agents, and its validity is partly decidable by queries over that database. Consumers cannot vouch for what they read: only 16\% of the sessions in our traces check key uniqueness, every wrong answer came from SQL that ran without error, and telling agents to verify validity themselves lifts example retrieval only from \DsTrajModeled\% to \DsTrajVerifyModeled\% under breaking changes. Existing safeguards cover parts of the problem: invalidation on schema change misses data-only breaks, and data-validation pipelines~\cite{schelter2018deequ,breck2019validation,dbt2026tests} test hand-declared constraints per table without knowing which knowledge depends on them.}
{这种记忆与智能体系统保存的对话、事实和流程记忆~\cite{chhikara2025mem0,wang2025awm,zhang2026ace}不同：它描述一个外部数据库，不需要任何人修改记忆，数据库的变化就可能让它变错；它的生产者与使用者是不同的智能体；它的有效性又可以部分地由该数据库上的查询判定。使用者无法为自己读到的内容担保：我们的轨迹中只有 16\% 的会话检查键唯一性，所有错误答案都来自执行成功的 SQL；让智能体自己核验有效性，在破坏性变化下也只把示例检索的正确率从 \DsTrajModeled\% 提高到 \DsTrajVerifyModeled\%。现有保障手段只覆盖其中一部分：只在模式变更时失效会漏掉纯数据破坏，数据验证管道~\cite{schelter2018deequ,breck2019validation,dbt2026tests}按表测试人工声明的约束，却不知道哪些知识依赖它们。}

\bi{The shared memory must therefore be a layer that checks once for all consumers, and it must answer three questions together. \emph{What may be published?} A successful task mixes reusable business meaning with question parameters and incidental observations; the layer must check what other agents will read rather than what the producer ran. \emph{When may a use rely on it?} A passed check describes one snapshot: under concurrent writers, check-then-execute answers on condition-violating data in up to \SnPreUnannMax\% of uses. \emph{Who keeps it valid and improves it?} A repair can restore one row per key while selecting the wrong population, and the only regression reference a deployment has, the producer's SQL, is valid only on the snapshot it was written for; a rewrite that is equivalent today may rely on a property that tomorrow's data breaks.}
{因此，共享记忆必须是一层，替所有使用者统一检查，并同时回答三个问题。\emph{什么可以发布？}一次成功的任务中混杂着可复用的业务含义、题目参数和偶然的观测；这一层要检查其他智能体将要读到的内容，而不是生产者当时执行的内容。\emph{一次使用何时可以依赖它？}一次通过的检查只描述一个快照：存在并发写入时，先检查后执行会让最多 \SnPreUnannMax\% 的使用在违反条件的数据上作答。\emph{由谁保持它有效、由谁改进它？}修复可以恢复每个键一行，却选中错误的总体，而部署中唯一的回归参照，即生产者写的 SQL，只在它所针对的快照上成立；今天等价的改写，可能依赖一个明天的数据会破坏的性质。}

\bi{\system\ (\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents) answers these questions with one abstraction, a versioned \emph{revision} of a definition that carries executable conditions derived from its structure: filtered key uniqueness for the grain, cardinality and completeness for each join, and the date role. Together with the definition's business premises, they make the canonical SQL count every business event exactly once in its period, up to the omissions that completeness bounds (Proposition~\ref{prop:sufficiency}). \emph{Publication} (steps~1--2 of Figure~\ref{fig:example}): admission separates definition filters from question parameters and replays the canonical SQL that consumers will read. \emph{Reliance} (step~4): a query declares the revisions it uses and runs in a snapshot on which their conditions hold, reusing check results whose transactional versions match the snapshot (Lemma~\ref{lem:reuse}). \emph{Maintenance and improvement} (steps~3 and~5--7): a check result is keyed by the condition's canonical form and the versions of the tables it reads, so it serves every definition and agent that needs it; a failed condition invalidates the revision, and repair publishes only the unique fix that reproduces the producer's answer as of learning time (Algorithm~\ref{alg:repair}); a cheaper rewrite is adopted only when the maintained conditions, including any premise it adds, imply its equivalence, and the layer falls back when that premise breaks (Proposition~\ref{prop:rewrite}).}
{\system（\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents，面向智能体的指标感知验证与复用）用一个抽象回答这些问题：定义的版本化\emph{修订}，它带着由其结构推出的可执行条件，即粒度对应过滤后键唯一性，每个连接对应连接基数与连接完整性，另有日期角色。与定义的业务前提一起成立时，这些条件使规范 SQL 把每个业务事件在其期间内恰好计数一次，遗漏仅限于完整性所约束的部分（命题~\ref{prop:sufficiency}）。\emph{发布}（图~\ref{fig:example} 第 1--2 步）：准入把定义过滤与题目参数分开，并重放使用者将要读到的规范 SQL。\emph{依赖}（第 4 步）：查询声明所用的修订，在这些修订的条件成立的快照中执行，事务性版本与快照一致的检查结果直接复用（引理~\ref{lem:reuse}）。\emph{维护与改进}（第 3、5--7 步）：检查结果按条件的规范形式及其读取表的版本索引，因此服务于所有需要该条件的定义和智能体；条件失败使修订失效，修复只发布按学习时刻复现生产者答案的唯一修复（算法~\ref{alg:repair}）；更省的改写只有在受维护的条件（包括它新增的前提）蕴含其等价时才采纳，前提被破坏时这一层回退（命题~\ref{prop:rewrite}）。}

\bi{This paper makes the following contributions:}
{本文的贡献如下：}
\begin{itemize}
\item \bi{A shared memory layer for data agents that takes over publication, reliance, and maintenance and improvement, built on revisions with executable validity conditions that we prove sufficient (Sections~\ref{sec:overview} and~\ref{sec:model}).}
{一个数据智能体的共享记忆层，承担发布、依赖以及维护与改进，建立在带有可执行有效性条件的修订之上，我们证明这些条件是充分的（第~\ref{sec:overview} 和~\ref{sec:model} 节）。}
\item \bi{Use-time enforcement that binds every declared use to evidence on its own snapshot, with a check-result reuse rule that we prove sound (Section~\ref{sec:execution}).}
{使用时的强制保证：把每一次声明了修订的使用绑定到其自身快照上的证据，检查结果的复用规则经我们证明是可靠的（第~\ref{sec:execution} 节）。}
\item \bi{Maintenance and improvement as a shared service: revalidation per condition, unique as-of repair, and rewrites whose equivalence the maintained conditions imply (Section~\ref{sec:maintenance}).}
{把维护与改进做成共享的服务：条件级重验证、按学习时刻的唯一修复，以及受维护条件蕴含其等价的改写（第~\ref{sec:maintenance} 节）。}
\item \bi{An evaluation that separates the value of sharing from that of maintenance (Section~\ref{sec:evaluation}): on fixed libraries, maintained definitions serve no wrong answer under the covered changes, whereas invalidation on schema change serves \RpSchemaWrongModeled; end to end, maintained memory answers \DsCondModeled\% under the covered breaking changes, against \DsTrajModeled\% for example retrieval, which is as accurate on unchanged data.}
{一套把共享的价值与维护的价值分开测量的评估（第~\ref{sec:evaluation} 节）：在固定的定义库上，维护后的定义在条件覆盖的变化下不给出错误答案，只在模式变更时失效则给出 \RpSchemaWrongModeled\ 个；端到端实验中，维护后的记忆在条件覆盖的破坏性变化下答对 \DsCondModeled\%，数据不变时同样准确的示例检索为 \DsTrajModeled\%。}
\end{itemize}
