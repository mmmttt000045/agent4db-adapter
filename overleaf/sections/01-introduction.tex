\section{\bt{Introduction}{引言}}
\label{sec:introduction}
\bi{Data agents answer analytical questions and build predictive features through repeated schema inspection, value probes, and join tests. These steps recur across sessions over the same database because business meanings, grain, filters, and joins are rarely explicit in a schema. In our metric traces, 57\% of LLM calls issue no SQL used by the answer, and 71\% of session time precedes the answer query. Section~\ref{sec:workload-characterization} quantifies the repeated knowledge in public benchmarks and our traces.}
{数据智能体通过反复检查模式、探查取值并验证连接，回答分析问题和构建预测特征。由于业务含义、粒度、过滤和连接很少在模式中明确给出，同一数据库上的会话会重复这些步骤。在我们的指标轨迹中，57\% 的 LLM 调用不发出答案所用的 SQL，71\% 的会话时间发生在答案查询之前。第~\ref{sec:workload-characterization} 节量化公开基准与我们轨迹中的知识重复。}

\bi{For example, Agent A learns that store revenue sums each ticket--item sale once; Agent B reuses that definition for September. When a restatement retains old versions, unchanged SQL double-counts sales. Figure~\ref{fig:metric-record} shows why reusable definitions need checked conditions and a repair-or-revoke policy.}
{例如，智能体 A 学到门店收入对每个票据--商品销售只求和一次；智能体 B 为九月复用这一定义。当更正保留旧版本时，未修改的 SQL 会重复计入销售。图~\ref{fig:metric-record} 说明可复用定义为何需要可检查的条件，以及修复或撤销的策略。}

\bi{Recent systems reduce repeated exploration from different angles: per-agent memories retain facts and workflows~\cite{chhikara2025mem0,packer2023memgpt,wang2025awm,zhao2024expel,ouyang2026reasoningbank,zhang2026ace,xu2025amem}, G-Memory shares textual trajectories within a multi-agent team~\cite{zhang2025gmemory}, AgentSM synthesizes trajectories and composite tools for text-to-SQL~\cite{biswal2026agentsm}, DataLab extracts calculation logic from historical scripts~\cite{weng2025datalab}, and metric layers centralize hand-written definitions~\cite{dbt2026metricflow,databricks2026metricviews}. However, text- and trajectory-based memories still require consumer agents to translate retrieved context into SQL for new periods or tasks, while reused SQL and extracted logic lack executable data conditions binding their validity to the underlying tables. Consequently, a data update can silently invalidate shared knowledge without triggering any SQL execution error.}
{近期系统从不同角度减少重复探索：单智能体记忆保存事实与工作流~\cite{chhikara2025mem0,packer2023memgpt,wang2025awm,zhao2024expel,ouyang2026reasoningbank,zhang2026ace,xu2025amem}，G-Memory 在多智能体团队内共享文本轨迹~\cite{zhang2025gmemory}，AgentSM 为 Text-to-SQL 合成轨迹与复合工具~\cite{biswal2026agentsm}，DataLab 从历史脚本提取计算逻辑~\cite{weng2025datalab}，指标层集中管理人工编写的定义~\cite{dbt2026metricflow,databricks2026metricviews}。然而，基于文本与轨迹的记忆仍要求消费者智能体为新的期间或任务把检索到的上下文转化为 SQL，而复用的 SQL 和提取的逻辑缺少将其有效性绑定到底层表的可执行数据条件。因此，数据更新可能悄然使共享知识失效，却不触发任何 SQL 执行错误。}

\bi{We place shared memory at the database boundary, so definitions learned in one session can serve other agents on the same database. The database exposes both invalidating writes and the snapshot on which a query uses a definition. Three requirements follow: \emph{reusable definitions} must support new periods and question forms; \emph{shared upkeep} must amortize learning and validation across agents; and \emph{validity under updates} must prevent silent errors without discarding all knowledge on every write. Section~\ref{sec:overview} presents the architecture.}
{我们把共享记忆放在数据库边界，使一个会话学得的定义能服务同库其他智能体。数据库同时提供可能使定义失效的写入信息，以及查询使用定义的快照。由此得到三项要求：\emph{定义可复用}，须支持新的期间和提问形式；\emph{维护共享}，须在智能体之间分摊学习与验证代价；\emph{更新后仍有效}，须防止静默错误，同时避免每次写入都丢弃全部知识。第~\ref{sec:overview} 节介绍架构。}

\bi{\system\ (\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents) implements these requirements as a shared metric and feature layer. It extracts structured definitions from verified agent sessions, publishes numbered revisions after deterministic checks, and compiles them for new questions. Each revision carries executable conditions derived from its grain and joins; we establish their sufficiency for aggregation under explicit business assumptions (Proposition~\ref{prop:sufficiency}). Condition results are shared by dependency version (Lemma~\ref{lem:reuse}), and queries use them on their own snapshots. Repairs and equivalent rewrites are published once for all consumers (Proposition~\ref{prop:rewrite}). Unlike manually maintained metric layers~\cite{dbt2026metricflow,databricks2026metricviews}, this layer is populated through agent use and checked against changing data. Text-to-SQL agents consume its definitions through the same database interface.}
{\system{}（\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents）以共享指标和特征层实现这些要求。它从核实的智能体会话提取结构化定义，经确定性检查发布带编号的版本，再为新问题编译查询。每个版本携带从粒度和连接推导的可执行条件；我们在明确的业务前提下证明这些条件对聚合的充分性（命题~\ref{prop:sufficiency}）。条件结果按依赖版本共享（引理~\ref{lem:reuse}），查询在自己的快照上使用它们。修复与等价重写各发布一次，供所有消费者使用（命题~\ref{prop:rewrite}）。不同于人工维护的指标层~\cite{dbt2026metricflow,databricks2026metricviews}，该层由智能体使用过程构建，并针对变化的数据检查。Text-to-SQL 智能体通过同一数据库接口消费其定义。}

\bi{We evaluate periodic retraining using two databases from RelBench~\cite{robinson2024relbench} against no memory, ACE~\cite{zhang2026ace}, G-Memory~\cite{zhang2025gmemory}, AWM~\cite{wang2025awm}, DeepPrep~\cite{fan2026deepprep}, and FeatPilot~\cite{liang2025featpilot}. From the second cutoff onward, \system\ reduces tokens by \RbStackMavraTokSave\% on rel-stack and \RbTrialMavraTokSave\% on rel-trial relative to no memory, and by \RbStackMavraVsBest\% and \RbTrialMavraVsBest\% relative to the most token-efficient agent memory on each database. Mean test scores remain comparable to the no-memory baseline across all six tasks. On TPC-DS, sharing across \PpAgents\ agents reduces tokens by \PpMavraTokSaveNone\% relative to no memory and \PpMavraTokSavePrivate\% relative to private memory with the same learning and checks. After a restatement, accuracy is \PpMavraChangeAcc\% with \system\ and \PpNoneChangeAcc\% without memory.}
{我们在两个 RelBench 数据库上评估定期重训~\cite{robinson2024relbench}，比较无记忆、ACE~\cite{zhang2026ace}、G-Memory~\cite{zhang2025gmemory}、AWM~\cite{wang2025awm}、DeepPrep~\cite{fan2026deepprep} 与 FeatPilot~\cite{liang2025featpilot}。从第二个截点起，\system\ 相对无记忆在 rel-stack 和 rel-trial 上分别减少 \RbStackMavraTokSave\% 和 \RbTrialMavraTokSave\% 的 token，相对各库最省 token 的智能体记忆分别减少 \RbStackMavraVsBest\% 和 \RbTrialMavraVsBest\%。六个任务的平均测试分数均保持与无记忆基线相当的预测质量。在 TPC-DS 上，\PpAgents\ 个智能体共享记忆，相对无记忆减少 \PpMavraTokSaveNone\% 的 token，相对采用相同学习和检查的私有记忆减少 \PpMavraTokSavePrivate\%。一次更正后，\system\ 准确率为 \PpMavraChangeAcc\%，无记忆为 \PpNoneChangeAcc\%。}

\bi{The contributions are:}{本文的贡献如下：}
\begin{itemize}
\item \bi{Evidence from public benchmarks and agent traces that reusable database knowledge, rather than identical SQL, drives repeated exploration (Section~\ref{sec:background}).}{通过公开基准与智能体轨迹说明，重复探索源于可复用的数据库知识，而非相同 SQL（第~\ref{sec:background} 节）。}
\item \bi{A shared layer that learns metric and temporally bounded feature definitions from verified sessions (Sections~\ref{sec:overview} and~\ref{sec:model}).}{从核实会话学习指标定义及受时间边界约束的特征定义的共享层（第~\ref{sec:overview}、\ref{sec:model} 节）。}
\item \bi{Conditions for aggregation correctness, sound reuse of snapshot-bound checks, and shared repair and equivalent rewrites (Section~\ref{sec:model}).}{聚合正确性条件、绑定快照的检查结果的可靠复用，以及共享修复与等价重写（第~\ref{sec:model} 节）。}
\item \bi{Evaluation of token cost, predictive quality, maintenance, and update robustness on RelBench, TPC-DS, and TPC-H (Section~\ref{sec:evaluation}).}{在 RelBench、TPC-DS 与 TPC-H 上评估 token 代价、预测质量、维护及更新鲁棒性（第~\ref{sec:evaluation} 节）。}
\end{itemize}
