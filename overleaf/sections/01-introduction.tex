\section{\bt{Introduction}{引言}}
\label{sec:introduction}
\bi{A data agent answers an analytical question by exploring the database: it lists tables, inspects values, tests joins, and settles on SQL over many LLM turns. Exploration is where the time and tokens go. Of the 12.67 SQL statements that an o3 agent issues per task, 7.00 explore tables and columns, and expert hints such as which column holds the relevant information cut the statements by 18\%~\cite{liu2026agents}. In the sessions we recorded, 57\% of an agent's LLM calls issue neither the SQL that its answer uses nor the answer, and 71\% of a session passes before that SQL starts; on TPC-DS, an agent without memory spends \PpNoneLateSteps\ LLM calls, \PpNoneLateTools\ tool calls, \PpNoneLateTokK\,k tokens, and \PpNoneLateS\,s on a single metric question. And the exploration is repeated, because tasks on one database need the same knowledge: which fact rows a metric aggregates, which records count as one business event, and how tables join. The public benchmark LiveSQLBench documents this knowledge for each of its databases~\cite{livesqlbench2025}: \ExLsSharePct\% of the tasks that need documented knowledge share it with another task on the same database, and the more tasks a database serves, the more of the knowledge that a new task needs was already needed before, \ExLsTenth\% for the 10th task on a database and \ExLsTwentieth\% for the 20th. On BIRD~\cite{li2023bird}, \ExBdSharePct\% of the questions share a defined term with another question on the same database. Each such task is answered by a new agent session that explores the knowledge again, and in our sessions no SQL probe that repeats a fact repeats the text of an earlier one, so a query cache serves none of them (Section~\ref{sec:workload-characterization}).}
{数据智能体通过探索数据库来回答分析问题：在多轮大模型调用中列出表、查看取值、检验连接，最后确定 SQL。时间和 token 都花在探索上。o3 智能体每个任务平均发出 12.67 条 SQL，其中 7.00 条用于查看表和列；专家给出提示（例如哪一列包含相关信息）后，SQL 减少 18\%~\cite{liu2026agents}。在我们记录的会话中，智能体 57\% 的大模型调用既不发出答案所用的 SQL，也不给出答案，会话 71\% 的时间都在这条 SQL 开始之前；在 TPC-DS 上，没有记忆的智能体回答一道指标题要 \PpNoneLateSteps\ 次大模型调用、\PpNoneLateTools\ 次工具调用、\PpNoneLateTokK\,k token 和 \PpNoneLateS\ 秒。而且探索是重复的，因为同一数据库上的任务需要同样的知识：一个指标聚合哪些事实行、哪些记录算作一次业务事件、表之间如何连接。公开基准 LiveSQLBench 为它的每个数据库记录了这类知识~\cite{livesqlbench2025}：在需要这些知识的任务中，\ExLsSharePct\% 与同库另一任务共用知识；而且一个库服务的任务越多，新任务所需的知识中此前已被需要过的就越多，库上第 10 个任务为 \ExLsTenth\%，第 20 个为 \ExLsTwentieth\%。在 BIRD~\cite{li2023bird} 上，\ExBdSharePct\% 的问题与同库另一问题共用一个被定义的术语。每个这样的任务都由一个新的智能体会话回答，它把这些知识重新探索一遍；而在我们记录的会话中，重复事实的 SQL 探查没有一条与先前探查的文本相同，因此查询缓存一条也服务不了（第~\ref{sec:workload-characterization} 节）。}

\bi{Agent memory does not remove this repetition, because it is organized per agent. Memory systems keep an agent's conversations and facts~\cite{chhikara2025mem0,packer2023memgpt}, induce workflows and strategies from its own trajectories~\cite{wang2025awm,zhao2024expel,ouyang2026reasoningbank}, or evolve its context~\cite{zhang2026ace,xu2025amem}; for text-to-SQL, AgentSM turns a system's past trajectories into semantic memory and leaves shared memory to future work~\cite{biswal2026agentsm}. With per-agent memory, every new agent pays for the same exploration again: with $N$ agents asking about $k$ metrics, the agents explore up to $N\cdot k$ times, so the cost grows with the number of agents rather than with the amount of knowledge. Yet the agents of an organization query the same tables and ask about the same metrics, and agent-first data systems call for a persistent memory that serves many agents~\cite{liu2026agents}. Sharing today's memories does not answer this call. They store text about an agent's work, namely facts, strategies, notes, and plans, which an agent must still turn into SQL over tables it has not inspected, so it still explores; and nothing in them records which data a stored item depends on, so a change of the data silently makes the item wrong for every agent that reads it.}
{智能体记忆并不能消除这种重复，因为它是按智能体组织的。现有记忆系统保存一个智能体的对话与事实~\cite{chhikara2025mem0,packer2023memgpt}，从它自己的轨迹中归纳工作流与策略~\cite{wang2025awm,zhao2024expel,ouyang2026reasoningbank}，或演化它的上下文~\cite{zhang2026ace,xu2025amem}；在 Text-to-SQL 上，AgentSM 把一个系统过去的轨迹整理成语义记忆，并把共享记忆留作未来工作~\cite{biswal2026agentsm}。在单智能体记忆下，每个新来的智能体都要为同样的探索再付一次代价：$N$ 个智能体问 $k$ 个指标，最多要探索 $N\cdot k$ 次，代价随智能体数量增长，而不是随知识量增长。然而一个组织里的智能体查询的是同一批表、问的是同一批指标，面向智能体的数据系统也呼吁一种为众多智能体服务的持久记忆~\cite{liu2026agents}。把现有记忆直接共享并不能满足这一要求。它们保存的是关于智能体工作的文字，即事实、策略、笔记和计划；智能体仍要在尚未查看过的表上把这些文字变成 SQL，因此仍然要探索；而且其中没有记录一条内容依赖哪些数据，数据一变，它就悄悄地对每个读到它的智能体都变成错的。}

\bi{We argue that the memory of data agents belongs with the database and is shared by every agent that queries it: one agent explores, and every other agent, whatever it asks, answers with one SQL (Figure~\ref{fig:architecture}). The database is the right place for this memory: every agent already passes through it, so what one agent learns can reach all of them; it sees every write, so it can tell when shared knowledge breaks; and it can check that knowledge and run the query on the same snapshot. The agents then explore $k$ times instead of $N\cdot k$. Three requirements decide whether sharing actually saves. \emph{One exploration serves every agent:} the knowledge one agent found must answer the questions that other agents ask about the same metric, for other periods and in other forms, whereas a query or result cache serves only exact repeats. \emph{Upkeep is paid once:} learning, checking, and maintaining shared knowledge must be paid once per definition, not once per agent; an agent told to verify the grain, joins, and date keys of the shared SQL it reads spends \AmVerifyExtraS\,s and \AmVerifyExtraTokK\,k tokens more per question even on unchanged data. \emph{The savings survive data changes:} a learned definition is correct only while unstated data properties hold. The SQL \code{SUM(ss\_net\_paid)} over a month's sales is correct because each ticket--item key identifies one sale; when a restatement keeps old sales as non-current rows, the SQL still runs but counts restated sales twice, returning 14,300,525.64 for September instead of 12,932,888.04. A stale shared definition hands every agent a wrong answer, and discarding shared knowledge on every write sends every agent back to exploring, \ScenRelearnTok\,M tokens of relearning per run in our study.}
{我们认为，数据智能体的记忆应当放在数据库一侧，由查询它的所有智能体共享：一个智能体探索，其他每个智能体无论问什么，都用一条 SQL 作答（图~\ref{fig:architecture}）。数据库是放置这种记忆的合适位置：每个智能体本来就要经过它，一个智能体学到的东西可以到达所有智能体；它看得到每一次写入，因此知道共享知识何时失效；它还能在同一个快照上检查这些知识并执行查询。于是智能体只需探索 $k$ 次，而不是 $N\cdot k$ 次。共享能否真正省下代价，取决于三个要求。\emph{一次探索服务所有智能体：}一个智能体找到的知识，必须能回答其他智能体就同一指标提出的问题，包括其他期间与其他问法，而查询缓存与结果缓存只能服务完全相同的重复。\emph{维护只付一次：}学习、检查和维护共享知识的代价必须每个定义只付一次，而不是每个智能体付一次；被要求核对所读共享 SQL 的粒度、连接与日期键的智能体，即使数据不变，每题也多花 \AmVerifyExtraS\ 秒和 \AmVerifyExtraTokK\,k token。\emph{节省经得起数据变化：}学到的定义只在一些未写明的数据性质成立时才正确。对一个月的销售求 \code{SUM(ss\_net\_paid)} 之所以正确，是因为每个小票--商品键对应一笔销售；一次更正把旧销售行保留为非当前行之后，SQL 照常执行，却把被更正的销售算了两次，9 月返回 14,300,525.64，而正确值是 12,932,888.04。过期的共享定义会把错误答案交给每个智能体，而每次写入就丢弃共享知识又会把每个智能体送回去重新探索，在我们的实验中每次运行要为重新学习花 \ScenRelearnTok\,M token。}

\bi{\system\ (\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents) is a shared memory layer between data agents and a SQL database that meets the three requirements. It learns numbered revisions of metric definitions from the agents' own successful sessions and compiles a revision into the SQL for any period, difference, or ranking, so one exploration answers every later agent with one query. It pays for everything around a definition once for all agents: the publication checks replay the generated SQL that other agents will read, check results are keyed by the condition and the versions of the tables it reads so that one check serves every definition and every agent that needs it (Lemma~\ref{lem:reuse}), a broken definition is repaired once, and a cheaper equivalent revision, once published, speeds up every agent that runs it (Proposition~\ref{prop:rewrite}). It keeps the savings valid as the data changes: each revision carries executable conditions derived from its structure, which we prove sufficient for the generated SQL to count each business event once in its period (Proposition~\ref{prop:sufficiency}), and a query uses a revision only on a snapshot on which its conditions hold. To our knowledge, \system\ is the first memory that independent data agents share and that stays valid against the changing database it describes. In data-system terms, \system\ is a metric layer that the agents build from their own sessions and that the database keeps valid, whereas today's metric layers are written by engineers and not checked at run time~\cite{dbt2026metricflow,databricks2026metricviews}. It does not compete with text-to-SQL: an agent that writes SQL for questions, as every agent in our evaluation does, is the consumer of the memory, and the same agent without memory is our baseline.}
{\system（\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents，面向智能体的指标感知验证与复用）是位于数据智能体与 SQL 数据库之间、满足这三个要求的共享记忆层。它从智能体自己的成功会话中学习指标定义的带编号版本，并把版本编译成任意期间、差值或排名的 SQL，因此一次探索可以让之后的每个智能体用一条查询作答。定义周边的一切代价都为所有智能体只付一次：发布前检查重放其他智能体将要读到的生成的 SQL；检查结果按条件与其所读表的版本索引，一次检查服务所有需要它的定义与智能体（引理~\ref{lem:reuse}）；失效的定义只修复一次；更省的等价版本一经发布，每个执行它的智能体都更快（命题~\ref{prop:rewrite}）。它让节省在数据变化时依然有效：每个版本带有从其结构推出的可执行条件，我们证明这些条件足以让生成的 SQL 把每个业务事件在其期间内只计数一次（命题~\ref{prop:sufficiency}），查询只在版本条件成立的快照上使用该版本。据我们所知，\system\ 是第一个由相互独立的数据智能体共享、并针对其所描述的不断变化的数据库保持有效的记忆。用数据系统的话说，\system\ 是一个由智能体从自己的会话中建立、由数据库保持有效的指标层，而现有的指标层由工程师手写、运行时不做检查~\cite{dbt2026metricflow,databricks2026metricviews}。它与 Text-to-SQL 并不竞争：为问题编写 SQL 的智能体（我们实验中的每个智能体都是如此）是记忆的使用者，同一个智能体不带记忆就是我们的基线。}

\bi{We measure the savings directly. When \PpAgents\ agents arrive at one TPC-DS database and ask a mix of questions, \system\ uses \PpMavraTokSaveNone\% fewer tokens than agents without memory and its agents finish \PpMavraSpeedupNone$\times$ faster. The saving grows as agents arrive (\PpMavraTokSaveNoneNFour\% after four agents, \PpMavraTokSaveNoneNEight\% after eight), because the first agents pay for learning and every later agent reuses: once a metric is learned, an agent answers with \PpMavraLateSteps\ LLM calls and \PpMavraLateTools\ tool calls instead of \PpNoneLateSteps\ and \PpNoneLateTools, with \PpMavraLateTokXNone$\times$ fewer tokens and \PpMavraLateSpeedupNone$\times$ faster, and more answers are correct (\PpMavraAcc\% against \PpNoneAcc\%). The saving follows how often questions reuse knowledge: these agents answer \ExModelReusePct\% of their questions from shared definitions, and at the repetition of LiveSQLBench our cost model still predicts \ExModelTokSaveLs\% to \ExModelTokSaveLsTwentieth\% fewer tokens (Section~\ref{sec:alternatives}). Single-agent memory built with the same learning and checks saves little, since few agents ask again about what they themselves learned; \system\ uses \PpMavraTokSavePrivate\% fewer tokens than it and is \PpMavraSpeedupPrivate$\times$ faster. Per question, a reusing agent is also \GeHoldSpeedup$\times$ faster with \GeHoldTokSave\% fewer tokens on TPC-H. Sharing keeps its own cost small: one maintenance per definition needs \PpMavraMaintS\,s of database time where per-agent copies need \PpPrivateMaintS\,s, and one optimization makes the SQL of every agent \OptSaveMean\% faster on average. After a restatement, \system's agents still answer \PpMavraChangeAcc\% correctly with \PpMavraChangeTokK\,k tokens per question, against \PpNoneChangeAcc\% at \PpNoneChangeTokK\,k tokens without memory.}
{我们直接测量节省。当 \PpAgents\ 个智能体陆续使用同一 TPC-DS 数据库、提出各种问题时，\system\ 比无记忆的智能体少用 \PpMavraTokSaveNone\% 的 token，其智能体快 \PpMavraSpeedupNone\ 倍。节省随智能体到来而增长（4 个智能体后为 \PpMavraTokSaveNoneNFour\%，8 个后为 \PpMavraTokSaveNoneNEight\%），因为最先到来的智能体为学习付出代价，之后的每个智能体都复用：指标学会之后，智能体每题只需 \PpMavraLateSteps\ 次大模型调用、\PpMavraLateTools\ 次工具调用，而不是 \PpNoneLateSteps\ 次、\PpNoneLateTools\ 次，少用 \PpMavraLateTokXNone\ 倍 token、快 \PpMavraLateSpeedupNone\ 倍，答对的也更多（\PpMavraAcc\%，无记忆为 \PpNoneAcc\%）。节省取决于问题复用知识的频繁程度：这些智能体有 \ExModelReusePct\% 的题从共享定义作答；按 LiveSQLBench 的重复程度，我们的代价模型仍预测 token 少用 \ExModelTokSaveLs\%--\ExModelTokSaveLsTwentieth\%（第~\ref{sec:alternatives} 节）。用同样的学习与检查构建的单智能体记忆省得很少，因为很少有智能体会再问自己学过的指标；\system\ 比它少用 \PpMavraTokSavePrivate\% 的 token、快 \PpMavraSpeedupPrivate\ 倍。按每道题计，复用记忆的智能体在 TPC-H 上也快 \GeHoldSpeedup\ 倍、少用 \GeHoldTokSave\% 的 token。共享本身的代价很小：每个定义维护一次需要 \PpMavraMaintS\ 秒数据库时间，按智能体分别保存的副本需要 \PpPrivateMaintS\ 秒；一次优化让每个智能体的 SQL 平均快 \OptSaveMean\%。一次更正之后，\system\ 的智能体仍答对 \PpMavraChangeAcc\%，每题 \PpMavraChangeTokK\,k token；无记忆为 \PpNoneChangeAcc\%、每题 \PpNoneChangeTokK\,k token。}

\bi{This paper makes the following contributions:}
{本文的贡献如下：}
\begin{itemize}
\item \bi{We show on two public benchmarks that tasks on one database need the same knowledge, increasingly so as tasks accumulate, and in recorded sessions that data agents spend their time and tokens exploring this knowledge again rather than repeating queries, so that neither query caches nor per-agent memory remove the cost, and we state the three requirements under which sharing saves: one exploration for every agent, upkeep paid once, and savings that survive data changes (Section~\ref{sec:background}).}
{我们在两个公开基准上表明，同一数据库上的任务需要同样的知识，且任务越多越是如此；并在记录的会话中表明，数据智能体把时间和 token 花在重新探索这些知识而不是重复查询上，因此查询缓存与单智能体记忆都消除不了这部分代价；并给出共享能够省下代价的三个要求：一次探索服务所有智能体、维护只付一次、节省经得起数据变化（第~\ref{sec:background} 节）。}
\item \bi{We design \system, a memory shared by all agents of a database that learns metric definitions from their sessions and turns every later question about a learned metric into one SQL (Sections~\ref{sec:overview} and~\ref{sec:shared-object}).}
{我们设计了 \system：一个由数据库的所有智能体共享的记忆，它从智能体的会话中学习指标定义，把之后关于已学指标的每个问题变成一条 SQL（第~\ref{sec:overview} 与~\ref{sec:shared-object} 节）。}
\item \bi{We keep the cost of sharing small and its savings valid by doing the work around a definition once for all agents: check results shared under a reuse rule proved sound, conditions proved sufficient for a definition's aggregate, repair once, and optimization revisions proved equivalent wherever their conditions hold (Section~\ref{sec:model}).}
{我们为所有智能体一次性完成定义周边的工作，使共享的代价很小、节省保持有效：在经证明可靠的复用规则下共享的检查结果，经证明足以保证定义聚合正确的条件，一次修复，以及经证明在其条件成立时等价的优化版本（第~\ref{sec:model} 节）。}
\item \bi{We measure the time and tokens that sharing saves (Section~\ref{sec:evaluation}): across a population of agents against no memory and single-agent memory; per question on two schemas; for the cost of sharing itself; and under data changes.}
{我们测量共享省下的时间和 token（第~\ref{sec:evaluation} 节）：在一群智能体上与无记忆和单智能体记忆比较；在两种模式上按每道题比较；测量共享本身的代价；以及在数据变化下的表现。}
\end{itemize}
