\section{\bt{Introduction}{引言}}
\label{sec:introduction}
\bi{A data agent answers an analytical question by exploring the database: it lists tables, inspects values, tests joins, and settles on SQL over many turns. Agents on the same database repeat this exploration, and what they rediscover is knowledge rather than queries: which fact rows a metric aggregates, which records count as one business event, and how tables join (Section~\ref{sec:workload-characterization}). Much of it cannot be recovered from the data: enterprise warehouses name columns in terminology that only domain experts understand~\cite{floratou2024nl2sql}, and expert-annotated evidence raises GPT-4's execution accuracy on BIRD from 34.9\% to 54.9\%~\cite{li2023bird}. Systems are therefore converging on keeping what one agent learned for later agents: metric layers let engineers declare definitions~\cite{databricks2026metricviews}, business-intelligence systems derive them from script histories~\cite{weng2025datalab}, and agent-first data systems propose a persistent memory that serves many agents~\cite{liu2026agents,biswal2026agentsm}. The payoff is large: in our study, agents that reuse shared definitions answer \DsCondHoldout\% of held-out questions instead of \DsNoShareHoldout\%, \AmHoldSpeedup$\times$ faster.}
{数据智能体通过探索数据库来回答分析问题：多轮列出表、查看取值、检验连接，最后确定 SQL。同一数据库上的智能体反复进行这种探索，而它们重新发现的是知识而不是查询：一个指标聚合哪些事实行，哪些记录算作一次业务事件，表之间如何连接（第~\ref{sec:workload-characterization} 节）。其中很多知识无法从数据中恢复：企业数仓的列名使用只有领域专家才懂的术语~\cite{floratou2024nl2sql}，专家标注的证据使 GPT-4 在 BIRD 上的执行正确率从 34.9\% 提高到 54.9\%~\cite{li2023bird}。因此，系统正在向“把一个智能体学到的东西保存给后来的智能体”靠拢：指标层让工程师声明定义~\cite{databricks2026metricviews}，商业智能系统从脚本历史中推导定义~\cite{weng2025datalab}，面向智能体的数据系统提出为众多智能体服务的持久记忆~\cite{liu2026agents,biswal2026agentsm}。收益很大：在我们的实验中，复用共享定义的智能体答对 \DsCondHoldout\% 的留出题（独自探索为 \DsNoShareHoldout\%），而且快 \AmHoldSpeedup\ 倍。}

\bi{Sharing, however, turns one agent's observation into other agents' premise. The SQL an agent learns for store return amount, \code{SUM(sr\_return\_amt)}, is correct because, on the snapshot it explored, a ticket--item key identifies one completed return, the joins do not fan out, and the return date assigns each return to its period; the SQL states none of this, and the schema enforces none of it. When an ETL change later appends an application-state row for each new return, no table or column changes and the SQL still runs, but it counts many returns twice, returning 6,588,699.86 for one period instead of 3,294,349.93. The agents that reuse the definition never saw its evidence and learn nothing from a successful execution. Such data-only updates are routine~\cite{kimball2013toolkit}, and even a hand-declared join property in a commercial metric layer ``is not validated at runtime''~\cite{databricks2026metricviews}. A memory that only stores and retrieves hands every consumer the same wrong answer.}
{然而，共享把一个智能体的观测变成了其他智能体的前提。智能体为门店退货金额学到的 SQL \code{SUM(sr\_return\_amt)} 之所以正确，是因为在它探索的快照上，小票--商品键对应一笔已完成的退货，连接不放大行数，退货日期把每笔退货归入其期间；这些性质 SQL 一条也没写明，表结构一条也不强制。之后一次 ETL 改动为每笔新退货追加一条申请状态记录：表和列都没有变，SQL 照常执行，却把许多退货计算了两次，某个期间返回 6,588,699.86，而正确值是 3,294,349.93。复用这个定义的智能体从未见过它的证据，从一次成功的执行中也看不出问题。这类纯数据更新是日常操作~\cite{kimball2013toolkit}；即使是商用指标层中人工声明的连接性质，也“不在运行时验证”~\cite{databricks2026metricviews}。只负责存储和检索的记忆，会把同一个错误答案交给每一个使用者。}

\bi{This memory differs from the conversational, factual, and procedural memories of agent systems~\cite{chhikara2025mem0,wang2025awm,zhang2026ace}. It describes an external database that changes without anyone editing the memory. Its producers and consumers are different agents, so a consumer cannot vouch for what it reads: only 16\% of the sessions in our traces check key uniqueness, and every wrong answer came from SQL that ran without error. And its validity is partly decidable by queries over that database, so the layer that holds it can check once for all consumers and enforce the outcome where the knowledge is used. Existing safeguards cover parts of this: invalidation on schema change misses data-only breaks, data-validation pipelines~\cite{schelter2018deequ,breck2019validation,dbt2026tests} test hand-declared constraints per table without knowing which knowledge depends on them, and agent memories leave the consistency of shared memory open~\cite{biswal2026agentsm,liu2026agents}. Telling agents to verify validity themselves lifts example retrieval only from \DsTrajModeled\% to \DsTrajVerifyModeled\% under breaking changes.}
{这种记忆与智能体系统保存的对话、事实和流程记忆~\cite{chhikara2025mem0,wang2025awm,zhang2026ace}不同。它描述一个外部数据库，不需要任何人修改记忆，数据库的变化就可能让它变错。它的生产者与使用者是不同的智能体，因此使用者无法为自己读到的内容担保：我们的轨迹中只有 16\% 的会话检查键唯一性，所有错误答案都来自执行成功、没有报错的 SQL。它的有效性又可以部分地由该数据库上的查询判定，因此保存它的那一层能够替所有使用者统一检查，并在知识被使用处执行检查的结论。现有保障手段只覆盖其中一部分：只在模式变更时失效会漏掉纯数据破坏，数据验证管道~\cite{schelter2018deequ,breck2019validation,dbt2026tests}按表测试人工声明的约束，却不知道哪些知识依赖它们，智能体记忆则把共享记忆的一致性留作开放问题~\cite{biswal2026agentsm,liu2026agents}。让智能体自己核验有效性，在破坏性变化下只把示例检索的正确率从 \DsTrajModeled\% 提高到 \DsTrajVerifyModeled\%。}

\bi{The shared memory must therefore be a layer that takes over what each consumer would otherwise check alone, and it must answer three questions together. \emph{What may be published?} A successful task mixes reusable business meaning with question parameters and incidental observations; the layer must publish only the reusable part, with the evidence and conditions that justify it, and check what other agents will read rather than what the producer ran. \emph{When may a use rely on it?} A passed check describes one snapshot, and a write can commit between the check and the query that relies on it: under concurrent writers, check-then-execute answers on condition-violating data in up to \SnPreUnannMax\% of uses. \emph{Who keeps it valid and improves it?} Maintenance must be paid once for all consumers, yet both ways of changing shared knowledge are risky. A repair can restore one row per key while selecting the wrong population, and the only regression reference a deployment has, the producer's SQL, is valid only on the snapshot it was written for; a rewrite that is equivalent today may rely on a property that tomorrow's data breaks.}
{因此，共享记忆必须是一层，由它承担原本要由每个使用者各自检查的部分，并同时回答三个问题。\emph{什么可以发布？}一次成功的任务中混杂着可复用的业务含义、题目参数和偶然的观测；这一层只能发布可复用的部分，连同支撑它的证据和条件，并且要检查其他智能体将要读到的内容，而不是生产者当时执行的内容。\emph{一次使用何时可以依赖它？}一次通过的检查只描述一个快照，写入可能在检查与依赖它的查询之间提交：存在并发写入时，先检查后执行会让最多 \SnPreUnannMax\% 的使用在违反条件的数据上作答。\emph{由谁保持它有效、由谁改进它？}维护必须为所有使用者只付一次，而改变共享知识的两种方式都有风险。修复可以恢复每个键一行，却选中错误的总体，而部署中唯一的回归参照，即生产者写的 SQL，只在它所针对的快照上成立；今天等价的改写，可能依赖一个明天的数据会破坏的性质。}

\bi{\system\ (\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents) answers these questions with one abstraction, a versioned \emph{revision} of a definition that carries the executable conditions on which its SQL depends. \emph{Publication}: admission turns a judged-successful trajectory into a structured definition that separates definition filters from question parameters, and replays the canonical SQL compiled from its fields. The conditions follow from that structure, namely filtered key uniqueness for the grain, cardinality and completeness for each join, and the date role; together with the definition's business premises, they make the canonical SQL count every business event exactly once in its period, up to the omissions that completeness bounds (Proposition~\ref{prop:sufficiency}). \emph{Reliance}: an agent declares the revisions a query uses, and \system\ runs the query in a snapshot on which their conditions hold, reusing check results whose transactional versions match the snapshot (Lemma~\ref{lem:reuse}). \emph{Maintenance and improvement}: a check result is keyed by the condition's canonical form and the versions of the tables it reads, so it serves every definition and agent that needs the condition; a failed condition invalidates the revision, and repair publishes only the unique structural fix that reproduces the producer's answer as of learning time (Algorithm~\ref{alg:repair}). The same channel publishes cheaper rewrites, adopted only when the maintained conditions, including any premise a rewrite adds, imply equivalence (Proposition~\ref{prop:rewrite}); when a change breaks that premise, the layer falls back to the form that does not need it. The managed knowledge is metric definitions with their grain and join paths, the guarantee covers declared uses, and because maintenance works on structured definitions, it applies equally to definitions declared in a semantic layer.}
{\system（\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents，面向智能体的指标感知验证与复用）用一个抽象回答这些问题：定义的版本化\emph{修订}，它带着其 SQL 所依赖的可执行条件。\emph{发布}：准入把一条判题成功的轨迹转成结构化定义，把定义过滤与题目参数分开，并重放由字段编译出的规范 SQL。条件由这一结构推出，即粒度对应过滤后键唯一性，每个连接对应连接基数与连接完整性，另有日期角色；与定义的业务前提一起成立时，它们使规范 SQL 把每个业务事件在其期间内恰好计数一次，遗漏仅限于完整性所约束的部分（命题~\ref{prop:sufficiency}）。\emph{依赖}：智能体声明查询所用的修订，\system\ 在这些修订的条件成立的快照中执行查询，事务性版本与快照一致的检查结果直接复用（引理~\ref{lem:reuse}）。\emph{维护与改进}：检查结果按条件的规范形式及其读取表的版本索引，因此服务于所有需要该条件的定义和智能体；条件失败使修订失效，修复只发布结构上唯一、且按学习时刻复现生产者答案的修复（算法~\ref{alg:repair}）。同一通道也发布更省的改写：只有受维护的条件（包括改写新增的前提）蕴含其等价时才采纳（命题~\ref{prop:rewrite}）；数据变化破坏这一前提时，这一层回退到不需要它的写法。受管理的知识是指标定义及其粒度与连接路径，保证覆盖声明了修订的使用；由于维护作用于结构化定义，它同样适用于在语义层中声明的定义。}

\bi{We evaluate \system\ at the system level, where learned libraries are fixed and only maintenance varies, and end to end with DeepSeek V4.1 Flash agents. On libraries learned by three LLMs and on TPC-DS, maintained definitions serve no wrong answer under the covered changes, whereas invalidation on schema change serves \RpSchemaWrongModeled\ and \TrSchemaWrongModeled; same-snapshot use never answers on condition-violating data; and maintenance work follows the distinct conditions an update touches. End to end, maintained memory answers \DsCondModeled\% under the covered breaking changes, against \DsTrajModeled\% for matched example retrieval, which is as accurate on unchanged data, and through a lifecycle of accumulating updates one library keeps \LcAccCond\% of answers correct (\LcAccTraj\% with retrieved examples, \LcAccNone\% without memory).}
{我们在系统层（固定学到的定义库，只改变维护方式）和端到端层（基于 DeepSeek V4.1 Flash 的智能体）评估 \system。在 3 个大模型学到的定义库和 TPC-DS 上，维护后的定义在条件覆盖的变化下不给出错误答案，只在模式变更时失效的做法分别给出 \RpSchemaWrongModeled\ 和 \TrSchemaWrongModeled\ 个；同快照使用从不在违反条件的数据上作答；维护工作沿更新触及的不同条件展开。端到端实验中，维护后的记忆在条件覆盖的破坏性变化下答对 \DsCondModeled\%，数据不变时同样准确的匹配示例检索为 \DsTrajModeled\%；在更新不断累积的生命周期中，一个定义库保持 \LcAccCond\% 的答案正确（检索示例为 \LcAccTraj\%，无记忆为 \LcAccNone\%）。}

\bi{This paper makes the following contributions:}
{本文的贡献如下：}
\begin{itemize}
\item \bi{A shared memory layer for data agents that takes over publication, reliance, and maintenance and improvement, built on versioned revisions of metric definitions with four kinds of executable validity conditions, which we prove sufficient for the canonical SQL to count every business event once (Sections~\ref{sec:overview} and~\ref{sec:model}).}
{一个数据智能体的共享记忆层，承担发布、依赖以及维护与改进；它建立在指标定义的版本化修订之上，修订带有四类可执行的有效性条件，我们证明这些条件足以让规范 SQL 把每个业务事件只计数一次（第~\ref{sec:overview} 和~\ref{sec:model} 节）。}
\item \bi{Use-time enforcement that binds every declared use to evidence on the query's own snapshot, applying the transactional consistency of TxCache~\cite{ports2010txcache} to check results under a reuse rule we prove sound (Lemma~\ref{lem:reuse}; Section~\ref{sec:execution}).}
{使用时的强制保证：把每一次声明了修订的使用绑定到查询自身快照上的证据，把 TxCache~\cite{ports2010txcache} 的事务一致性用于检查结果，其复用规则经我们证明是可靠的（引理~\ref{lem:reuse}；第~\ref{sec:execution} 节）。}
\item \bi{Maintenance and improvement as a shared service: condition-level revalidation, repair that publishes only the unique fix that reproduces the producer's answer as of learning time (Algorithm~\ref{alg:repair}), and rewrites whose equivalence the maintained conditions imply, with fallback when a premise breaks (Proposition~\ref{prop:rewrite}; Section~\ref{sec:maintenance}).}
{把维护与改进做成共享的服务：条件级重验证；只发布按学习时刻复现生产者答案的唯一修复（算法~\ref{alg:repair}）；只采纳受维护条件蕴含其等价的改写，前提被破坏时回退（命题~\ref{prop:rewrite}；第~\ref{sec:maintenance} 节）。}
\item \bi{An implementation and an evaluation that separates the value of sharing from that of maintenance, motivated by a characterization of data-agent workloads against 441 million Redshift queries (Sections~\ref{sec:background} and~\ref{sec:evaluation}).}
{一个实现，以及把共享的价值与维护的价值分开测量的评估；设计动机来自把数据智能体负载与 4.41 亿条 Redshift 查询对照的负载刻画（第~\ref{sec:background} 和~\ref{sec:evaluation} 节）。}
\end{itemize}
