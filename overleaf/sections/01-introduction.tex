\section{\bt{Introduction}{引言}}
\label{sec:introduction}
\bi{Data agents answer analytical questions and build predictive features through repeated schema inspection, value probes, and join tests. These steps recur across sessions over the same database because business meanings, grain, filters, and joins are rarely explicit in a schema. In our metric traces, 57\% of LLM calls issue no SQL used by the answer, and 71\% of session time precedes the answer query. Section~\ref{sec:workload-characterization} quantifies the repeated knowledge in public benchmarks and our traces.}
{数据智能体通过反复检查模式、探查取值并验证连接，回答分析问题和构建预测特征。由于业务含义、粒度、过滤和连接很少在模式中明确给出，同一数据库上的会话会重复这些步骤。在我们的指标轨迹中，57\% 的 LLM 调用不发出答案所用的 SQL，71\% 的会话时间发生在答案查询之前。第~\ref{sec:workload-characterization} 节量化公开基准与我们轨迹中的知识重复。}

\bi{For example, Agent A learns that store revenue sums each ticket--item sale once; Agent B reuses that definition for September. When a restatement retains old versions, unchanged SQL double-counts sales. Figure~\ref{fig:metric-record} shows why reusable definitions need checked conditions and a repair-or-revoke policy.}
{例如，智能体 A 学到门店收入对每个票据--商品销售只求和一次；智能体 B 为九月复用这一定义。当更正保留旧版本时，未修改的 SQL 会重复计入销售。图~\ref{fig:metric-record} 说明可复用定义为何需要可检查的条件，以及修复或撤销的策略。}

\bi{Prior work already reduces repeated exploration through reusable experience. AgentSM organizes database trajectories, retrieves them by database and question similarity, and combines recurring tool sequences into composite tools~\cite{biswal2026agentsm}. DataLab extracts business logic from historical SQL/Python scripts, organizes it for retrieval, and uses a DSL to support code generation~\cite{weng2025datalab}. G-Memory shares trajectories and insights within a multi-agent system~\cite{zhang2025gmemory}, and metric layers centralize executable definitions~\cite{dbt2026metricflow,databricks2026metricviews}. These capabilities establish that structured knowledge, sharing, and SQL reuse are already available. Our focus is the connection between a learned definition, the data conditions supporting it, and the snapshot on which a consumer executes it.}
{已有工作已经通过复用经验减少重复探索。AgentSM 组织数据库轨迹，按数据库和问题相似度检索，并把反复出现的工具序列组合成复合工具~\cite{biswal2026agentsm}。DataLab 从历史 SQL/Python 脚本提取业务逻辑，组织为可检索的知识，并通过 DSL 支持代码生成~\cite{weng2025datalab}。G-Memory 在多智能体系统内共享轨迹与洞见~\cite{zhang2025gmemory}，指标层集中管理可执行定义~\cite{dbt2026metricflow,databricks2026metricviews}。这些工作已经提供结构化知识、共享和 SQL 复用能力。本文关注学得的定义、支撑该定义的数据条件，以及消费者执行它所用快照之间的联系。}

\bi{We place this lifecycle at the database boundary, where writes and query snapshots are visible. A reusable definition needs three mechanisms: \emph{derived data conditions} to detect when its structural assumptions fail; \emph{shared validation} to avoid checking the same condition separately for every consumer; and \emph{snapshot-bound use} to prevent a write between validation and execution from invalidating the evidence. A failed condition must lead to a checked repair or revocation. These mechanisms let a definition serve new questions while its modeled assumptions remain valid.}
{我们把这套生命周期放在能观察写入与查询快照的数据库边界。可复用定义需要三种机制：\emph{派生数据条件}，检测结构前提何时失效；\emph{共享验证}，避免每个消费者分别检查同一条件；\emph{绑定快照的使用}，防止验证与执行之间的写入使证据失效。条件不成立时，必须执行经过检查的修复或撤销。这些机制使定义在已建模的前提仍成立时服务新的问题。}

\bi{\system\ (\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents) implements these requirements as a shared metric and feature layer. It extracts structured definitions from verified agent sessions, publishes numbered revisions after deterministic checks, and compiles them for new questions. For metrics, grain and joins determine executable conditions sufficient for aggregation under explicit business assumptions (Proposition~\ref{prop:sufficiency}). Check results are shared by dependency version (Lemma~\ref{lem:reuse}) and validated on the query's snapshot. Failed conditions trigger checked repair or revocation; equivalent rewrites carry their own maintained assumptions (Proposition~\ref{prop:rewrite}). Feature definitions additionally enforce per-instance temporal bounds. This design connects publication, validation, use, and maintenance through the same definition record.}
{\system{}（\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents）以共享指标和特征层实现这些要求。它从核实的智能体会话提取结构化定义，经确定性检查发布带编号的版本，再为新问题编译查询。对于指标，粒度和连接确定可执行条件；在明确的业务前提下，这些条件足以支持正确聚合（命题~\ref{prop:sufficiency}）。检查结果按依赖版本共享（引理~\ref{lem:reuse}），并在查询快照上验证。条件失效触发经过检查的修复或撤销；等价重写携带自身需要维护的前提（命题~\ref{prop:rewrite}）。特征定义还强制逐样本的时间边界。这一设计通过同一份定义记录连接发布、验证、使用与维护。}

\bi{We evaluate periodic retraining using two databases from RelBench~\cite{robinson2024relbench} against no memory, ACE~\cite{zhang2026ace}, G-Memory~\cite{zhang2025gmemory}, AWM~\cite{wang2025awm}, DeepPrep~\cite{fan2026deepprep}, and FeatPilot~\cite{liang2025featpilot}. From the second cutoff onward, \system\ reduces tokens by \RbStackMavraTokSave\% on rel-stack and \RbTrialMavraTokSave\% on rel-trial relative to no memory, and by \RbStackMavraVsBest\% and \RbTrialMavraVsBest\% relative to the most token-efficient evaluated agent memory on each database. Mean test scores remain comparable to the no-memory baseline across all six tasks. On TPC-DS, sharing across \PpAgents\ agents reduces tokens by \PpMavraTokSaveNone\% relative to no memory and \PpMavraTokSavePrivate\% relative to private memory with the same learning and checks. After a restatement, accuracy is \PpMavraChangeAcc\% with \system\ and \PpNoneChangeAcc\% without memory.}
{我们在两个 RelBench 数据库上评估定期重训~\cite{robinson2024relbench}，比较无记忆、ACE~\cite{zhang2026ace}、G-Memory~\cite{zhang2025gmemory}、AWM~\cite{wang2025awm}、DeepPrep~\cite{fan2026deepprep} 与 FeatPilot~\cite{liang2025featpilot}。从第二个截点起，\system\ 相对无记忆在 rel-stack 和 rel-trial 上分别减少 \RbStackMavraTokSave\% 和 \RbTrialMavraTokSave\% 的 token，相对各库已评估的最省 token 的智能体记忆分别减少 \RbStackMavraVsBest\% 和 \RbTrialMavraVsBest\%。六个任务的平均测试分数均保持与无记忆基线相当的预测质量。在 TPC-DS 上，\PpAgents\ 个智能体共享记忆，相对无记忆减少 \PpMavraTokSaveNone\% 的 token，相对采用相同学习和检查的私有记忆减少 \PpMavraTokSavePrivate\%。一次更正后，\system\ 准确率为 \PpMavraChangeAcc\%，无记忆为 \PpNoneChangeAcc\%。}

\bi{The contributions are:}{本文的贡献如下：}
\begin{itemize}
\item \bi{A publication and compilation path from verified sessions to revisioned metric and temporally bounded feature definitions, with data conditions derived from their structure (Sections~\ref{sec:overview} and~\ref{sec:model}).}{从核实会话到版本化指标定义及受时间边界约束的特征定义的发布与编译路径，并从定义结构推导数据条件（第~\ref{sec:overview}、\ref{sec:model} 节）。}
\item \bi{A metric lifecycle combining dependency-versioned shared checks, execution-snapshot validation, and checked repair or revocation; sufficiency and reuse results state its assumptions (Section~\ref{sec:model}).}{将按依赖版本共享检查、执行快照验证及经过检查的修复或撤销结合起来的指标生命周期，并通过充分性与复用结论明确其前提（第~\ref{sec:model} 节）。}
\item \bi{Workload evidence and evaluations that distinguish the cost of executable reuse, shared upkeep, and failures under data changes, alongside predictive quality on RelBench (Sections~\ref{sec:background} and~\ref{sec:evaluation}).}{负载证据与实验区分可执行复用的代价、共享维护的代价及数据变化下的失效，并评估 RelBench 上的预测质量（第~\ref{sec:background}、\ref{sec:evaluation} 节）。}
\end{itemize}
