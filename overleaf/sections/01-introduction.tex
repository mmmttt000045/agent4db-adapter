\section{\bt{Introduction}{引言}}
\label{sec:introduction}
\bi{Data agents repeatedly explore the same database to answer different questions and build predictive features. An agent asking for March revenue, another asking for September revenue, and a third asking for quarterly revenue all need the same measure, grain, filters, and joins. When each session discovers these independently, the workload pays repeatedly for schema inspection, value probes, join tests, and the LLM calls that plan and interpret them. In our traces of 100 memoryless metric sessions, 93\% of lookups repeat a fact obtained by an earlier session, and 71\% of session time precedes the answer query. Public benchmark tasks exhibit the same overlap in calculations and domain knowledge (Section~\ref{sec:workload-characterization}).}
{数据智能体为回答不同问题和构建预测特征，会反复探索同一数据库。询问三月收入、九月收入和季度收入的智能体，都需要相同的度量、粒度、过滤与连接。如果每个会话独立发现这些知识，整个负载就要反复支付模式检查、取值探查、连接验证，以及规划这些操作和解释结果的大模型调用开销。在我们的 100 个无记忆指标会话轨迹中，93\% 的查找重复此前会话获得的事实，71\% 的会话时间发生在答案查询开始之前。公开基准中的任务也表现出计算规则与领域知识的重叠（第~\ref{sec:workload-characterization} 节）。}

\bi{Existing reuse mechanisms offer two starting points. Agent memories retain trajectories, workflows, and playbooks from experience, making discoveries available to later sessions~\cite{wang2025awm,zhang2026ace,biswal2026agentsm}. Semantic layers such as MetricFlow and metric views instead expose declared measures, joins, and filters that a compiler can turn into queries~\cite{dbt2026metricflow,databricks2026metricviews}. The former capture knowledge as agents work; the latter give knowledge an explicit representation for shared execution and management.}
{现有复用机制提供了两种起点。智能体记忆从经验中保存轨迹、工作流与操作手册，让后续会话利用已有发现~\cite{wang2025awm,zhang2026ace,biswal2026agentsm}。MetricFlow 和指标视图等语义层则显式声明度量、连接与过滤，再由编译器生成查询~\cite{dbt2026metricflow,databricks2026metricviews}。前者在智能体工作时积累知识，后者为知识提供可供共享执行与管理的明确表示。}

\bi{The core tension is between acquiring knowledge from experience and maintaining it as a database object. A successful trajectory records what worked on past data, but does not by itself expose the grain and join conditions that must hold after an update. A declarative metric layer exposes reusable semantics, but starts from definitions supplied by developers or analysts. Bridging these approaches requires more than retrieving or summarizing a trace: a discovery must become a checked executable definition, and its validity must be tied to the database snapshot on which it is used.}
{核心矛盾在于：如何把从经验中获取的知识，变成可持续维护的数据库对象。成功轨迹记录的是在过去数据上行得通的做法，本身并未显式给出更新后仍需成立的粒度与连接条件；声明式指标层提供可复用语义，却以开发者或分析师预先提供的定义为起点。连接两者需要超越轨迹检索与摘要：将发现转化为经检查的可执行定义，并把定义的有效性绑定到实际使用它的数据库快照。}

\bi{\system\ (\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents) builds this bridge through checked extraction and snapshot-bound compilation and execution. Checked extraction converts a successful session into a structured definition of the measure, grain, joins, and filters, with entity and time bounds for features. For metrics, publication checks test that both the example SQL and the compiled definition reproduce the independently verified answer. Knowledge can therefore accumulate from database use while passing explicit publication gates before it is shared. Figure~\ref{fig:metric-record} contrasts independent exploration with this learned semantic layer.}
{\system{}（\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents）通过受检提取与快照绑定的编译、执行连接这两种方式。受检提取将成功会话转化为结构化定义，记录度量、粒度、连接与过滤，并为特征记录实体和时间边界。对于指标，发布检查验证示例 SQL 与编译所得定义都能重现独立核实的答案。知识因此随数据库使用持续积累，并在共享前通过明确的发布门控。图~\ref{fig:metric-record} 对照独立探索与这一逐步学得的语义层。}

\bi{For a new question, compilation instantiates the definition for the requested period or prediction instances. The layer validates its structural conditions and executes the consuming query in the same repeatable-read transaction, reusing check results only at matching dependency versions. This binds validation to the data actually read. Updates trigger revalidation, checked repair, or revocation, and the resulting work is shared across consumers. Our correctness argument connects business premises, structural conditions, and the query snapshot (Section~\ref{sec:model}); the amortization model explains how sharing their upkeep reduces repeated exploration and maintenance (Section~\ref{sec:alternatives}).}
{面对新问题，编译器按所需期间或预测样本实例化定义。共享层在同一个可重复读事务中验证结构条件并执行消费查询，仅在依赖版本匹配时复用检查结果，从而让验证对应实际读取的数据。更新触发重验证、受检修复或撤销，这些工作由多个使用者共享。正确性论证连接业务前提、结构条件与查询快照（第~\ref{sec:model} 节）；分摊模型则解释，共享知识及其维护如何减少重复探索与检查（第~\ref{sec:alternatives} 节）。}

\bi{The evaluation tests both maintained reuse and its amortized cost. After a TPC-DS restatement, \system\ reaches \PpMavraChangeAcc\% accuracy versus \PpNoneChangeAcc\% without memory. Synthetic retail and TPC-H experiments distinguish the structural changes it handles from value-semantic changes that need additional information. Across the \PpAgents-agent TPC-DS population, \system\ uses \PpMavraTokSaveNone\% fewer tokens and runs \PpMavraSpeedupNone$\times$ faster than no memory, with \PpMavraTokSavePrivate\% fewer tokens than private memory. On six RelBench tasks~\cite{robinson2024relbench}, token use from the second retraining cutoff onward falls by \RbStackMavraTokSave\% on rel-stack and \RbTrialMavraTokSave\% on rel-trial, with comparable predictive quality.}
{实验同时检验持续维护下的复用与其分摊代价。TPC-DS 数据更正后，\system\ 正确率为 \PpMavraChangeAcc\%，无记忆为 \PpNoneChangeAcc\%。合成零售数据和 TPC-H 实验进一步区分可处理的结构变化与需要额外信息的值域语义变化。在 \PpAgents\ 个智能体的 TPC-DS 群体中，\system\ 相对无记忆少用 \PpMavraTokSaveNone\% 的 token，快 \PpMavraSpeedupNone\ 倍，相对私有记忆少用 \PpMavraTokSavePrivate\% 的 token。在六项 RelBench 任务上~\cite{robinson2024relbench}，从第二个重训截点起，rel-stack 和 rel-trial 的 token 分别减少 \RbStackMavraTokSave\% 与 \RbTrialMavraTokSave\%，预测质量相当。}

\bi{The contributions are:}{本文的贡献如下：}
\begin{itemize}
\item \bi{A learned semantic layer that turns agent discoveries into shared executable metric and feature definitions through checked extraction (Sections~\ref{sec:overview} and~\ref{sec:shared-object}).}
{通过受检提取，将智能体发现转化为共享的可执行指标与特征定义，逐步构建语义层（第~\ref{sec:overview}、\ref{sec:shared-object} 节）。}
\item \bi{Snapshot-bound validation and shared maintenance, with sufficient conditions for aggregation correctness and cross-snapshot reuse of check results (Section~\ref{sec:model}).}
{提出快照绑定的验证与共享维护机制，给出聚合正确性和跨快照复用检查结果的充分条件（第~\ref{sec:model} 节）。}
\item \bi{A workload analysis, amortization model, and evaluation of correctness under data changes and cost across agent populations and retraining sessions (Sections~\ref{sec:background} and~\ref{sec:evaluation}).}
{通过负载分析、分摊模型与实验，评估数据变化下的正确性，以及跨智能体群体和重训会话的开销（第~\ref{sec:background}、\ref{sec:evaluation} 节）。}
\end{itemize}
