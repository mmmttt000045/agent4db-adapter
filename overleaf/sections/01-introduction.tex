\section{\bt{Introduction}{引言}}
\label{sec:introduction}

\bi{Enterprise databases and data warehouses support recurring analytical workloads, including business reporting, ad hoc analysis, and predictive modeling. LLM-based data agents undertake these tasks for different users through separate sessions and clients~\cite{lei2025spider2,guo2024dsagent,liu2026agents}. Although the questions vary, many rely on the same database-specific knowledge: metric definitions, data grain, filters, and join relationships~\cite{floratou2024nl2sql,robinson2024relbench}. For example, monthly reports and quarterly business reviews may use the same revenue calculation over different reporting periods (Figure~\ref{fig:metric-record}). Once an agent has established this calculation, subsequent agents should be able to reuse it for their own questions. When discoveries remain in individual session histories or private memories, other agents must repeat the exploration or reconstruct the calculation.}
{企业数据库与数据仓库承接反复发生的分析任务，包括经营报表、即席分析和预测建模。基于大语言模型的数据智能体通过不同会话和客户端，为不同用户执行这些任务~\cite{lei2025spider2,guo2024dsagent,liu2026agents}。尽管问题各不相同，许多任务仍然依赖相同的数据库知识：指标口径、数据粒度、过滤规则与连接关系~\cite{floratou2024nl2sql,robinson2024relbench}。例如，月度报表与季度经营分析可以采用同一营业额计算，仅统计期间不同（图~\ref{fig:metric-record}）。智能体一旦确定这一计算，后续智能体便应能够将其复用于各自的问题。当这些发现留在各自的会话历史或私有记忆中时，其他智能体仍需重复探索或重构计算。}

\bi{As these tasks recur, the database also changes, and the assumptions behind a shared calculation may cease to hold. Consider a revenue calculation that joins sales to a lookup table on a key observed to be unique. A later data load may introduce multiple rows for that key, causing the same join to count sales more than once. The SQL still executes, and rerunning it on fresh data does not repair the invalid assumption. By contrast, inserting additional sales need not change the calculation at all. Maintaining reusable knowledge therefore requires distinguishing changes that merely alter the answer from changes that undermine the calculation. In a shared memory, an undetected failure can propagate across the agents that reuse the affected definition.}
{这些分析任务持续开展的同时，数据库也在变化，共享计算所依赖的前提可能不再成立。考虑一条营业额计算：它使用在已观测数据中具有唯一性的键，将销售记录与查找表连接。后续数据导入可能为同一个键引入多条记录，使原有连接重复计算销售额。此时 SQL 仍能正常执行，在新数据上重新运行也无法修复已经失效的前提。相比之下，新增销售记录可能只改变营业额数值，并不要求修改计算本身。因此，维护可复用知识，需要区分仅改变答案的数据变化与破坏计算前提的数据变化。在共享记忆中，未被发现的前提失效可能将错误传播给多个复用该定义的智能体。}

\bi{Existing work provides several foundations for reuse. Agent memories retain and refine insights and workflows~\cite{zhao2024expel,wang2025awm,zhang2026ace}, while multi-agent memories share accumulated experience~\cite{zhang2025gmemory}. AgentSM reuses structured trajectories and composite tools for database tasks~\cite{biswal2026agentsm}. Database-oriented systems extract calculation logic from scripts~\cite{weng2025datalab} or centralize metric definitions for SQL generation~\cite{dbt2026metricflow,databricks2026metricviews}. These capabilities make prior knowledge reusable. However, continued reuse as the database evolves requires establishing whether the computation's data-dependent assumptions still hold. Revising memory from task feedback or executing a shared definition does not by itself establish this validity. We study how to maintain learned computations through explicit conditions and dependencies, so that affected knowledge can be identified and maintained for all consumers.}
{既有工作为复用提供了多方面基础。智能体记忆保留并改进洞见和工作流~\cite{zhao2024expel,wang2025awm,zhang2026ace}，多智能体记忆共享积累的经验~\cite{zhang2025gmemory}。AgentSM 为数据库任务复用结构化轨迹与复合工具~\cite{biswal2026agentsm}。面向数据库的系统从脚本中提取计算逻辑~\cite{weng2025datalab}，或集中管理指标定义以生成 SQL~\cite{dbt2026metricflow,databricks2026metricviews}。这些能力使已有知识能够复用。然而，要在数据库演进过程中持续复用，还需要确认计算依赖的数据前提是否仍然成立。仅依据任务反馈修改记忆，或执行共享定义，并不足以确立这种有效性。本文研究如何通过显式条件与依赖维护已学到的计算，使受影响的知识能够被定位，并面向所有使用者统一维护。}

\bi{This problem poses three challenges. \emph{First, extracting reusable computation.} Successful traces mix business logic with question-specific parameters. Extraction must separate the two and make the assumptions supporting reuse explicit. \emph{Second, localizing maintenance.} A change to a dependency calls for revalidation, but does not necessarily invalidate the calculation. The system must identify affected conditions and determine which definitions require repair while retaining knowledge that remains valid. \emph{Third, coordinating validation and reuse.} Independent checks by different agents duplicate work, while a check on an earlier database state may not justify execution on a later one. Validation evidence must be shared across consumers and remain applicable to the data read by each consuming query.}
{这一问题面临三项挑战。\emph{第一，提取可复用计算。}成功轨迹混合了业务逻辑与特定问题的参数。提取过程必须分离二者，并显式记录支持复用的前提。\emph{第二，定位维护范围。}依赖发生变化意味着需要重验，却不一定意味着计算失效。系统必须定位受影响的条件，确定哪些定义需要修复，同时保留仍然有效的知识。\emph{第三，协调验证与复用。}不同智能体独立检查会重复工作，而在较早数据库状态上完成的检查，未必能支持在后续状态上执行。验证证据需要在使用者之间共享，并适用于各消费查询实际读取的数据。}

\bi{We present \system\ (\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents), a shared memory layer between heterogeneous data agents and the database. Its central design is to manage \emph{executable definitions together with checkable conditions of reuse}. A metric definition separates the measure, grain, joins, and filters from question parameters; a feature definition additionally identifies the entity and temporal window. Before publication, deterministic checks validate extracted definitions and compare their compiled results with verified metric answers or submitted feature values. Later agents retrieve accepted definitions and instantiate them for new periods or prediction instances, reusing the computation established by earlier sessions.}
{本文提出 \system{}（\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents），一个位于异构数据智能体与数据库之间的共享记忆层。其核心设计是\emph{将可执行定义与可检查的复用条件共同管理}。指标定义将度量、粒度、连接和过滤与问题参数分离；特征定义进一步记录实体与时间窗口。发布前，确定性检查验证提取出的定义，并将其编译结果与经过核实的指标答案或提交的特征值比较。后续智能体检索已通过检查的定义，为新的期间或预测样本实例化，从而复用先前会话已经确定的计算。}

\bi{\system\ maintains reusable knowledge through its dependencies. Condition identities and dependency versions let consumers share validation evidence and identify conditions requiring revalidation after data changes. When a recorded condition fails, the system repairs or invalidates affected metric definitions while retaining knowledge whose required conditions remain valid. Validated metric repairs become available to subsequent consumers, so each agent need not rediscover the same correction. For metric execution, validation is bound to the consuming query's database snapshot, aligning the validity decision with the data used to compute the answer. These mechanisms extend sharing from the initial discovery to the validation and maintenance needed for continued reuse.}
{\system\ 根据依赖关系维护可复用知识。条件标识与依赖版本使使用者能够共享验证证据，并在数据变化后定位需要重验的条件。当已记录的条件不再成立时，系统修复受影响的指标定义，或将其标记为不可复用，同时保留所需条件仍然成立的知识。经过验证的指标修复可供后续使用者复用，无需各个智能体分别重新发现相同的修正。对于指标执行，验证与消费查询的数据库快照绑定，使有效性判断与计算答案所使用的数据对齐。这些机制将共享从最初的知识发现，延伸到持续复用所需的验证与维护。}

\bi{In summary, we make the following contributions:}{综上，本文的主要贡献如下：}
\begin{itemize}
\item \bi{We design and implement \system, a shared memory layer between heterogeneous data agents and the database that makes knowledge acquired in individual sessions reusable across agents, tasks, and sessions.}
{我们设计并实现了 \system，一个位于异构数据智能体与数据库之间的共享记忆层，使单个会话获得的知识能够跨智能体、任务和会话复用。}

\item \bi{We develop an extraction and publication pipeline that converts successful session discoveries into a uniform representation of parameterized, executable metric and feature definitions. The pipeline separates reusable computation from task-specific inputs, records checkable reuse conditions, and validates definitions before publication.}
{我们设计了知识提取与发布流程，将成功会话中的发现统一表示为参数化的可执行指标与特征定义。该流程分离可复用计算与任务特定输入，记录可检查的复用条件，并在发布前验证定义。}

\item \bi{We design dependency-aware validation and repair mechanisms that recheck affected conditions after data updates and block reuse of metric definitions whose recorded conditions fail on the query snapshot. The mechanisms selectively repair or invalidate affected definitions, preserve unaffected knowledge, and share validated repairs across consumers.}
{我们设计了基于依赖的动态验证与修复机制，在数据更新后重验受影响的条件，并阻止复用在查询快照上不满足已记录条件的指标定义。这些机制定向修复受影响的定义或将其标记为不可复用，保留未受影响的知识，并在使用者之间共享经过验证的修复。}

\item \bi{We evaluate \system\ on RelBench, TPC-DS, and TPC-H to study cross-agent reuse, maintenance under data updates, answer and predictive quality, token consumption, and end-to-end time. The evaluation accounts for the costs of learning, publication, validation, and maintenance.}
{我们在 RelBench、TPC-DS 和 TPC-H 上评估 \system，考察跨智能体复用、数据更新后的维护、答案与预测质量、token 消耗以及端到端耗时，并计入学习、发布、验证和维护的开销。}
\end{itemize}
