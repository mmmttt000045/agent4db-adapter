\section{\bt{Introduction}{引言}}
\label{sec:introduction}
\bi{A data agent answers an analytical question by exploring the database: it lists tables, inspects values, tests joins, and settles on SQL over many LLM turns. Exploration is where the time and tokens go, and it is repeated. Agents on the same database rediscover the same knowledge in every session: which fact rows a metric aggregates, which records count as one business event, and how tables join. In our traces, 93\% of the lookups of new agent sessions repeat a fact that an earlier session had already obtained, while none of the repeated SQL probes repeats its text, so a query cache serves none of them (Section~\ref{sec:workload-characterization}).}
{数据智能体通过探索数据库来回答分析问题：在多轮大模型调用中列出表、查看取值、检验连接，最后确定 SQL。时间和 token 都花在探索上，而且探索是重复的。同一数据库上的智能体在每个会话里重新发现同样的知识：一个指标聚合哪些事实行，哪些记录算作一次业务事件，表之间如何连接。在我们记录的会话中，新会话 93\% 的查找都在重复此前会话已经得到的事实，而重复的 SQL 探查没有一条文本相同，因此查询缓存一条也服务不了（第~\ref{sec:workload-characterization} 节）。}

\bi{Agent memory does not remove this repetition, because it is organized per agent. Memory systems keep an agent's conversations and facts~\cite{chhikara2025mem0,packer2023memgpt}, induce workflows and strategies from its own trajectories~\cite{wang2025awm,zhao2024expel,ouyang2026reasoningbank}, or evolve its context~\cite{zhang2026ace,xu2025amem}; for text-to-SQL, AgentSM turns a system's past trajectories into semantic memory and leaves shared memory to future work~\cite{biswal2026agentsm}. With per-agent memory, every new agent pays for the same exploration again, so the cost grows with the number of agents rather than with the amount of knowledge. Yet the agents of an organization query the same tables and ask about the same metrics, and agent-first data systems call for a persistent memory that serves many agents~\cite{liu2026agents}.}
{智能体记忆并不能消除这种重复，因为它是按智能体组织的。现有记忆系统保存一个智能体的对话与事实~\cite{chhikara2025mem0,packer2023memgpt}，从它自己的轨迹中归纳工作流与策略~\cite{wang2025awm,zhao2024expel,ouyang2026reasoningbank}，或演化它的上下文~\cite{zhang2026ace,xu2025amem}；在 Text-to-SQL 上，AgentSM 把一个系统过去的轨迹整理成语义记忆，并把共享记忆留作未来工作~\cite{biswal2026agentsm}。在单智能体记忆下，每个新来的智能体都要为同样的探索再付一次代价，代价随智能体数量增长，而不是随知识量增长。然而一个组织里的智能体查询的是同一批表、问的是同一批指标，面向智能体的数据系统也呼吁一种为众多智能体服务的持久记忆~\cite{liu2026agents}。}

\bi{We argue that the memory of data agents belongs with the database and is shared by every agent that queries it: one agent explores, and every later agent, whatever it asks, reuses what was learned. Figure~\ref{fig:example} shows the idea on one metric, store revenue. One agent learns its definition once (step~1); \system\ publishes it (step~2), and every later agent answers questions about any month, difference, or ranking with the generated SQL instead of exploring (step~4).}
{我们认为，数据智能体的记忆应当放在数据库一侧，由查询它的所有智能体共享：一个智能体探索，之后的每个智能体无论问什么，都复用已经学到的东西。图~\ref{fig:example} 以一个指标——门店营业额——说明这一点。一个智能体学一次它的定义（第 1 步）；\system\ 发布它（第 2 步）；之后每个智能体回答任何月份、差值或排名的问题时，都用生成的 SQL 代替探索（第 4 步）。}

\bi{Sharing on a database raises two problems that per-agent memory does not face. \emph{Transfer:} agents ask different questions, so what is shared must be knowledge, a definition separated from question parameters, not queries or results. \emph{Correctness under change:} a definition that one agent learned is correct only while unstated data properties hold. The SQL learned in step~1, \code{SUM(ss\_net\_paid)} over a month's sales, is correct because each ticket--item key identifies one sale; when a restatement later keeps old sales as non-current rows (step~5), no table or column changes and the SQL still runs, but it counts restated sales twice and returns 14,300,525.64 for September instead of 12,932,888.04. The agents that reuse it never saw the data it was learned from: only 16\% of the sessions in our traces check key uniqueness, and every wrong answer came from SQL that ran without error. A memory that only stores and retrieves turns one stale definition into a wrong answer for every agent, and if each agent had to verify what it reads, it would pay per agent again.}
{在数据库上共享带来单智能体记忆不会遇到的两个问题。\emph{可迁移：}智能体问的问题各不相同，因此共享的必须是知识，即与题目参数分开的定义，而不是查询或结果。\emph{变化下的正确性：}一个智能体学到的定义只在一些未写明的数据性质成立时才正确。第 1 步学到的 SQL（对一个月的销售求 \code{SUM(ss\_net\_paid)}）之所以正确，是因为每个小票--商品键对应一笔销售；之后一次更正把旧销售行保留为非当前行（第 5 步）：表和列都没有变，SQL 照常执行，却把被更正的销售算了两次，9 月返回 14,300,525.64，而正确值是 12,932,888.04。复用它的智能体从未见过它赖以成立的数据：我们记录的会话中只有 16\% 检查键唯一性，所有错误答案都来自执行成功的 SQL。只负责存储和检索的记忆，会把一个过期的定义变成每个智能体的错误答案；而如果每个智能体都要自己核验读到的内容，又要按智能体重复付出代价。}

\bi{\system\ (\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents) is a shared memory layer between data agents and a SQL database that solves both problems once for all agents. It shares numbered revisions of metric definitions, published from successful sessions only after the publication checks replay the generated SQL that other agents will read. Each revision carries executable conditions derived from its structure, which we prove sufficient for the generated SQL to count each business event once in its period (Proposition~\ref{prop:sufficiency}). \system\ checks the conditions when the tables they read change and shares the check results across definitions and agents; a failed condition leads to a unique, regression-tested repair (steps~5--7) or to invalidation, and a query uses a revision only on a snapshot on which its conditions hold. Because every agent reuses the same SQL, \system\ also publishes cheaper equivalent revisions, so that one optimization speeds up every agent (step~3).}
{\system（\textbf{M}etric-\textbf{A}ware \textbf{V}alidation and \textbf{R}euse for \textbf{A}gents，面向智能体的指标感知验证与复用）是位于数据智能体与 SQL 数据库之间的共享记忆层，为所有智能体一次性地解决这两个问题。它共享指标定义的带编号版本；版本从成功的会话中学来，只有在发布前检查重放了其他智能体将要读到的生成的 SQL 之后才发布。每个版本带有从其结构推出的可执行条件，我们证明这些条件足以让生成的 SQL 把每个业务事件在其期间内只计数一次（命题~\ref{prop:sufficiency}）。条件所读的表变化时，\system\ 检查这些条件，并在定义与智能体之间共享检查结果；条件失败则导致唯一的、经过回归测试的修复（第 5--7 步）或失效；查询只在版本条件成立的快照上使用该版本。由于所有智能体复用同一份 SQL，\system\ 还发布更省的等价版本，使一次优化让每个智能体都更快（第 3 步）。}

\bi{We evaluate the cost of sharing directly. When \PpAgents\ agents arrive at one TPC-DS database and ask a mix of questions, \system\ uses \PpMavraTokSaveNone\% fewer tokens than agents without memory and its agents finish \PpMavraSpeedupNone$\times$ faster; against single-agent memory built with the same learning and checks, it uses \PpMavraTokSavePrivate\% fewer tokens and is \PpMavraSpeedupPrivate$\times$ faster, because each metric is explored once instead of once per agent. Once a metric is learned, an agent answers with \PpMavraLateTokXNone$\times$ fewer tokens and \PpMavraLateSpeedupNone$\times$ faster than exploring alone, and more answers are correct (\PpMavraAcc\% against \PpNoneAcc\% and \PpPrivateAcc\%). Sharing examples of past sessions saves as much on unchanged data but hands stale SQL to every agent after an update: after a restatement, \system's agents answer \PpMavraChangeAcc\% correctly and those of example retrieval \PpTrajChangeAcc\%, and under the breaking changes the conditions cover on two schemas, \system\ keeps \DsCondModeled--\GeCondModeled\% of answers correct against \GeTrajModeled--\DsTrajModeled\%.}
{我们直接测量共享的代价。当 \PpAgents\ 个智能体陆续使用同一 TPC-DS 数据库、提出各种问题时，\system\ 比无记忆的智能体少用 \PpMavraTokSaveNone\% 的 token，其智能体快 \PpMavraSpeedupNone\ 倍；与用同样的学习与检查构建的单智能体记忆相比，少用 \PpMavraTokSavePrivate\% 的 token、快 \PpMavraSpeedupPrivate\ 倍，因为每个指标只探索一次，而不是每个智能体探索一次。指标学会之后，智能体每题比独自探索少用 \PpMavraLateTokXNone\ 倍 token、快 \PpMavraLateSpeedupNone\ 倍，答对的也更多（\PpMavraAcc\%，后两者为 \PpNoneAcc\% 与 \PpPrivateAcc\%）。共享以往会话的示例在数据不变时省下同样多的工作，但更新之后会把过期的 SQL 交给每个智能体：一次更正之后，\system\ 的智能体答对 \PpMavraChangeAcc\%，示例检索为 \PpTrajChangeAcc\%；在两种模式上条件覆盖的破坏性变化下，\system\ 保持 \DsCondModeled--\GeCondModeled\% 的答案正确，示例检索为 \GeTrajModeled--\DsTrajModeled\%。}

\bi{This paper makes the following contributions:}
{本文的贡献如下：}
\begin{itemize}
\item \bi{A shared memory layer for data agents that turns per-agent exploration into knowledge learned once per database and reused by every agent, motivated by a study of agent workloads (Sections~\ref{sec:background} and~\ref{sec:overview}).}
{一个数据智能体的共享记忆层，把按智能体重复的探索变成每个数据库只学一次、所有智能体复用的知识，并以对智能体负载的分析为动机（第~\ref{sec:background} 和~\ref{sec:overview} 节）。}
\item \bi{The mechanisms that keep shared knowledge correct and cheap for all agents at once: definitions with executable conditions proved sufficient, publication checks on what consumers read, shared check results with unique as-of repair and same-snapshot execution, and optimization revisions (Section~\ref{sec:model}).}
{为所有智能体一次性保持共享知识正确且便宜的机制：带可执行条件、经证明充分的定义，针对使用者所读内容的发布前检查，共享检查结果、按学习时刻的唯一修复与同快照执行，以及优化版本（第~\ref{sec:model} 节）。}
\item \bi{An evaluation of what sharing saves (Section~\ref{sec:evaluation}): across a population of agents against no memory, single-agent memory, and shared examples; per question on two schemas; and under data changes, end to end and by replaying fixed libraries on four schemas (TPC-DS, TPC-H, SSB, and a real bank database).}
{一套测量共享省下多少的评估（第~\ref{sec:evaluation} 节）：在一群智能体上与无记忆、单智能体记忆和共享示例比较；在两种模式上按每道题比较；以及在数据变化下的端到端实验和在四种模式（TPC-DS、TPC-H、SSB 与一家银行的真实数据库）上回放固定定义库。}
\end{itemize}
