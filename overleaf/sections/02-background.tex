\subsection{\bt{Repeated knowledge across agent queries}{智能体查询之间的知识重复}}
\label{sec:workload-characterization}
\bi{Tasks over the same database often draw on the same calculations, domain rules, and value meanings. Table~\ref{tab:external} measures this overlap in released text-to-SQL benchmarks. Among tasks with identified knowledge needs, \ExLsSharePct\% on LiveSQLBench and \ExBdSharePct\% on BIRD share knowledge with another task on their database. In LiveSQLBench, \ExLsRepeatPct\% of knowledge uses repeat an earlier use, with similar repetition among calculations. The table's final rows show the opportunity growing as more tasks arrive: an increasing share of each task's required knowledge has appeared in earlier tasks. Answering each task in a fresh session repeatedly incurs the cost of discovering that knowledge.}
{同一数据库上的任务往往依赖相同的计算、领域规则和取值含义。表~\ref{tab:external} 在已发布的 Text-to-SQL 基准中测量这种重叠。在已识别出知识需求的任务中，LiveSQLBench 的 \ExLsSharePct\% 和 BIRD 的 \ExBdSharePct\% 与同库其他任务共用知识。LiveSQLBench 中，\ExLsRepeatPct\% 的知识使用重复了此前的使用，计算类知识也有相近的重复程度。表格最后几行展示复用机会随任务增长的趋势：每个任务所需知识中，越来越多已在此前任务中出现。每项任务都从新会话开始回答，就会反复付出发现这些知识的代价。}

\bi{The measurement uses the knowledge supplied by each benchmark. LiveSQLBench, the basis of BIRD-Interact~\cite{livesqlbench2025,huo2026birdinteract}, provides \ExLsKb\ knowledge-base entries across \ExLsDbs\ PostgreSQL databases; BIRD supplies evidence defining each question's terms~\cite{li2023bird}. Because LiveSQLBench does not release task-to-entry dependencies, we count a dependency when a question names an entry or an entry built on it. For BIRD, we count the terms defined in its evidence. This lexical measure captures explicit reuse and gives a conservative estimate by leaving implicit references and paraphrases uncounted.}
{测量依据各基准提供的知识。LiveSQLBench 是 BIRD-Interact 的基础~\cite{livesqlbench2025,huo2026birdinteract}，为 \ExLsDbs\ 个 PostgreSQL 数据库提供 \ExLsKb\ 条知识；BIRD 则为每个问题提供定义其术语的证据~\cite{li2023bird}。LiveSQLBench 未公开任务与条目的依赖关系，因此我们在问题点名某条目或依赖它的条目时计入依赖；对 BIRD，则统计证据定义的术语。这种词汇度量捕捉显式复用，未计入隐含引用和不同措辞的表达，因此给出保守估计。}

\bi{The two workloads repeat work at different levels. Redset repeats an earlier template in 93.4\% of statements, with only 6.6 templates per 100 statements; prepared statements and a result cache serving 34\% of reads fit this workload well. The agent trace has 76 templates per 100 statements, because sessions write SQL anew. Yet 93\% of their lookups recover a fact obtained by an earlier session. None of the SQL probes repeating a fact has identical text to an earlier probe, so query-text caching misses this repetition.}
{两类负载在不同层面重复工作。Redset 中 93.4\% 的语句重复已有模板，每百条语句只有 6.6 个模板；预编译语句和服务了 34\% 读查询的结果缓存很适合这一负载。智能体轨迹每百条语句则有 76 个模板，因为会话会重新编写 SQL；然而，它们 93\% 的查找都在获取此前会话已经得到的事实。重复事实的 SQL 探查没有一条与先前探查的文本相同，按查询文本索引的缓存因而无法利用这种重复。}

\bi{Knowledge reuse can also save the LLM work around a query. Exact or semantic result caching makes a probe cheaper to execute, while the agent still has to formulate it and interpret its output. In our trace, 57\% of LLM calls issue no SQL used by the answer, and 71\% of session time passes before the answer SQL starts. Liu et al.\ observe a similar pattern for an OpenAI o3-based agent: of 12.67 statements per task, 3.44 explore tables and 3.56 explore columns. Expert hints reduce column exploration by 27.7\% and total statements by 18.1\%~\cite{liu2026agents}. \system\ supplies such database knowledge from earlier sessions so later agents can bypass its discovery.}
{知识复用还可以省去查询前后的大模型工作。精确匹配或语义结果缓存能降低探查的执行代价，智能体却仍需构造探查并解释输出。在我们的轨迹中，57\% 的大模型调用不发出答案所用的 SQL，71\% 的会话时间发生在答案 SQL 开始之前。Liu 等人在基于 OpenAI o3 的智能体中观察到相似现象：每任务的 12.67 条语句中，3.44 条查看表，3.56 条查看列；专家提示使列探索减少 27.7\%，总语句数减少 18.1\%~\cite{liu2026agents}。\system\ 从此前会话积累这类数据库知识，让后续智能体省去发现它们的过程。}

\bi{Sharing definitions also addresses errors that SQL execution alone cannot reveal. Of 32 wrong answers in our trace, 31 arise when a question names a metric without defining it. Only 16\% of sessions check key uniqueness. A shared definition supplies the missing business meaning and gives the layer explicit conditions to maintain for later consumers.}
{共享定义还针对 SQL 执行本身无法揭示的错误。轨迹中的 32 个错误答案，有 31 个发生在问题只给指标名而不给定义时；只有 16\% 的会话检查键唯一性。共享定义提供缺失的业务含义，也为共享层提供明确条件，供其为后续使用者持续维护。}

\subsection{\bt{Amortizing exploration across agents}{跨智能体分摊探索开销}}
\label{sec:alternatives}
\bi{Sharing memory across agents amortizes the discovery of database knowledge. A private memory serves the later sessions of its owner; a database-wide memory also serves other agents whose questions use the same definitions. With $N$ agents and $k$ metrics, private copies can require up to $Nk$ discoveries, whereas under stable data one successful publication per metric can serve the population. \system\ makes these publications executable for new periods and tasks, reducing both repeated discovery and the work of translating knowledge into SQL. The population study measures this effect using shared and private copies of the same learning and validation mechanisms (Section~\ref{sec:population-eval}).}
{跨智能体共享记忆可以分摊数据库知识的发现开销。私有记忆服务其拥有者的后续会话；数据库范围的共享记忆还服务使用相同定义的其他智能体。对于 $N$ 个智能体和 $k$ 个指标，私有副本至多需要 $Nk$ 次发现；数据稳定时，每个指标一次成功发布即可服务整个群体。\system\ 将这些发布的定义编译为新期间和任务所需的查询，同时减少重复发现以及把知识转化为 SQL 的工作。群体实验使用学习和验证机制相同的共享与私有副本，测量这一效果（第~\ref{sec:population-eval} 节）。}

\bi{\emph{A cost model.} Let $N$ agents each ask $q$ questions about $k$ metrics, let $c_e$ be the cost of answering a question by exploration and $c_r$ the cost of answering it from memory, and let $c_l$ be the cost of learning one definition (extraction and publication checks). Assume stable definitions and one successful publication per metric. Without memory the agents pay $Nq\,c_e$. Shared memory pays at most $k(c_e+c_l)$ for the first question about each metric and $(Nq-k)\,c_r$ for the rest, plus its upkeep once per data change, so its saving
\[ 1-\frac{k(c_e+c_l)+(Nq-k)\,c_r}{Nq\,c_e}\;\longrightarrow\;1-\frac{c_r}{c_e}\qquad(N\to\infty) \]
grows with every agent that arrives. Per-agent memory pays the learning up to $Nk$ times and reuses only when an agent asks about a metric it learned itself, which is rare when each agent asks a few of many questions, so its cost stays near $Nq\,c_e$. Section~\ref{sec:population-eval} measures both: on TPC-DS, $c_e$ is \PpNoneLateTokK\,k tokens and $c_r$ is \PpMavraLateTokK\,k, so the token saving approaches \PpMavraAsymTokSaveNone\%. Writing $r=(Nq-k)/Nq$ for the share of questions answered from memory, the saving is $1-(1-r)(c_e+c_l)/c_e-r\,c_r/c_e$. With $c_l=\ExModelLearnTokK$\,k tokens, the model gives \ExModelTokSaveOurs\% at the \ExModelReusePct\% of questions that \system's agents answer from memory, the saving we measure.}
{\emph{代价模型。}设 $N$ 个智能体各就 $k$ 个指标提 $q$ 个问题，$c_e$ 为靠探索回答一道题的代价，$c_r$ 为从记忆回答一道题的代价，$c_l$ 为学习一个定义的代价（提取与发布前检查）。假定定义稳定、每个指标一次成功发布。没有记忆时，智能体共付 $Nq\,c_e$。共享记忆为每个指标的第一道题至多付 $k(c_e+c_l)$，其余的题付 $(Nq-k)\,c_r$，再加上每次数据变化只付一次的维护，因此它的节省
\[ 1-\frac{k(c_e+c_l)+(Nq-k)\,c_r}{Nq\,c_e}\;\longrightarrow\;1-\frac{c_r}{c_e}\qquad(N\to\infty) \]
随每个新到的智能体增长。单智能体记忆至多要付 $Nk$ 次学习，且只在智能体问到自己学过的指标时才复用；每个智能体只从众多问题中问几个时，这很少发生，因此它的代价停留在 $Nq\,c_e$ 附近。第~\ref{sec:population-eval} 节测量了这两者：在 TPC-DS 上，$c_e$ 为 \PpNoneLateTokK\,k token，$c_r$ 为 \PpMavraLateTokK\,k，因此 token 的节省趋近 \PpMavraAsymTokSaveNone\%。记 $r=(Nq-k)/Nq$ 为从记忆作答的题目占比，节省即为 $1-(1-r)(c_e+c_l)/c_e-r\,c_r/c_e$。取 $c_l=\ExModelLearnTokK$\,k token，模型在 \system\ 的智能体从记忆作答的 \ExModelReusePct\% 处给出 \ExModelTokSaveOurs\%，与实测的节省一致。}
