\bi{In a parameterized application, query templates and database knowledge reside in code, so millions of queries reduce to thousands of templates~\cite{ma2018querybot}; a new data-agent session must acquire that knowledge through schema lookups, data probes, and checks. Table~\ref{tab:workload-characterization} compares two workloads. The application side is Redset~\cite{vanrenen2024redset}: 441 million queries of 400 Amazon Redshift clusters over three months, analyzed per cluster with the dataset's template fingerprint, which overestimates repetition~\cite{redset2024dataset}. The agent side is 100 new DeepSeek V4.1 Flash sessions, each answering one of 25 questions of Section~\ref{sec:evaluation} (the learning questions and the first three scored types) with table-listing, table-description, and SQL tools and no shared state. A lookup's \emph{fact} is its purpose together with the tables and columns it reads.}
{在参数化应用中，查询模板和数据库知识保存在代码里，数百万条查询可归并为数千个模板~\cite{ma2018querybot}；全新的数据智能体会话则必须通过结构查找、数据探查和检查获得这些知识。表~\ref{tab:workload-characterization} 对照两类负载。应用侧采用 Redset~\cite{vanrenen2024redset}：400 个 Amazon Redshift 集群三个月的 4.41 亿条查询，按集群分析，模板标识采用数据集自带的特征指纹，它会高估重复程度~\cite{redset2024dataset}。智能体侧是 100 个全新的 DeepSeek V4.1 Flash 会话，每个会话回答第~\ref{sec:evaluation} 节 25 道题（学习题与前三种计分题型）中的一道，只有列出表、描述表和执行 SQL 三种工具，互不共享状态。查找所获得的\emph{事实}由其目的及读取的表和列确定。}

\bi{Applications repeat queries, which prepared statements and result caches serve well. Agents repeat knowledge: their SQL changes from session to session, while almost every lookup repeats a fact that an earlier session obtained, and since no repeated SQL probe repeats its text, a cache keyed by query text serves none of them. Answers are wrong without any failure: 31 of the 32 wrong answers occur when a question names a metric without defining it, exactly where a shared definition helps. And only 16\% of sessions check key uniqueness, the kind of condition that \system\ maintains on their behalf.}
{应用重复的是查询，预编译语句和结果缓存能很好地服务它们。智能体重复的是知识：它们的 SQL 在会话之间不断变化，而几乎每次查找都在重复此前会话已经得到的事实；重复事实的 SQL 探查没有一条文本相同，因此按查询文本索引的缓存一条也服务不了。答案在没有任何报错的情况下出错：32 个错误答案中有 31 个出现在题目只给出指标名而不给定义时，这正是共享定义能帮上忙的地方。只有 16\% 的会话检查键唯一性，而这正是 \system\ 代为维护的那类条件。}

\subsection{\bt{Per-agent memory and shared memory}{单智能体记忆与共享记忆}}
\label{sec:alternatives}
\bi{Three kinds of memory can remove this repeated exploration, and they differ in who benefits. \emph{Per-agent memory}, the design of current agent memory systems, keeps what one agent learned for that agent's later sessions: a new agent starts empty and explores every metric it is asked about, and an agent that asks about a metric once gains nothing from having learned it. \emph{Shared examples} store the successful sessions of all agents and retrieve them by question similarity~\cite{biswal2026agentsm}: every agent benefits, but an example is the SQL of one question on one past snapshot. \emph{Shared knowledge}, the design of \system, stores the definition behind such SQL with its question parameters removed, so that every agent can compile it for its own question. With $N$ agents asking about $k$ metrics, per-agent memory explores up to $N\cdot k$ times and shared memory $k$ times; Section~\ref{sec:population-eval} measures the difference.}
{有三类记忆可以消除这种重复探索，它们的区别在于谁受益。\emph{单智能体记忆}是现有智能体记忆系统的做法，把一个智能体学到的东西留给它自己以后的会话：新来的智能体从空开始，每遇到一个指标都要探索；只问一次某个指标的智能体，学到了也用不上。\emph{共享示例}保存所有智能体的成功会话，按题面相似度检索~\cite{biswal2026agentsm}：每个智能体都受益，但一个示例只是某道题在某个过去快照上的 SQL。\emph{共享知识}是 \system\ 的做法，保存这些 SQL 背后去掉题目参数的定义，使每个智能体都能针对自己的问题编译它。若 $N$ 个智能体问到 $k$ 个指标，单智能体记忆最多探索 $N\cdot k$ 次，共享记忆探索 $k$ 次；第~\ref{sec:population-eval} 节测量其差别。}

\bi{\emph{A cost model.} Let $N$ agents each ask $q$ questions about $k$ metrics, let $c_e$ be the cost of answering a question by exploration and $c_r$ the cost of answering it from memory, and let $c_\ell$ be the cost of learning one definition (extraction and publication checks). Without memory the agents pay $Nq\,c_e$. Shared memory pays at most $k(c_e+c_\ell)$ for the first question about each metric and $(Nq-k)\,c_r$ for the rest, plus its upkeep once per data change, so its saving
\[ 1-\frac{k(c_e+c_\ell)+(Nq-k)\,c_r}{Nq\,c_e}\;\longrightarrow\;1-\frac{c_r}{c_e}\qquad(N\to\infty) \]
grows with every agent that arrives. Per-agent memory pays the learning up to $Nk$ times and reuses only when an agent asks about a metric it learned itself, which is rare when each agent asks a few of many questions, so its cost stays near $Nq\,c_e$. Section~\ref{sec:population-eval} measures both: on TPC-DS, $c_e$ is \PpNoneLateTokK\,k tokens and $c_r$ is \PpMavraLateTokK\,k, so the token saving approaches \PpMavraAsymTokSaveNone\%.}
{\emph{代价模型。}设 $N$ 个智能体各就 $k$ 个指标提 $q$ 个问题，$c_e$ 为靠探索回答一道题的代价，$c_r$ 为从记忆回答一道题的代价，$c_\ell$ 为学习一个定义的代价（提取与发布前检查）。没有记忆时，智能体共付 $Nq\,c_e$。共享记忆为每个指标的第一道题至多付 $k(c_e+c_\ell)$，其余的题付 $(Nq-k)\,c_r$，再加上每次数据变化只付一次的维护，因此它的节省
\[ 1-\frac{k(c_e+c_\ell)+(Nq-k)\,c_r}{Nq\,c_e}\;\longrightarrow\;1-\frac{c_r}{c_e}\qquad(N\to\infty) \]
随每个新到的智能体增长。单智能体记忆至多要付 $Nk$ 次学习，且只在智能体问到自己学过的指标时才复用；每个智能体只从众多问题中问几个时，这很少发生，因此它的代价停留在 $Nq\,c_e$ 附近。第~\ref{sec:population-eval} 节测量了这两者：在 TPC-DS 上，$c_e$ 为 \PpNoneLateTokK\,k token，$c_r$ 为 \PpMavraLateTokK\,k，因此 token 的节省趋近 \PpMavraAsymTokSaveNone\%。}

\bi{Table~\ref{tab:capabilities} places these designs next to three that data systems already offer. Query and result caches are shared but save only on a query that repeats, and they stay correct by invalidating on writes, which also discards the saving. Metric layers share definitions that engineers write by hand and do not validate at run time. Data validation tests tables, not the knowledge that depends on them. {表~\ref{tab:capabilities} 把这些设计与数据系统已有的三种设计放在一起比较。查询与结果缓存是共享的，但只在查询重复时省下代价，并靠写入时失效保持正确，这也一并丢掉了节省。指标层共享由工程师手写的定义，运行时并不验证。数据验证检查的是表，而不是依赖这些表的知识。这些设计没有一种能同时做到：为每个智能体省下代价，在尚无人问过的问题上省下代价，所用的知识从智能体自己的会话中学到，并在数据变化后保住这份节省。\system\ 同时做到这四点，并为所有智能体对每个共享定义只付一次维护代价。}
