\section{\bt{System Overview}{系统概览}}
\label{sec:overview}
\bi{\system\ is a shared memory layer between data agents and a SQL database, PostgreSQL in our prototype. It shares verified, executable metric and feature definitions, their numbered revisions and learning records, and check results. Agents supply analytical questions or prediction tasks; the layer returns reusable definitions and SQL for the requested period or seed table. Figure~\ref{fig:architecture} summarizes its publication, reuse, and maintenance paths.}
{\system\ 是位于数据智能体与 SQL 数据库之间的共享记忆层，原型使用 PostgreSQL。它共享经验证的可执行指标与特征定义、定义版本及其学习记录，以及检查结果。智能体提供分析问题或预测任务；系统返回可复用的定义，以及针对所需期间或种子表生成的 SQL。图~\ref{fig:architecture} 概括其发布、复用和维护三条路径。}

\bi{\emph{Learn and publish.} Agents explore through common table, join, and SQL tools. For metric questions, they submit answers with the query references and arithmetic that produced them; for prediction tasks, they submit feature SQL and validation scores. From successful sessions, \system\ extracts structured candidates and publishes revisions only after deterministic checks (Sections~\ref{sec:shared-object} and~\ref{sec:features}). Agents cannot write definitions directly. Table descriptions and verified join paths are also shared to reduce repeated exploration.}
{\emph{学习与发布。}智能体通过共用的表、连接和 SQL 工具开展探索。对于指标问题，提交答案时附上产生答案的查询编号和算式；对于预测任务，则提交特征 SQL 和验证分数。\system\ 从成功会话中提取结构化候选，仅在通过确定性检查后发布版本（第~\ref{sec:shared-object} 与~\ref{sec:features} 节）。智能体不能直接写入定义。表描述和经验证的连接路径也会共享，以减少重复探索。}

\bi{\emph{Retrieve and execute.} For analytics, \code{find\_metric} supplies a valid revision and its SQL. The agent passes the revision to \code{run\_sql}, which checks the conditions on the query's snapshot before executing the SQL (Section~\ref{sec:execution}). For prediction tasks, \code{find\_features} retrieves definitions for the target entity. Then \code{compose\_features} compiles the selected definitions into SQL for the seed table, with temporal bounds for each instance (Section~\ref{sec:features}). Missing or invalid definitions lead agents back to exploration.}
{\emph{检索与执行。}对于分析查询，\code{find\_metric} 返回有效版本及生成的 SQL。智能体在 \code{run\_sql} 中声明该版本，后者先在执行快照上检查其条件，再运行查询（第~\ref{sec:execution} 节）。对于预测任务，\code{find\_features} 检索目标实体的定义，\code{compose\_features} 将选定定义编译为针对种子表、带逐样本时间边界的 SQL（第~\ref{sec:features} 节）。定义未命中或失效时，智能体重新探索。}

\bi{\emph{Validate and maintain.} After an update, \system\ rechecks conditions whose dependencies changed, sharing matching check results across definitions and agents. It repairs affected metric definitions or invalidates them, and revokes feature definitions whose conditions fail (Sections~\ref{sec:maintenance} and~\ref{sec:features}). Cheaper equivalent metric revisions are checked before publication and shared by all consumers, amortizing optimization as well as maintenance (Section~\ref{sec:optimization}).}
{\emph{验证与维护。}数据更新后，\system\ 重新检查依赖发生变化的条件，在定义与智能体之间共享匹配的检查结果。系统修复受影响的指标定义或将其置为失效，并撤销条件不再成立的特征定义（第~\ref{sec:maintenance} 与~\ref{sec:features} 节）。开销更低的等价指标版本在发布前经过检查，随后向所有使用者共享，从而共同分摊优化与维护开销（第~\ref{sec:optimization} 节）。}
