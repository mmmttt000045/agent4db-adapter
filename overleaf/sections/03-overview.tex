\section{\bt{System Overview}{系统概览}}
\label{sec:overview}
\bi{\system\ sits between agents and PostgreSQL (Figure~\ref{fig:architecture}). It exposes tool-style HTTP endpoints for listing and describing tables, finding and checking join paths, looking up metric definitions (\code{find\_metric}), and running SQL (\code{run\_sql}); agents submit final answers with the query references and arithmetic that produced them, so the middleware records a calculation chain for every task. An in-memory store keeps versioned definitions, join paths, grain entries, verdicts, and evidence. Version detection reads table fingerprints, DML statistics, and an ETL batch log; in snapshot-bound mode, statement-level triggers maintain transactional table versions (Section~\ref{sec:snapshot}). The middleware is about 6,600 lines of Rust with 40 unit and integration tests.}
{\system\ 位于智能体与 PostgreSQL 之间（图~\ref{fig:architecture}）。它通过工具式 HTTP 接口提供列出和描述表、查找与检查连接路径、查找指标定义（\code{find\_metric}）以及执行 SQL（\code{run\_sql}）等功能；智能体提交最终答案时附上产生答案的查询编号和算式，因此中间层为每个任务记录一条计算链。内存知识库保存版本化的定义、连接路径、粒度条目、条件结论和证据。版本检测读取表指纹、DML 统计和 ETL 批次日志；在绑定快照模式下，语句级触发器维护事务性表版本（第~\ref{sec:snapshot} 节）。中间层约 6,600 行 Rust 代码，含 40 个单元与集成测试。}

\bi{A definition moves through three paths. On the \emph{learning path}, an agent answers a question whose business meaning is stated explicitly; if an independent judge accepts the answer, an offline extractor turns the recorded calculation chain into a structured candidate, which the admission gates validate before publication. On the \emph{use path}, another agent calls \code{find\_metric}; if any dependency version has changed, the lookup first runs condition maintenance and then returns the current valid revision with its fields and caveats. On the \emph{execution path}, the agent's \code{run\_sql} declares the metric keys and revisions it uses; the middleware rejects absent, revoked, or superseded revisions, reviews the SQL against recorded grain and join requirements, and, in snapshot-bound mode, checks the revisions' conditions and runs the query on one snapshot. Revocations reach agents as notices on their next tool response.}
{一个定义经过三条路径。在\emph{学习路径}上，智能体回答一道显式给出业务含义的题目；若独立判题接受其答案，离线提炼器把记录的计算链转成结构化候选，由准入门槛验证后发布。在\emph{使用路径}上，另一个智能体调用 \code{find\_metric}；若有依赖版本变化，查找先执行条件维护，再返回当前有效修订及其字段和注意事项。在\emph{执行路径}上，智能体在 \code{run\_sql} 中声明所用的指标键和修订号；中间层拒绝不存在、已撤销或已被替代的修订，按记录的粒度和连接要求审查 SQL，并在绑定快照模式下于同一快照上核对修订条件、执行查询。撤销通过智能体下一次工具调用的返回中的通知传达。}
