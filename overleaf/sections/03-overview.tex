\section{\bt{System Overview}{系统概览}}
\label{sec:overview}
\bi{\system{} stores reusable computations and applicability conditions between data agents and PostgreSQL (Figure~\ref{fig:architecture}); agents retain their own session histories.}
{\system{} 在数据智能体与 PostgreSQL 之间保存可复用计算及适用条件（图~\ref{fig:architecture}），智能体保留自身会话历史。}
\subsection{\bt{Components and shared state}{组件与共享状态}}
\bi{\emph{Shared knowledge} stores metric revisions $m_i^r$, feature revisions $f_i^r$, and their required conditions $C$. Here $i$ identifies an object and $r$ its revision. Each condition $c$ has a check query $Q_c$; cached results carry the versions $V(T)$ of tables $T$ read by that query. Table descriptions and verified joins are also shared. \emph{Publish} extracts and checks candidates; \emph{Lookup} consults the \emph{Version tracker}; \emph{Maintain} refreshes checks and invokes \emph{Metric repair}; \emph{Compile and run} instantiates accepted definitions. Independent ETL jobs and writers change the database.}
{\emph{共享知识}保存指标修订 $m_i^r$、特征修订 $f_i^r$ 及所需条件 $C$，对象标识 $i$ 与修订号 $r$ 分开。各条件 $c$ 具有检查查询 $Q_c$，缓存结果携带所读表 $T$ 的版本 $V(T)$。定义、检查结果、表描述和验证连接在智能体间共享。\emph{发布}提取并检查候选，\emph{查找}访问\emph{版本跟踪}，\emph{维护}刷新检查并调用\emph{指标修复}，\emph{编译与执行}实例化已通过检查的定义。ETL 和其他写入方独立修改数据库。}

\subsection{\bt{End-to-end workflow}{端到端工作流程}}
\bi{\emph{Publication (1--3).} A successful session supplies its question, SQL trace, and answer provenance. The extractor separates reusable computation from question parameters; the deterministic gate checks fields, data assumptions, and reproduction before publishing a revision. Sections~\ref{sec:publication} and~\ref{sec:features} give metric and feature checks.}
{\emph{发布（1--3）。}成功会话提供题目、SQL 轨迹和答案溯源。提取器分离可复用计算与问题参数，确定性检查验证字段、数据前提和计算重现后发布修订。第~\ref{sec:publication}、\ref{sec:features} 节给出指标及特征检查。}
\bi{\emph{Lookup and maintenance (4--7).} A consumer requests a definition, supplying its own period or prediction seeds. Lookup returns an applicable revision and generated SQL, replacing repeated schema inspection, probes, and join tests. Stale evidence enters Maintain, which reuses version-matching results and runs missing checks. Failed metric conditions trigger repair; regression-approved replacements become $m^{r+1}$, while unrepaired revisions become unavailable. Concurrent requests share in-flight validation and repair (Section~\ref{sec:maintenance}).}
{\emph{查找与维护（4--7）。}使用者请求定义并提供自己的期间或预测种子，查找返回适用修订及生成 SQL，替代重复的模式检查、探查和连接测试。过期证据进入维护，复用版本匹配结果、执行缺失检查。失败的指标条件触发修复，通过回归的替代版本记为 $m^{r+1}$，未修复版本不可用；并发请求共享在途验证与修复（第~\ref{sec:maintenance} 节）。}
\bi{\emph{Execution (8--9).} A metric consumer submits query $q$ and declared revisions. The system checks every $c\in C(m^r)$ and runs $q$ in the same read-only snapshot $s$, with visible state $D_s$. Feature compilation instead bounds each event time $t$ by its seed time $t_i$, excluding future events. Sections~\ref{sec:execution} and~\ref{sec:features} detail these paths.}
{\emph{执行（8--9）。}指标使用者提交查询 $q$ 及声明修订，系统在可见状态为 $D_s$ 的同一只读快照 $s$ 中检查全部 $c\in C(m^r)$ 并执行 $q$。特征编译则以种子时间 $t_i$ 为事件时间 $t$ 的上界，排除未来事件。第~\ref{sec:execution}、\ref{sec:features} 节展开两条路径。}
\subsection{\bt{Sharing and selective revalidation}{共享与选择性重验}}
\bi{In Figure~\ref{fig:architecture}, two agents reuse $m_1^{\mathrm{v}3}$ for September/October, and a prediction agent reuses $f_1^{\mathrm{v}1}$. Condition $c_2$ on $T_3$ serves $m_1^{\mathrm{v}3}$, $m_2^{\mathrm{v}1}$, and $f_1^{\mathrm{v}1}$. If ETL changes $V(T_2)$ from \ensuremath{\mathrm{v}13} to \ensuremath{\mathrm{v}14}, $c_3$ loses matching evidence and $m_2^{\mathrm{v}1}$ becomes pending; unchanged $T_1/T_3$ preserve the revenue and spending definitions. Failed $c_4$ makes $m_3^{\mathrm{v}2}$ invalid. }
{图~\ref{fig:architecture}中，两个智能体为九／十月复用 $m_1^{\mathrm{v}3}$，预测智能体复用 $f_1^{\mathrm{v}1}$。$T_3$ 上的条件 $c_2$ 服务于 $m_1^{\mathrm{v}3}$、$m_2^{\mathrm{v}1}$ 和 $f_1^{\mathrm{v}1}$。若 ETL 将 $V(T_2)$ 从 \ensuremath{\mathrm{v}13} 改为 \ensuremath{\mathrm{v}14}，$c_3$ 失去匹配证据，$m_2^{\mathrm{v}1}$ 转为待验证；未变的 $T_1/T_3$ 保留营业额与消费定义。失败的 $c_4$ 使 $m_3^{\mathrm{v}2}$ 无效。}
