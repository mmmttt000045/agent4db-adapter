\section{\bt{System Overview}{系统概览}}
\label{sec:overview}
\bi{\system\ is a shared memory layer between data agents and a SQL database, PostgreSQL in our prototype (Figure~\ref{fig:architecture}). Every agent reaches the database through the same tools: it lists and describes tables, finds join paths, looks up metric definitions with \code{find\_metric}, and runs SQL with \code{run\_sql}. Agents submit final answers with the query references and arithmetic that produced them, so \system\ records how every answer was computed and can learn from it. The memory keeps the numbered revisions of each definition, join paths, check results, and learning records, and it is one memory for all agents: whatever any agent's session teaches it, every other agent can use.}
{\system\ 是位于数据智能体与 SQL 数据库之间的共享记忆层，原型使用 PostgreSQL（图~\ref{fig:architecture}）。所有智能体都通过同一组工具访问数据库：列出和描述表、查找连接路径、查找指标定义（\code{find\_metric}）以及执行 SQL（\code{run\_sql}）。智能体提交最终答案时附上产生答案的查询编号和算式，因此 \system\ 记录每个答案是如何算出的，并能从中学习。记忆保存各定义的版本、连接路径、检查结果和学习记录，并且所有智能体共用这一份记忆：任何一个智能体的会话教给它的东西，其他每个智能体都能使用。}

\bi{A definition moves through the three paths of Figure~\ref{fig:architecture}. On the \emph{learning path}, a session whose question states the business definition and whose answer matches the reference answer is turned into a candidate, and the publication checks decide whether it becomes shared (Section~\ref{sec:shared-object}). On the \emph{use path}, \code{find\_metric} rechecks the conditions whose tables changed and returns the valid revision with its generated SQL, which the agent runs instead of exploring. On the \emph{execution path}, \code{run\_sql} rejects declared revisions that are absent or invalidated and runs the query on a snapshot on which their conditions hold (Section~\ref{sec:execution}). Agents read a revision's business definition, fields, generated and example SQL, and revision number; \system\ keeps its conditions and their check results. No agent writes to the memory directly, so one agent's mistake cannot reach the others without passing the checks.}
{一个定义经过图~\ref{fig:architecture} 的三条路径。在\emph{学习路径}上，题目给出业务定义、且答案与参考答案一致的会话被转成候选，由发布前检查决定它是否成为共享内容（第~\ref{sec:shared-object} 节）。在\emph{使用路径}上，\code{find\_metric} 重查所读表发生变化的条件，返回有效版本及其生成的 SQL，智能体执行它而不必探索。在\emph{执行路径}上，\code{run\_sql} 拒绝不存在或已失效的声明版本，并在这些版本的条件成立的快照上执行查询（第~\ref{sec:execution} 节）。智能体读到一个版本的业务定义、字段、生成的 SQL 与示例 SQL 和版本号；\system\ 保管它的条件与检查结果。任何智能体都不直接写记忆，因此一个智能体的错误不经过检查就到不了其他智能体。}
