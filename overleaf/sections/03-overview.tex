\section{\bt{System Overview}{系统概览}}
\label{sec:overview}
\bi{\system\ is a shared memory layer between data agents and a SQL database, PostgreSQL in our prototype (Figure~\ref{fig:architecture}). Every agent reaches the database through the same tools: it lists and describes tables, finds join paths, looks up metric definitions with \code{find\_metric}, and runs SQL with \code{run\_sql}. Agents submit final answers with the query references and arithmetic that produced them, so \system\ records how every answer was computed and can learn from it. The memory keeps the numbered revisions of each definition with their learning records, along with table descriptions, join paths, and check results (Section~\ref{sec:shared-object} states what is shared and what is not), and it is one memory for all agents: whatever any agent's session teaches it, every other agent can use.}
{\system\ 是位于数据智能体与 SQL 数据库之间的共享记忆层，原型使用 PostgreSQL（图~\ref{fig:architecture}）。所有智能体都通过同一组工具访问数据库：列出和描述表、查找连接路径、查找指标定义（\code{find\_metric}）以及执行 SQL（\code{run\_sql}）。智能体提交最终答案时附上产生答案的查询编号和算式，因此 \system\ 记录每个答案是如何算出的，并能从中学习。记忆保存各定义的版本及其学习记录，以及表描述、连接路径和检查结果（哪些内容共享、哪些不共享见第~\ref{sec:shared-object} 节），并且所有智能体共用这一份记忆：任何一个智能体的会话教给它的东西，其他每个智能体都能使用。}


\bi{A definition moves through the three paths of Figure~\ref{fig:architecture}. \emph{Publish} (1--2): one agent explores and answers a question whose business definition is stated; when its answer is verified, \system\ extracts a candidate and publishes it after the publication checks (Section~\ref{sec:shared-object}). \emph{Use} (3--5): every other agent looks the metric up with \code{find\_metric}, receives the valid revision with its generated SQL, and answers with one query instead of exploring; it declares the revision to \code{run\_sql}, and \system\ runs the query on a snapshot on which the revision's conditions hold (Section~\ref{sec:execution}). \emph{Maintain and optimize} (6--8): when updates change a table, \system\ rechecks only the conditions over changed tables, reusing check results across definitions and agents, repairs or invalidates a broken definition, and publishes cheaper equivalent revisions, each once for all agents (Sections~\ref{sec:maintenance} and~\ref{sec:optimization}). No agent writes to the memory directly, so one agent's mistake cannot reach the others without passing the checks.}
{一个定义经过图~\ref{fig:architecture} 的三条路径。\emph{发布}（1--2）：一个智能体探索并回答一道给出业务定义的题；答案核对正确后，\system\ 提取候选，经发布前检查后发布（第~\ref{sec:shared-object} 节）。\emph{使用}（3--5）：其他每个智能体用 \code{find\_metric} 查到该指标，拿到有效版本及其生成的 SQL，用一条查询作答而不必探索；它在 \code{run\_sql} 中声明该版本，\system\ 在版本条件成立的快照上执行查询（第~\ref{sec:execution} 节）。\emph{维护与优化}（6--8）：数据更新改变某张表时，\system\ 只重查所读表发生变化的条件，在定义与智能体之间复用检查结果，自动修复失效的定义（无法修复时置为失效），并发布更省的等价版本，这些都为所有智能体只做一次（第~\ref{sec:maintenance} 与~\ref{sec:optimization} 节）。任何智能体都不直接写记忆，因此一个智能体的错误不经过检查就到不了其他智能体。}
