\section{\bt{System Overview}{系统概览}}
\label{sec:overview}
\bi{\system\ is a shared memory layer between data agents and a SQL database, PostgreSQL in our prototype (Figure~\ref{fig:architecture}). It exposes tools for listing and describing tables, finding join paths, looking up metric definitions (\code{find\_metric}), and running SQL (\code{run\_sql}); agents submit final answers with the query references and arithmetic that produced them, so the middleware records how every answer was computed. The shared memory keeps the numbered revisions of each definition, join paths, grain entries, check results, and learning records.}
{\system\ 是位于数据智能体与 SQL 数据库之间的共享记忆层，原型使用 PostgreSQL（图~\ref{fig:architecture}）。它以工具接口的形式提供列出和描述表、查找连接路径、查找指标定义（\code{find\_metric}）以及执行 SQL（\code{run\_sql}）等功能；智能体提交最终答案时附上产生答案的查询编号和算式，因此中间件记录每个答案是如何算出的。共享记忆保存各定义的版本、连接路径、粒度条目、检查结果和学习记录。}

\bi{\emph{Who reads and who writes.} Agents read a revision's business definition, fields, generated and example SQL, caveats, and revision number; \system\ keeps its conditions, their check results with the table versions they were checked at, the publication record, and the learning snapshot for as-of queries. No agent writes to the memory directly: a revision enters only through the publication checks, whether it comes from the learning agent, a repair, or an optimization, and a published revision is never edited in place. Two candidates for one metric whose structures differ are kept as separate entries. Consumers declare the revisions a query uses, which lets \system\ check validity at execution and notify a consumer, on its next tool response, when what it relied on has changed.}
{\emph{谁读，谁写。}智能体读到一个版本的业务定义、字段、生成的 SQL 与示例 SQL、注意事项和版本号；\system\ 保管该版本的条件、条件的检查结果及检查时的表版本、发布记录，以及供 as-of 查询使用的学习时快照。任何智能体都不直接写记忆：新版本只能经过发布前检查进入，无论它来自学习、修复还是优化；已发布的版本从不原地修改。同一指标下结构不同的两个候选作为两个条目分别保存。使用者声明查询所用的版本，这使 \system\ 能够在执行时检查有效性，并在使用者所用的内容变化时，于其下一次工具调用的返回中通知它。}

\bi{A definition moves through the three paths of Figure~\ref{fig:architecture}. On the \emph{learning path}, the learning agent answers a question that states the business definition; if the answer matches the reference answer, which a hand-written reference query computes on the same snapshot, an offline extractor turns the recorded queries and arithmetic into a candidate for the publication checks (Section~\ref{sec:maintenance}). On the \emph{use path}, \code{find\_metric} first runs condition maintenance if the version of a table it reads has changed and then returns the valid revision. On the \emph{execution path}, \code{run\_sql} rejects declared revisions that are absent or invalidated and runs the query on one snapshot on which their conditions hold (Section~\ref{sec:execution}).}
{一个定义经过图~\ref{fig:architecture} 的三条路径。在\emph{学习路径}上，学习智能体回答一道给出业务定义的题目；若答案与参考答案（由人工编写的参考查询在同一快照上算出）一致，离线提取器把记录下的查询与算式转成候选，交给发布前检查（第~\ref{sec:maintenance} 节）。在\emph{使用路径}上，若它读取的某张表的版本变化，\code{find\_metric} 先执行条件维护，再返回有效版本。在\emph{执行路径}上，\code{run\_sql} 拒绝不存在或已失效的声明版本，并在这些版本的条件成立的同一快照上执行查询（第~\ref{sec:execution} 节）。}
