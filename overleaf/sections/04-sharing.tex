\section{\bt{Design of \system}{\system\ 的设计}}
\label{sec:model}
\bi{Sharing saves time and tokens only if one agent's exploration answers other agents' questions, and only if keeping the shared knowledge valid costs less than exploring again. This section describes what agents share and how one exploration becomes one SQL for every later agent (Section~\ref{sec:shared-object}), when shared knowledge is correct (Section~\ref{sec:sufficiency}), and how \system\ maintains and optimizes it once for all agents (Sections~\ref{sec:maintenance} and~\ref{sec:optimization}).}
{共享要省下时间和 token，一个智能体的探索必须能回答其他智能体的问题，而且让共享知识保持有效的代价必须小于重新探索。本节说明智能体共享什么、一次探索如何变成之后每个智能体的一条 SQL（第~\ref{sec:shared-object} 节），共享的知识何时正确（第~\ref{sec:sufficiency} 节），以及 \system\ 如何为所有智能体一次性地维护与优化它（第~\ref{sec:maintenance} 与~\ref{sec:optimization} 节）。}

\subsection{\bt{What agents share and how it is learned}{智能体共享什么、如何学来}}
\label{sec:shared-object}
\bi{\emph{What is shared.} \system\ shares knowledge that passes three tests: it describes the database rather than an agent or a question, so it is the same for every agent; an agent spends LLM calls exploring to find it; and the data can check whether it still holds. Metric definitions pass all three, and they are what \system\ learns from the agents' sessions: the fact rows a metric aggregates, its grain, its joins, and its filters, including the value meanings that the filters encode, such as the category value that marks electronics. \system\ also shares what it computes from the data itself, namely table descriptions, verified join paths, and check results; sharing them saves the database the work of recomputing them, while an agent still spends the tool call that asks for them. Answers are not shared as knowledge: a question's parameters belong to that question, and its answer holds for one period on one snapshot. Reusing answers is the work of a result cache, which the layer keeps as well; it saves database time on an exact repeat but not the LLM call that issues the query. Strategies, workflows, conversations, and preferences are not shared at all: they describe an agent and its user rather than the data, differ between agents, and carry no condition that the data can check, so they belong in the agent's own memory, which \system\ complements rather than replaces. Definitions that different teams give one name are not merged; people reconcile them (Section~\ref{sec:limitations}).}
{\emph{共享什么。}\system\ 共享同时满足三点的知识：它描述的是数据库，而不是某个智能体或某道题，因此对每个智能体都一样；智能体要花大模型调用去探索才能找到它；数据能检查它是否仍然成立。指标定义三点都满足，也是 \system\ 从智能体会话中学习的对象：指标聚合哪些事实行，它的粒度、连接与过滤条件，包括过滤条件所表达的取值含义，例如哪个类别取值代表电子品类。\system\ 还共享它自己从数据算出的内容，即表描述、验证过的连接路径和检查结果；共享它们省掉了数据库重算的工作，但智能体仍要花一次工具调用去取。答案不作为知识共享：题目参数只属于那道题，答案只对一个快照上的一个期间成立。复用答案是结果缓存的事，这一层也保存结果缓存；它在查询完全相同时省下数据库时间，却省不下发出这条查询的那次大模型调用。策略、工作流、对话与偏好完全不共享：它们描述的是智能体及其用户而不是数据，各智能体互不相同，也没有数据能检查的条件，因此属于智能体自己的记忆，\system\ 是对它的补充而不是替代。不同团队对同一名称给出的定义不合并，由人来调和（第~\ref{sec:limitations} 节）。}

\bi{A definition revision is $m^r=(B,I,C,E,r)$, where $B$ is its business meaning, $I$ its structured implementation, $C$ its set of executable conditions, $E$ its learning record, and $r$ its revision number. The implementation records the fact table, aggregate expression, grain, date join, joins, and definition filters; its joins form a many-to-one tree rooted at the fact table (a star or snowflake). Question parameters such as the month are not part of it: the generated SQL is compiled from $I$ for any period, difference, or ranking, so one learning session serves questions that no agent has asked yet.}
{定义的一个版本记为 $m^r=(B,I,C,E,r)$，其中 $B$ 为业务含义，$I$ 为结构化实现，$C$ 为可执行条件集，$E$ 为学习记录，$r$ 为版本号。实现记录事实表、聚合表达式、粒度、日期连接、连接和定义过滤；连接构成以事实表为根的多对一连接树（星型或雪花型）。月份等题目参数不属于实现：生成的 SQL 由 $I$ 针对任意期间、差值或排名编译得到，因此一次学习会话可以服务尚无智能体问过的问题。}

\bi{\emph{Learning from use.} Any agent's session can teach the memory once its answer is verified. In a deployment the verification comes from the people who own the metric: the asking user confirms the answer, it matches a figure in an existing report, or an analyst approves it. \system\ needs this one verified value of the learning question and nothing else; in our experiments a reference query on the same snapshot stands in for it. A candidate comes from a verified session whose question states the business definition. The extractor turns the session's SQL and arithmetic into a candidate without seeing business rows, and seven deterministic publication checks follow, from the match with the verified answer and key uniqueness to a replay of the generated SQL compiled from the fields against that answer. The replay tests what other agents will read rather than what the producer ran, so a candidate that drops a filter or hard-codes a parameter is rejected before it reaches anyone. Learning is paid once, by the first session that meets a metric, and a definition is verified once, not every time an agent uses it.}
{\emph{边用边学。}任何智能体的会话，只要答案经过核实，都可以教给记忆。实际部署中，核实来自指标的负责人：提问者确认答案、答案与已有报表中的数字一致，或由分析师审核通过。\system\ 只需要学习题的这一个核实值，别的都不需要；实验中由在同一快照上执行的参考查询代替它。候选来自题目给出业务定义、答案经过核实的会话。提取器在看不到业务数据行的情况下，把会话的 SQL 与算式转成候选；随后是七项确定性的发布前检查，从与核实答案一致、键唯一，到重放由字段编译出的生成的 SQL 并与该答案比较。重放检查的是其他智能体将要读到的内容，而不是生产者当时执行的内容，因此丢掉过滤或写死参数的候选在到达任何人之前就被拒绝。学习只付一次，由最先遇到某个指标的会话承担；一个定义只需核实一次，而不是每次使用都核实。}

\subsection{\bt{When shared knowledge is correct}{共享的知识何时正确}}
\label{sec:sufficiency}
\bi{Data-only updates break learned SQL while the schema stays the same: status-change rows, restatements, or duplicate loads violate the grain, reused dimension keys make a many-to-one join fan out, and late or reformatted date keys move facts to another period or to none~\cite{kimball2013toolkit}. A condition $c$ is a predicate over the tables $\operatorname{dep}(c)$ with a check query $Q_c$ that returns violating rows or nothing; its normalized form $\operatorname{id}(c)$ consists of its type, tables, keys, join direction, normalized filters, and null policy. \system\ derives four kinds from $I$. \emph{Filtered key uniqueness} $\operatorname{KeyUnique}(T,K,\varphi)$: no two rows of $\sigma_\varphi(T)$ agree on $K$. \emph{Join cardinality}: each row of $L$ in a join $L\to R$ matches at most the permitted number of $R$ rows. \emph{Date join}: the fact's date key joins the date dimension many-to-one. \emph{Join completeness}: for the date join and every inner join, the fraction of fact rows that match no row stays within the fraction recorded at publication plus 0.1 percentage points.}
{纯数据更新会在模式不变的情况下破坏学到的 SQL：状态流水、更正保留旧行或重复加载破坏粒度，被重用的维度键使多对一连接放大行数，迟到或改了格式的日期键把事实移到别的期间或使其无处可归~\cite{kimball2013toolkit}。条件 $c$ 是表集合 $\operatorname{dep}(c)$ 上的谓词，附带一个检查查询 $Q_c$，返回违例行或空；其规范化形式 $\operatorname{id}(c)$ 由类型、表、键、连接方向、规范化的过滤和空值规则组成。\system\ 从 $I$ 推导四类条件。\emph{过滤后键唯一性} $\operatorname{KeyUnique}(T,K,\varphi)$：$\sigma_\varphi(T)$ 中没有两行在 $K$ 上取值相同。\emph{连接基数}：连接 $L\to R$ 中每条 $L$ 记录匹配的 $R$ 记录数不超过允许值。\emph{日期连接}：事实的日期键与日期维度多对一连接。\emph{连接完整性}：对日期连接和每个内连接，匹配不到任何行的事实行比例不超过发布时记录的比例加 0.1 个百分点。}

\bi{For a period $p$, the generated SQL evaluates $\mathrm{AGG}(e)$ over the rows of $\sigma_\varphi(F)\bowtie R_1\bowtie\cdots\bowtie R_k$ whose date falls in $p$. The business meaning contributes two assumptions that no query can check: (B1) the metric's business events correspond one-to-one to the values of $K$ in $\sigma_\varphi(F)$, and (B2) $e$ evaluates on an event's row to that event's measurement.}
{对期间 $p$，生成的 SQL 在 $\sigma_\varphi(F)\bowtie R_1\bowtie\cdots\bowtie R_k$ 中日期落在 $p$ 内的行上计算 $\mathrm{AGG}(e)$。业务含义提供两条任何查询都无法检查的前提：（B1）指标的业务事件与 $\sigma_\varphi(F)$ 中 $K$ 的取值一一对应；（B2）在事件对应的行上，$e$ 求值得到该事件的度量值。}
\begin{proposition}[\bt{Sufficiency}{充分性}]
\label{prop:sufficiency}
\bi{If B1 and B2 hold on $D_s$ and every condition in $C(m^r)$ holds on $D_s$, then for every period $p$ the generated SQL of $m^r$ returns $\mathrm{AGG}$ over the measurements of the events whose date lies in $p$, each event contributing exactly once; the events it omits are those whose date or join key matches no row, and the completeness conditions bound their fraction.}
{若 B1、B2 在 $D_s$ 上成立，且 $C(m^r)$ 中每个条件都在 $D_s$ 上成立，则对每个期间 $p$，$m^r$ 的生成的 SQL 返回日期落在 $p$ 内的事件度量值的 $\mathrm{AGG}$，每个事件恰好贡献一次；被遗漏的只有日期键或连接键匹配不到任何行的事件，其比例受完整性条件约束。}
\end{proposition}
\begin{proof}[\bt{Proof sketch}{证明概要}]
\bi{By B1 and filtered key uniqueness, $\sigma_\varphi(F)$ holds one row per event. Join cardinality keeps every join from duplicating a row, join completeness bounds the rows that inner joins drop, and the date join gives each row at most one date and hence at most one period. Every remaining row contributes its measurement (B2) once, to the period of its date.}
{由 B1 和过滤后键唯一性，$\sigma_\varphi(F)$ 中每个事件恰有一行。连接基数保证连接不复制任何行，连接完整性约束内连接排除的行，日期连接给每行至多一个日期，因而至多一个期间。于是每个保留下来的行把其度量值（B2）恰好贡献一次，归入其日期所在的期间。}
\end{proof}
\bi{Conversely, while B1 and B2 hold, every data-only update that makes the generated SQL count an event twice or drop facts beyond the recorded fraction violates a condition; changes to the values themselves, such as a rescaled measure, are outside the conditions.}
{反过来，只要 B1、B2 成立，凡是使生成的 SQL 把一个事件计数两次、或排除超过记录比例的事实的纯数据更新，都会违反某个条件；取值本身的变化（例如度量换了量纲）不在条件范围内。}

\subsection{\bt{Maintenance once for all agents}{为所有智能体一次性维护}}
\label{sec:maintenance}
\bi{\emph{Shared check results.} The version $V(T)$ of a table identifies the state that a check read: either the schema fingerprint, DML counters, and ETL batch identifier, or a \emph{transactional version} that a statement-level trigger increments inside every writing transaction. A check result is keyed by $\bigl(\operatorname{id}(c),V(\operatorname{dep}(c))\bigr)$, so it serves every definition and every agent that needs the same condition on the same table versions. When an agent looks up a definition, \system\ compares the versions recorded for each condition's tables with the current ones, keeps the check results of conditions over unchanged tables, looks up a completed result for each remaining condition at the current versions, and runs $Q_c$ only if none exists; concurrent requests for the same check share that one execution (request coalescing). Joins are checked through shared join entries, so a changed or vanished join path also makes the definition pending. A failed condition invalidates the revision; consumers then learn that the definition is unavailable and explore on their own, and the next successful learning session publishes it again.}
{\emph{共享的检查结果。}表的版本 $V(T)$ 标识检查读到的状态：或者组合结构指纹、DML 计数与 ETL 批次号，或者使用\emph{事务性版本}，由语句级触发器在每个写事务内递增。检查结果以 $\bigl(\operatorname{id}(c),V(\operatorname{dep}(c))\bigr)$ 为键，因此服务于所有在相同表版本上需要同一条件的定义和智能体。智能体查找定义时，\system\ 把每个条件所读各表记录下的版本与当前版本比较：未变化表上的条件保留原有检查结果；对其余条件，查找同一规范化形式在当前版本上的已完成结果，没有才执行 $Q_c$，同一检查的并发请求共享这一次执行（请求合并）。连接通过共享的连接条目检查，因此连接路径被改变或消失时，定义同样变为待验证。条件失败使版本失效；使用者随即得知定义不可用、自行探索，下一次成功的学习会话会重新发布它。}

\bi{\emph{Repair once.} When a fact-table grain fails, repair searches equality filters on columns with few distinct values that restore one row per business key without losing keys. It publishes a fix only if exactly one filter passes, because a table and an appended backup both pass and nothing structural tells which holds the business truth, and only if the fix and the agent's learning SQL return equal results as \emph{as-of queries} (time-travel queries) at learning time, the only data on which the agent's SQL was verified. A repair runs once and serves every agent; requests that arrive while it runs join it, and a definition that cannot be repaired is invalidated, so its consumers explore until a session relearns it.}
{\emph{只修复一次。}事实表粒度失效时，修复在取值较少的列上搜索等值过滤，要求恢复每个业务键一行且不丢键。只有恰好一个过滤通过时才发布修复，因为表和追加的备份都能通过，结构上无从判断哪一份是业务真相；而且修复与智能体的学习 SQL 以学习时刻为基准作 \emph{as-of 查询}（时间旅行查询）时结果必须相同，因为智能体的 SQL 只在那时的数据上核对过。修复只做一次、服务所有智能体；修复期间到达的请求与之合并；无法修复的定义被置为失效，其使用者自行探索，直到某个会话重新学到它。}

\bi{\emph{Checks at query execution.}\label{sec:execution} An agent declares the revisions a query uses, and \code{run\_sql} rejects absent and invalidated ones and SQL that lacks a filter the grain requires. A passed check describes one snapshot, and a writer may commit before the query runs, so \system\ validates on the query's own snapshot: it opens a repeatable-read transaction, looks up the check result of each declared revision's conditions at the snapshot's transactional versions, runs only the missing checks inside the transaction, and executes the query there if they hold. Looking up rather than rerunning is what keeps this cheap, and it rests on the following lemma.}
{\emph{执行时检查。}智能体声明查询所用的版本，\code{run\_sql} 拒绝不存在或已失效的版本，以及缺少粒度所需过滤的 SQL。一次通过的检查只描述一个快照，查询执行之前可能有写入提交，因此 \system\ 在查询自己的快照上验证：它开启可重复读事务，按快照的事务性版本查找所声明版本各条件的检查结果，只在该事务内执行缺失的检查，条件成立才在其中执行查询。靠查找而不是重跑，这一步才便宜，其依据是下面的引理。}

\label{sec:snapshot}
\begin{lemma}[\bt{Check-result reuse}{检查结果复用}]
\label{lem:reuse}
\bi{Let $v_s(T)$ be the transactional version of $T$ visible in snapshot $s$. If $v_{s_1}(T)=v_{s_2}(T)$ for every $T\in\operatorname{dep}(c)$, then $c(D_{s_1})=c(D_{s_2})$.}
{设 $v_s(T)$ 为快照 $s$ 中可见的 $T$ 的事务性版本。若对每个 $T\in\operatorname{dep}(c)$ 都有 $v_{s_1}(T)=v_{s_2}(T)$，则 $c(D_{s_1})=c(D_{s_2})$。}
\end{lemma}
\begin{proof}
\bi{PostgreSQL snapshots are nested, say $s_1\subseteq s_2$. A transaction that writes $T$ increments $T$'s counter in the same transaction, so equal versions leave no transaction in $s_2\setminus s_1$ that writes $T$, and both snapshots see the same state of every table that $Q_c$ reads.}
{PostgreSQL 的快照是嵌套的，不妨设 $s_1\subseteq s_2$。写 $T$ 的事务在同一事务内递增 $T$ 的计数，因此版本相等意味着 $s_2\setminus s_1$ 中没有写 $T$ 的事务，两个快照看到 $Q_c$ 所读各表的同一状态。}
\end{proof}
\subsection{\bt{Optimization once for all agents}{为所有智能体一次性优化}}
\label{sec:optimization}
\bi{A published definition is correct but not necessarily cheap, and because agents copy its generated SQL, a cheaper equivalent speeds up every consumer. After learning, \system\ runs an optimization pass over the valid definitions; candidates are structured definitions, so compilation, the conditions, and Proposition~\ref{prop:sufficiency} apply to them. Two rules propose candidates: \emph{key range} replaces the period join with a range predicate on the fact table's date key, whose bounds scalar subqueries read from the date dimension, and \emph{left-join removal} drops a left join that contributes no column and no filter. Only when no rule candidate is published does an LLM propose candidates from the definition, its generated SQL and plan, and table sizes; a proposal is published only if it coincides with a rule rewrite. A candidate must pass the static, grain, and SQL checks and three tests. \emph{Assumption}: the key-range rule adds date-key contiguity, checked before adoption and maintained afterwards. \emph{Equivalence}: candidate and current revision return equal results for the learning question as of learning time and, within one repeatable-read snapshot, for the twelve months of the learning year, a quarter, a period difference, and a monthly ranking. \emph{Cost}: in the same snapshot, the paired execution times of at least eight periods, measured in alternating order, must have a 95\% confidence interval below zero and a mean saving of at least 10\%.}
{已发布的定义是正确的，但不一定是最省的；由于智能体会照抄它的生成的 SQL，一个更省的等价写法对每个使用者都有收益。学习结束后，\system\ 对有效的定义执行一轮优化；候选都是结构化定义，因此编译、条件和命题~\ref{prop:sufficiency} 都适用于它们。两条规则提出候选：\emph{日期键范围}把期间连接改为事实表日期键上的范围谓词，上下界由标量子查询从日期维度读出；\emph{去掉左连接}去掉一个既不提供列也不带过滤的左连接。只有在没有规则候选发布时，才由大模型根据定义、其生成的 SQL 与执行计划以及表的规模提出候选；提议只有与某个规则改写相同时才发布。候选必须通过静态、粒度和 SQL 检查以及三项测试。\emph{前提}：日期键范围规则新增日期键连续条件，采纳前检查，之后受维护。\emph{等价}：候选与当前版本对学习题按学习时刻返回相同结果，并在一个可重复读快照内对学习年份的 12 个月、一个季度、一次期间差值和一次按月排名返回相同结果。\emph{代价}：在同一快照中，至少 8 个期间以交替顺序测得的配对执行时间差，其 95\% 置信区间必须整体低于 0，平均节省至少 10\%。}
\begin{proposition}[\bt{Rule equivalence}{规则等价}]
\label{prop:rewrite}
\bi{Let the date dimension's key be unique on $D$. (a) If \emph{date-key contiguity} holds on $D$, i.e., the keys of every month form an integer interval that begins one above the previous month's last key, then for every period of consecutive months the generated SQL of a key-range revision returns on $D$ what that of its previous revision returns. (b) If the right side of a removed left join is unique on the join key on $D$, removing the join does not change the result.}
{设日期维度的键在 $D$ 上唯一。（a）若\emph{日期键连续性}在 $D$ 上成立，即每个月的键构成一个整数区间、且从上个月最后一个键加一开始，则对由连续月份组成的每个期间，键区间版本的生成的 SQL 在 $D$ 上返回与其前一版本相同的结果。（b）若被消除的左连接右侧在连接键上唯一，消除该连接不改变结果。}
\end{proposition}
\begin{proof}[\bt{Proof sketch}{证明概要}]
\bi{(a) By contiguity, the keys of a period's months are exactly the integer interval between the bounds, so a fact row's key lies in the interval if and only if it joins one date row of the period. (b) A left join with at most one match keeps each left row once and supplies nothing that is read.}
{（a）由连续性，一个期间各月的键恰好是边界之间的整数区间，因此事实行的键落在区间内当且仅当它连接到该期间的一行日期。（b）至多一个匹配的左连接使每个左侧行恰好保留一次，且不提供任何被读取的内容。}
\end{proof}
\bi{The assumption of (a) is a condition of the new revision; that of (b) is a condition of the previous revision that the new revision no longer needs. Wherever the maintained conditions hold, a rule revision thus agrees with its previous revision on every period, and the sampled tests check the implementation and measure the cost. Maintenance checks an added assumption last; when it alone fails, every condition shared with the previous revision has just been confirmed, and \system\ invalidates the optimized revision and makes its previous revision current again, so an optimization never trades correctness for speed.}
{（a）的前提是新版本的条件；（b）的前提是前一版本的条件，新版本不再需要它。因此，只要受维护的条件成立，规则版本就在每个期间上都与前一版本一致；抽样测试检查的是实现并测量代价。维护最后检查新增的前提；只有它不成立时，与前一版本共有的每个条件都刚刚得到确认，\system\ 使优化后的版本失效，并让前一版本重新成为当前版本，因此优化从不以正确性换取速度。}

\subsection{\bt{Prediction tasks: shared feature definitions}{预测任务：共享的特征定义}}
\label{sec:features}
\bi{Many tasks of data agents end in a model rather than in one answer: given seed rows of an entity and a seed time, the agent writes SQL that returns, for every seed, aggregates of that entity's data before the seed time, and a fixed learner is trained on them. The forecasting tasks of RelBench have this form~\cite{robinson2024relbench}, and an agent spends most of such a session exploring tables and probing values before its first features are validated. \system\ shares the same kind of object for these tasks. A \emph{feature definition} is a metric definition (fact, measure, grain, verified many-to-one joins, required filters) with three more fields: the entity it describes, reached from the fact through a foreign key or a verified join (optionally through an anchor column, such as the owner of a seed post); a look-back window; and the value that a seed without rows takes, as the submitted SQL filled it in. \system\ compiles a definition into one lateral aggregate per seed whose predicate bounds every row by the seed's time and the window, so a compiled feature cannot read data recorded after the seed time. A \emph{task program} is the set of definitions that a successful session submitted for a task, with its validation score and the complete SQL of the submission.}
{数据智能体的许多任务以一个模型而不是一个答案结束：给定某个实体的种子行及其种子时间，智能体写出 SQL，对每个种子返回该实体在种子时间之前的数据的聚合，再由固定的学习器在这些特征上训练。RelBench 的预测任务就是这种形式~\cite{robinson2024relbench}，而这类会话的大部分时间花在第一组特征得到验证之前的看表与探查上。\system\ 为这些任务共享同一类对象。一条\emph{特征定义}是一条指标定义（事实表、度量、粒度、经验证的多对一连接、必需的过滤）再加三个字段：它描述的实体（经事实表的外键或经验证的连接到达，必要时经一个锚列，例如种子帖子的作者）、回看窗口，以及没有行的种子取的值（与提交的 SQL 的填法一致）。\system\ 把一条定义编译为对每个种子的一个 LATERAL 聚合，其谓词把每一行限定在该种子的时间与窗口之内，因此编译出的特征不可能读到种子时间之后记录的数据。一个\emph{任务方案}是一次成功会话为某任务提交的那组定义，连同它的验证分数和那次提交的完整 SQL。}
\bi{\system\ learns these objects as it learns metrics. After a session whose features beat the entity-table reference, an extractor turns the submitted SQL into definition drafts, and a draft is published only if four checks pass on the current snapshot: its fields are valid (columns exist, expressions read only the tables involved, every join is many-to-one); the fact's grain key is unique; the compiled SQL reproduces the submitted column value by value on 2,000 seeds; and recomputing it on views that hide every row after the seed time changes no value. An agent starts with \code{find\_program}, which returns its task's latest program, both the complete SQL, after checking that it still runs on the current snapshot, and the SQL compiled from the program's still-valid definitions; \code{find\_features} returns the definitions published on the task's entity by any agent, compiled for the agent's seed table, and \code{compose\_features} compiles a chosen set. When new data arrive, the conditions of every definition are checked again as in Section~\ref{sec:maintenance}, and a definition whose condition fails is revoked: unlike a metric, a feature has no single reference value against which a repair could be checked.}
{\system\ 像学习指标一样学习这些对象。一次会话的特征优于实体表参照时，提炼器把提交的 SQL 转为若干定义草稿；只有在当前快照上通过四项检查，草稿才会发布：字段合法（列存在，表达式只读涉及的表，每个连接都是多对一）；事实表的粒度键唯一；编译出的 SQL 在 2,000 个种子上逐值重现提交的列；在隐去种子时间之后所有行的视图上重算，任何值都不变。智能体先调用 \code{find\_program}，它返回本任务最近的方案：在确认仍能在当前快照上执行之后的完整 SQL，以及由方案中仍然有效的定义编译出的 SQL；\code{find\_features} 返回任何智能体在本任务实体上发布的定义，并为该智能体的种子表编译好；\code{compose\_features} 编译选定的一组定义。新数据到来时，每条定义的条件按第~\ref{sec:maintenance} 节重新检查，条件不再成立的定义被撤下：与指标不同，特征没有一个可以用来检验修复的参照值。}
