\section{\bt{Publication, Maintenance, and Improvement}{发布、维护与改进}}
\label{sec:maintenance}
\subsection{\bt{Admission from successful trajectories}{从成功轨迹准入}}
\bi{Candidates are extracted only from tasks with explicit business evidence and a successful judgment. The extractor sees the question, the SQL and derivation of the answer provenance, rejected queries, and metadata, but no business rows or result values. Seven deterministic admission checks follow: a stated business basis; the judgment that the answer is correct; static well-formedness (columns exist, the measure uses only permitted columns, joins follow validated paths, and required grain filters are present without question literals); grain on the current snapshot; SQL review; replay of the example SQL; and replay of the canonical SQL compiled from the fields. The canonical replay checks what other agents will actually read, so a candidate that omits a filter or hard-codes a parameter fails it. Learning questions supply admission evidence; held-out questions only measure transfer.}
{只从具备显式业务依据且判题成功的任务中提取候选。提取器能看到题面、答案溯源中的 SQL 与算式、被拦下的查询以及元数据，但看不到业务行和结果值。随后执行七项确定性的准入检查：业务依据；答案经判定正确；静态合法性（列存在、度量只用允许的列、连接沿已验证路径、包含必需的粒度过滤且不含题目字面量）；当前快照上的粒度；SQL 审查；示例 SQL 重放；由字段编译的规范 SQL 重放。规范 SQL 重放检查的是其他智能体实际会读到的内容，因此遗漏过滤或把参数写死的候选会失败。学习题提供准入证据，留出题只用于测量迁移。}

\subsection{\bt{Selective revalidation and reuse}{选择性重验证与复用}}
\bi{On use, maintenance compares the recorded versions of each condition's dependencies with the current versions. Conditions over unchanged tables keep their evidence. For each remaining condition, \system\ looks up a completed check result for the same canonical form at the current versions; otherwise it runs $Q_c$, and concurrent requests for the same check share that execution. Joins are checked through the shared join entries, so a revised or vanished join path also makes the definition pending. The full-recheck baseline uses the same conditions, repair, regression, and request coalescing but rechecks the entire condition set of the definition and forces join cardinality checks to rerun.}
{使用时，维护过程把每个条件所依赖表的记录版本与当前版本比较。未变化表上的条件保留原有证据。对其余条件，\system\ 查找同一规范形式在当前版本上的已完成检查结果；否则执行 $Q_c$，对同一检查的并发请求共享这次执行。连接通过共享的连接条目检查，因此连接路径被修订或消失时，定义同样变为待验证。整定义重查基线使用相同的条件、修复、回归和请求合并，但重查定义的全部条件，并强制重跑连接基数检查。}

\subsection{\bt{Invalidation and bounded repair}{失效与有界修复}}
\bi{A failed condition invalidates the revision and records the reason. Repair handles two cases: a failed fact-table grain, for which it searches equality filters on low-cardinality columns, and a revised join path, whose new filters it adopts. A grain filter must keep exactly one row per business key without losing keys, which rejects, for instance, an application-state filter that drops returns that never had such a row. The fix must also be \emph{unique}: \system\ enumerates every passing filter and repairs only if exactly one exists, because two complete copies of the data, such as a primary table and an appended backup, each pass the structural tests, and nothing structural tells which holds the business truth. A unique fix must then pass the well-formedness, grain, and SQL-review checks and a regression test that runs the replacement and the agent's learning SQL as \emph{as-of queries} at learning time and requires equal results: the agent's SQL was judged correct only on that data, and on current data it can itself be stale, counting old versions after a restatement. Warehouses answer as-of queries through time travel (e.g., \code{FOR SYSTEM\_TIME AS OF}); our prototype keeps a copy of the tables taken at admission. Repair searches over the same table and key are shared across definitions, and a failed repair leaves the definition unavailable until new evidence is learned.}
{条件失败会使修订失效并记录原因。修复只处理两种情况：事实表粒度失效时，搜索低基数列上的等值过滤；连接路径被修订时，采用新路径的过滤。粒度过滤必须使每个业务键恰好保留一行且不丢键，因此会排除诸如申请状态过滤这样的候选：它丢掉了从未有过申请状态行的退货。修复还必须是\emph{唯一}的：\system\ 列出全部通过检查的过滤，只有恰好一个时才修复，因为主表与追加的备份副本这样的两份完整数据各自都能通过结构检查，结构上无从判断哪一份承载了业务事实。唯一的修复还要通过合法性、粒度与 SQL 审查检查以及回归测试：把替代修订与智能体的学习 SQL 一起以学习时刻为基准作 \emph{as-of 查询}，要求结果相同；智能体的 SQL 只在那时的数据上被判过对，在当前数据上它本身可能已经过期，例如多版本更正后会把旧版本也算进去。数仓用 time travel 回答 as-of 查询（如 \code{FOR SYSTEM\_TIME AS OF}）；我们的原型在准入时保留一份表的副本。同一张表、同一个键上的修复搜索在定义之间共享；修复失败的定义保持不可用，直到学到新的证据。}

\bi{The request that triggers maintenance performs the repair and receives the replacement revision. Other requests that arrive while the repair runs observe an invalidated revision; instead of rejecting them, \system\ coalesces them with the running maintenance and lets them read its outcome, so a successful repair serves them as well.}
{触发维护的请求执行修复并获得替代修订。修复期间到达的其他请求看到的是已失效的修订；\system\ 不拒绝它们，而是把它们与进行中的维护合并，读取其结果，因此修复成功时它们同样得到服务。}

\subsection{\bt{Optimization revisions}{优化修订}}
\label{sec:optimization}
\bi{A published definition is correct but not necessarily cheap, and because agents copy its canonical SQL, a cheaper equivalent benefits every consumer. After learning, \system\ runs an optimization sweep over the valid definitions. Candidates are structured definitions, so compilation, the conditions, and Proposition~\ref{prop:sufficiency} apply to them as to any revision. Two rules propose candidates: \emph{key range} replaces the period join with a range predicate on the fact table's date key, whose bounds scalar subqueries read from the date dimension, and \emph{left-join removal} drops a left join that contributes no column and no filter. Only when no rule candidate is published does an LLM propose candidates from the definition, its canonical SQL and plan, and table sizes, without business rows. A candidate must differ structurally from the current revision, pass the static, grain, and SQL-review admission checks, and pass three tests. \emph{Premise}: the key-range rule adds one condition, \emph{date-key contiguity}: the keys of every month form an integer interval that begins one above the previous month's last key; it is checked before adoption and maintained afterwards. \emph{Equivalence}: the canonical SQL of candidate and current revision return equal results for the learning question as of learning time and for every sampled question (the twelve months of the learning year, a quarter, a period difference, and a ranking) within one repeatable-read snapshot. \emph{Cost}: in the same snapshot, each period's two queries run under \code{EXPLAIN ANALYZE} in alternating order, and the candidate is adopted only if, over at least eight periods, the 95\% confidence interval of the paired differences lies below zero and the mean saving is at least 10\%. For the rules, equivalence does not rest on the samples.}
{已发布的定义是正确的，但不一定是最省的；由于智能体会照抄它的规范 SQL，一个更省的等价写法对每个使用者都有收益。学习结束后，\system\ 对有效的定义执行一轮优化。候选都是结构化定义，因此编译、条件和命题~\ref{prop:sufficiency} 像对任何修订一样适用于它们。两条规则提出候选：\emph{日期键范围}把期间连接改为事实表日期键上的范围谓词，上下界由标量子查询从日期维度读出；\emph{去掉左连接}去掉一个既不提供列也不带过滤的左连接。只有在没有规则候选发布时，才由大模型根据定义、其规范 SQL 与执行计划以及表的规模提出候选，输入不含业务行。候选必须在结构上与当前修订不同，通过静态、粒度和 SQL 审查这几项准入检查，并通过三项测试。\emph{前提}：日期键范围规则新增一条条件，即\emph{日期键连续}：每个月的键构成一个整数区间，且起点比上个月的最后一个键大一；采纳前检查，之后受维护。\emph{等价}：候选与当前修订的规范 SQL 对学习题按学习时刻返回相同结果，并在一个可重复读快照内对每个抽样题（学习年份的 12 个月、一个季度、一次期间差值和一次排名）返回相同结果。\emph{代价}：在同一快照中，每个期间的两条查询以交替顺序在 \code{EXPLAIN ANALYZE} 下执行；只有当至少 8 个期间的配对差的 95\% 置信区间整体低于 0、且平均节省至少 10\% 时才采纳候选。对规则而言，等价并不依赖抽样。}
\begin{proposition}[\bt{Rule equivalence}{规则等价}]
\label{prop:rewrite}
\bi{Let the date dimension's key be unique on $D$. (a) If date-key contiguity holds on $D$, then for every period consisting of consecutive months, the canonical SQL of a key-range revision returns on $D$ what the canonical SQL of its predecessor returns. (b) If the right side of a removed left join is unique on the join key on $D$, the canonical SQL without the join returns on $D$ what the canonical SQL with it returns.}
{设日期维度的键在 $D$ 上唯一。（a）若日期键连续在 $D$ 上成立，则对每个由连续月份组成的期间，日期键范围修订的规范 SQL 在 $D$ 上返回其前一修订的规范 SQL 所返回的值。（b）若被去掉的左连接的右侧在连接键上于 $D$ 上唯一，则去掉该连接后的规范 SQL 在 $D$ 上返回原规范 SQL 所返回的值。}
\end{proposition}
\begin{proof}[\bt{Proof sketch}{证明概要}]
\bi{(a) By contiguity, the keys of the months of a period form exactly the integer interval between the bounds the subqueries read, so a fact row's date key lies in the interval if and only if it joins a date row of the period, and by uniqueness only one; a key that matches no date row lies outside the dimension's key range, and both forms drop it. (b) A left join with at most one match keeps each left row exactly once and supplies nothing that the aggregate or the filters read.}
{（a）由连续性，一个期间所含月份的键恰好构成子查询读出的上下界之间的整数区间，因此事实行的日期键落在区间内当且仅当它连接到该期间的一行日期记录，且由唯一性只有一行；匹配不到任何日期行的键落在维度的键范围之外，两种写法都排除它。（b）至多匹配一行的左连接把每个左表行恰好保留一次，也不提供聚合或过滤读取的任何内容。}
\end{proof}
\bi{The premise of (a) is a condition of the new revision. The premise of (b) is a condition of the predecessor that the new revision no longer needs: if the right side later loses uniqueness, the predecessor becomes invalid while the new revision stays correct by Proposition~\ref{prop:sufficiency}. Wherever the maintained conditions hold, a rule revision therefore agrees with its predecessor on every period, not only on the samples; the sampled tests check the implementation and measure the cost. An LLM-proposed rewrite has no such rule behind it, and its equivalence rests on the sampled tests. The adopted candidate is published as the next revision of the same key and supersedes its predecessor, which stays usable while its own conditions hold. Maintenance checks a premise that an optimization added after all other conditions; when it alone fails, every condition shared with the predecessor has just been confirmed, and \system\ invalidates the optimized revision and reinstates the predecessor instead of searching for a repair (Section~\ref{sec:opt-eval}).}
{（a）的前提是新修订的条件。（b）的前提是前一修订的条件，新修订不再需要它：若右侧之后失去唯一性，前一修订失效，而新修订由命题~\ref{prop:sufficiency} 仍然正确。因此，只要受维护的条件成立，规则修订就在每个期间上都与前一修订一致，而不只是在抽样期间上；抽样测试检查的是实现，并测量代价。大模型提出的改写没有这样的规则作依据，其等价只依赖抽样测试。采纳的候选作为同一键的下一个修订发布，并取代前一修订；前一修订在其自身条件成立时仍可使用。维护最后检查优化新增的前提；只有它不成立时，与前一修订共有的每个条件都刚刚得到确认，\system\ 使优化后的修订失效并恢复前一修订，而不去搜索修复（第~\ref{sec:opt-eval} 节）。}
