\section{\bt{Related Work}{相关工作}}
\label{sec:related}
\paragraph{\bt{Agent memory}{智能体记忆}}
\bi{Agent memories retain facts and conversations~\cite{chhikara2025mem0,packer2023memgpt}, workflows~\cite{wang2025awm}, strategies~\cite{zhao2024expel,ouyang2026reasoningbank}, playbooks~\cite{zhang2026ace}, linked notes~\cite{xu2025amem}, and plans~\cite{zhang2025apc}. G-Memory shares hierarchical trajectories and insights within a multi-agent system~\cite{zhang2025gmemory}; Learning to Share reuses intermediate steps within a task~\cite{fioresi2026learning}, while Collaborative Memory and MemClaw govern access and writes across users or agents~\cite{rezazadeh2025collaborative,margalit2026governed}. Recent systems also support invalidation, version checks, transactions, and repair~\cite{wu2026invalidation,chen2026fresh,li2026memtx,zhao2026memorepair}. \system\ uses the database as a sharing boundary: agents contribute executable metric and feature definitions that later sessions compile for their own questions. Shared validation and maintenance support this reuse across the workload.}
{智能体记忆保存事实与对话~\cite{chhikara2025mem0,packer2023memgpt}、工作流~\cite{wang2025awm}、策略~\cite{zhao2024expel,ouyang2026reasoningbank}、手册~\cite{zhang2026ace}、相互链接的笔记~\cite{xu2025amem}和计划~\cite{zhang2025apc}。G-Memory 在多智能体系统内共享分层轨迹与洞见~\cite{zhang2025gmemory}；Learning to Share 在任务内复用中间步骤~\cite{fioresi2026learning}，Collaborative Memory 与 MemClaw 则管理跨用户或智能体的访问和写入~\cite{rezazadeh2025collaborative,margalit2026governed}。近期系统还支持失效、版本检查、事务和修复~\cite{wu2026invalidation,chen2026fresh,li2026memtx,zhao2026memorepair}。\system\ 以数据库为共享边界：智能体贡献可执行指标与特征定义，后续会话将其编译为自身问题所需的查询；共享验证与维护支撑整个负载中的复用。}

\paragraph{\bt{Database exploration memory}{数据库探索记忆}}
\bi{AgentSM structures prior or synthesized trajectories, retrieves similar questions within a database, and constructs composite tools from recurring tool sequences~\cite{biswal2026agentsm}. These mechanisms reduce repeated exploration. \system\ represents reusable work as metric and feature definitions shared by the agents of a database. Compilation binds their measures, grain, joins, and filters to new periods and seed tables, replacing repeated exploration and SQL construction. Shared checks and maintenance support continued use of these definitions.}
{AgentSM 将既往或合成轨迹结构化，在同一数据库内检索相似问题，并从重复的工具序列构造复合工具~\cite{biswal2026agentsm}，减少重复探索。\system\ 将可复用工作表示为同库智能体共享的指标与特征定义；编译把其中的度量、粒度、连接和过滤绑定到新的期间与种子表，替代重复探索和 SQL 构造。共享检查与维护支持这些定义的持续使用。}

\paragraph{\bt{Data agents and business semantics}{数据智能体与业务语义}}
\bi{Agent-first data systems motivate persistent database knowledge~\cite{liu2026agents,luo2026dataagents}; enterprise text-to-SQL and BI systems benefit from explicit business semantics~\cite{lei2025spider2,floratou2024nl2sql,li2023bird,sequeda2024kg,huo2026birdinteract,jiang2025siriusbi}. DataLab extracts metadata and calculation logic from historical SQL/Python scripts, organizes knowledge for retrieval, and translates requests through a DSL for downstream generation~\cite{weng2025datalab}. It also updates notebook dependency graphs after edits. \system\ accumulates executable definitions in a shared layer between agents and the database. Definitions learned in one session serve subsequent agents and tasks, amortizing discovery and SQL construction; validation and maintenance are performed through the same layer.}
{面向智能体的数据系统提出持久数据库知识的需求~\cite{liu2026agents,luo2026dataagents}；企业 Text-to-SQL 与 BI 系统受益于明确的业务语义~\cite{lei2025spider2,floratou2024nl2sql,li2023bird,sequeda2024kg,huo2026birdinteract,jiang2025siriusbi}。DataLab 从历史 SQL/Python 脚本提取元数据与计算逻辑，组织知识以支持检索，并通过 DSL 将请求转交后续生成流程~\cite{weng2025datalab}；它还在编辑后更新笔记本依赖图。\system\ 在智能体与数据库之间的共享层中积累可执行定义，使一个会话学到的定义服务后续智能体与任务，分摊发现和构造 SQL 的开销；验证与维护通过同一层完成。}

\bi{MetricFlow and Databricks metric views centralize metric definitions and query generation~\cite{dbt2026metricflow,databricks2026metricviews}. \system\ populates its shared layer from successful agent sessions, allowing knowledge to accumulate with database use. Compilation reuses definitions across periods and prediction instances; condition checks and maintenance keep revisions available to subsequent consumers as the database changes.}
{MetricFlow 与 Databricks 指标视图集中管理指标定义和查询生成~\cite{dbt2026metricflow,databricks2026metricviews}。\system\ 从成功的智能体会话构建共享层，使知识随数据库的使用而积累；编译支持跨期间与预测样本复用定义，条件检查与维护则随数据库变化管理供后续使用者复用的版本。}

\bi{\emph{Prediction over relational data.} RelBench poses forecasting tasks over multi-table databases~\cite{robinson2024relbench} and is the testbed of relational deep learning~\cite{fey2024rdl}; LLM agents engineer features for such tasks by writing and validating code or SQL~\cite{hollmann2023caafe,guo2024dsagent}. The database community automates data preparation for learning: FeatPilot searches join paths for the features that most improve a model~\cite{liang2025featpilot}, CtxPipe builds preparation pipelines for one table by reinforcement learning~\cite{gao2024ctxpipe}, DeepPrep explores operator pipelines with an LLM agent over a search tree~\cite{fan2026deepprep}, and KnowTrans transfers knowledge between data-preparation tasks by fine-tuning~\cite{ge2025knowtrans}. These works prepare data for one task at a time; \system\ makes the features that one agent verified reusable by every later session and every other task on the same database, and compiles them so that they cannot read data after the seed time.}
{\emph{关系数据上的预测。} RelBench 在多表数据库上提出预测任务~\cite{robinson2024relbench}，也是关系深度学习的实验平台~\cite{fey2024rdl}；LLM 智能体通过编写并验证代码或 SQL 为这类任务构建特征~\cite{hollmann2023caafe,guo2024dsagent}。数据库领域为学习任务自动做数据准备：FeatPilot 搜索对模型提升最大的连接路径特征~\cite{liang2025featpilot}，CtxPipe 用强化学习为单张表构建准备流水线~\cite{gao2024ctxpipe}，DeepPrep 用 LLM 智能体在搜索树上探索算子流水线~\cite{fan2026deepprep}，KnowTrans 通过微调在数据准备任务之间迁移知识~\cite{ge2025knowtrans}。这些工作一次为一个任务准备数据；\system\ 让一个智能体验证过的特征可被同一数据库上之后的每个会话和其他每个任务复用，并把它们编译成不可能读到种子时间之后的数据。}

\paragraph{\bt{Sharing work in database systems}{数据库系统中的工作共享}}
\bi{Databases have long avoided repeated work: multi-query optimization and shared execution evaluate the common work of concurrent queries once~\cite{sellis1988mqo,harizopoulos2005qpipe,giannikis2012shareddb}, recycling keeps intermediate results and invalidates those affected by updates~\cite{ivanova2010recycling}, and caches reuse results through semantic descriptions~\cite{dar1996semantic}, update-driven invalidation~\cite{garrod2008ferdinand}, input-dependent keys~\cite{gunda2010nectar}, leases that merge concurrent misses~\cite{nishtala2013memcache}, and transactional consistency~\cite{ports2010txcache}. Materialized views are maintained incrementally~\cite{gupta1995maintenance,blakeley1986efficiently}, deferred off the update path~\cite{colby1996deferred}, or refreshed when referenced~\cite{zhou2007lazy}, and build systems verify dependency traces~\cite{mokhov2018build,hammer2014adapton}. \system\ extends work sharing to agent exploration: learned definitions replace repeated discovery and SQL construction in later sessions. Dependency tracking and snapshot consistency also allow consumers to share validation evidence for those definitions (Lemma~\ref{lem:reuse}).}
{数据库一向避免重复工作：多查询优化与共享执行对并发查询的公共工作只计算一次~\cite{sellis1988mqo,harizopoulos2005qpipe,giannikis2012shareddb}，中间结果回收保留中间结果并使受更新影响的结果失效~\cite{ivanova2010recycling}，缓存借助语义描述~\cite{dar1996semantic}、更新驱动失效~\cite{garrod2008ferdinand}、依赖输入的键~\cite{gunda2010nectar}、合并并发未命中的租约~\cite{nishtala2013memcache}和事务一致性~\cite{ports2010txcache}复用结果。物化视图可以增量维护~\cite{gupta1995maintenance,blakeley1986efficiently}、移出更新路径~\cite{colby1996deferred}或在被引用时刷新~\cite{zhou2007lazy}，构建系统核验依赖轨迹~\cite{mokhov2018build,hammer2014adapton}。\system\ 将工作共享扩展到智能体探索：已学定义替代后续会话中重复的发现与 SQL 构造；依赖跟踪和快照一致性还允许使用者共享这些定义的验证证据（引理~\ref{lem:reuse}）。}

\paragraph{\bt{Constraints and data validation}{约束与数据验证}}
\bi{Summarizability research identifies disjointness and completeness as conditions for correct aggregation~\cite{lenz1997summarizability,mazon2009summarizability,horner2004additivity}, integrity checking specializes verification to the updates that can violate a constraint~\cite{nicolas1982integrity,ceri1990constraint}, and data-validation systems and pipeline tests check declared constraints on tables~\cite{schelter2018deequ,breck2019validation,dbt2026tests}. Building on foundational summarizability and integrity-checking primitives, \system\ automatically derives these conditions from learned definitions and integrates their shared verification into query admission and repair.}
{汇总性研究指出不相交与完整是聚合正确的条件~\cite{lenz1997summarizability,mazon2009summarizability,horner2004additivity}，完整性检查把验证限定在可能违反约束的更新上~\cite{nicolas1982integrity,ceri1990constraint}，数据验证系统与管道测试在表上检查声明的约束~\cite{schelter2018deequ,breck2019validation,dbt2026tests}。基于汇总性与完整性检查的基础机制，\system\ 自动从学得的定义推导这些条件，并将条件的共享验证纳入查询准入和修复。}
