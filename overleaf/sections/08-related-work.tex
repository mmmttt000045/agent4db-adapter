\section{\bt{Related Work}{相关工作}}
\label{sec:related}
\paragraph{\bt{Agent memory}{智能体记忆}}
\bi{Memory systems for LLM agents keep one agent's experience: long-term facts and conversations~\cite{chhikara2025mem0,packer2023memgpt}, workflows induced from successful trajectories~\cite{wang2025awm}, insights and strategies~\cite{zhao2024expel,ouyang2026reasoningbank}, evolving context playbooks~\cite{zhang2026ace}, linked notes~\cite{xu2025amem}, plan templates~\cite{zhang2025apc}, and past solutions~\cite{guo2024dsagent}; a tutorial treats agentic memory as a data-management problem~\cite{li2026agenticmemory}, and MemLens manages memory entries by their value~\cite{wei2026memlens}. Their knowledge concerns the agent's own tasks, evolves by the agent's own feedback, and is learned again by every agent. G-Memory shares a hierarchy of trajectories and insights among the agents of one multi-agent system~\cite{zhang2025gmemory}; it still stores text about earlier work, which our evaluation shows the agents turn into SQL by exploring again (Section~\ref{sec:relbench-eval}). Sharing between agents has also appeared within one task, where Learning to Share lets the parallel agents of one task add selected intermediate steps to a common memory to save computation~\cite{fioresi2026learning}, and as governed stores for agent fleets, where Collaborative Memory exposes memory fragments across users under access rules~\cite{rezazadeh2025collaborative} and MemClaw scopes, supersedes, and traces the writes of many agents~\cite{margalit2026governed}; these stores govern who writes and reads, but their entries do not describe a database whose data changes, and they do not measure what sharing saves. For memories that several agents read, recent work keeps derived records consistent through version stamps or explicit revocation: invalidation contracts evict cached fixes after data drift~\cite{wu2026invalidation}, PlanFence checks that a shared plan was derived from current input versions~\cite{chen2026fresh}, MemTX commits writes through snapshot-isolated transactions~\cite{li2026memtx}, and \textsc{MemoRepair} republishes the descendants of a corrected source after validation~\cite{zhao2026memorepair}. \system\ shares across independent agents and sessions, and its records describe a database that changes underneath them; it checks them against that database with conditions derived from each record, repairs or invalidates them once for every agent, and binds their use to the snapshot a query reads.}
{大模型智能体的记忆系统保存一个智能体的经验：长期事实与对话~\cite{chhikara2025mem0,packer2023memgpt}，从成功轨迹中归纳的工作流~\cite{wang2025awm}，洞见与策略~\cite{zhao2024expel,ouyang2026reasoningbank}，不断演化的上下文手册~\cite{zhang2026ace}，互相链接的笔记~\cite{xu2025amem}，计划模板~\cite{zhang2025apc}，以及既往方案~\cite{guo2024dsagent}；一篇教程把智能体记忆当作数据管理问题来讨论~\cite{li2026agenticmemory}，MemLens 按价值管理记忆条目~\cite{wei2026memlens}。这些知识关于智能体自己的任务，依据智能体自己的反馈演化，每个智能体都要重新学一遍。G-Memory 在一个多智能体系统的智能体之间共享分层的轨迹与洞见~\cite{zhang2025gmemory}；它保存的仍是关于以往工作的文字，我们的实验表明智能体要再次探索才能把它变成 SQL（第~\ref{sec:relbench-eval} 节）。智能体之间的共享也出现在同一任务之内，Learning to Share 让同一任务的并行智能体把选出的中间步骤加入公共记忆，以节省计算~\cite{fioresi2026learning}；也出现在面向智能体群的受治理存储中，Collaborative Memory 按访问规则在用户之间开放记忆片段~\cite{rezazadeh2025collaborative}，MemClaw 对多个智能体的写入做范围限定、取代与溯源~\cite{margalit2026governed}。这些存储管的是谁能写、谁能读，但其中的条目并不描述一个数据会变化的数据库，也没有测量共享省下多少。对于多个智能体读取的记忆，近期工作借助版本戳或显式撤销保持派生记录一致：失效契约在数据漂移后驱逐缓存的修正~\cite{wu2026invalidation}，PlanFence 检查共享计划是否由输入的当前版本推出~\cite{chen2026fresh}，MemTX 通过快照隔离的事务提交写入~\cite{li2026memtx}，\textsc{MemoRepair} 在验证后重新发布被更正来源的派生条目~\cite{zhao2026memorepair}。\system\ 在相互独立的智能体与会话之间共享，其记录描述一个会在其下变化的数据库；它用从每条记录推出的条件对照该数据库检查记录，为所有智能体一次性地修复或使其失效，并把使用绑定到查询所读的快照。}

\paragraph{\bt{Data agents and business semantics}{数据智能体与业务语义}}
\bi{Agent-first data systems observe that agent requests are highly redundant and call for a persistent memory that serves many agents~\cite{liu2026agents}; a tutorial surveys data agents and their difficulty with changing data~\cite{luo2026dataagents}. Enterprise schemas remain hard for text-to-SQL~\cite{lei2025spider2,floratou2024nl2sql}, explicit business semantics raise accuracy~\cite{li2023bird,sequeda2024kg}, and interactive benchmarks treat missing business knowledge as a failure to recover from~\cite{huo2026birdinteract}. Business-intelligence platforms maintain term definitions~\cite{jiang2025siriusbi} or generate calculation logic from script history~\cite{weng2025datalab}, metric layers let engineers declare definitions by hand~\cite{dbt2026metricflow,databricks2026metricviews}, and AgentSM keeps a text-to-SQL agent's prior or synthesized trajectories as semantic memory, retrieved by question similarity within the same database~\cite{biswal2026agentsm}. \system\ learns such definitions from agents' sessions and shares them; a text-to-SQL agent is a consumer of the memory, not a substitute for it. Robustness to schema variation~\cite{zhang2025evoschema,furst2025datamodel} is complementary.}
{面向智能体的数据系统指出智能体请求高度重复，并呼吁为众多智能体服务的持久记忆~\cite{liu2026agents}；一篇教程综述了数据智能体及其难以适应变化数据的问题~\cite{luo2026dataagents}。企业表结构对 Text-to-SQL 仍然困难~\cite{lei2025spider2,floratou2024nl2sql}，显式业务语义能提高正确率~\cite{li2023bird,sequeda2024kg}，交互式基准把缺失的业务知识当作需要弥补的失败~\cite{huo2026birdinteract}。商业智能平台维护术语定义~\cite{jiang2025siriusbi}或从脚本历史生成计算逻辑~\cite{weng2025datalab}，指标层由工程师人工声明定义~\cite{dbt2026metricflow,databricks2026metricviews}，AgentSM 把一个 Text-to-SQL 智能体以往的或合成的轨迹保存为语义记忆，在同一数据库内按问题相似度检索~\cite{biswal2026agentsm}。\system\ 从智能体的会话中学到这些定义并加以共享；Text-to-SQL 智能体是记忆的使用者，而不是它的替代。表结构变化下的鲁棒性~\cite{zhang2025evoschema,furst2025datamodel}与本文互补。}

\bi{\emph{Prediction over relational data.} RelBench poses forecasting tasks over multi-table databases~\cite{robinson2024relbench} and is the testbed of relational deep learning~\cite{fey2024rdl}; LLM agents engineer features for such tasks by writing and validating code or SQL~\cite{hollmann2023caafe,guo2024dsagent}. The database community automates data preparation for learning: FeatPilot searches join paths for the features that most improve a model~\cite{liang2025featpilot}, CtxPipe builds preparation pipelines for one table by reinforcement learning~\cite{gao2024ctxpipe}, DeepPrep explores operator pipelines with an LLM agent over a search tree~\cite{fan2026deepprep}, and KnowTrans transfers knowledge between data-preparation tasks by fine-tuning~\cite{ge2025knowtrans}. These works prepare data for one task at a time; \system\ makes the features that one agent verified reusable by every later session and every other task on the same database, and compiles them so that they cannot read data after the seed time.}
{\emph{关系数据上的预测。} RelBench 在多表数据库上提出预测任务~\cite{robinson2024relbench}，也是关系深度学习的实验平台~\cite{fey2024rdl}；LLM 智能体通过编写并验证代码或 SQL 为这类任务构建特征~\cite{hollmann2023caafe,guo2024dsagent}。数据库领域为学习任务自动做数据准备：FeatPilot 搜索对模型提升最大的连接路径特征~\cite{liang2025featpilot}，CtxPipe 用强化学习为单张表构建准备流水线~\cite{gao2024ctxpipe}，DeepPrep 用 LLM 智能体在搜索树上探索算子流水线~\cite{fan2026deepprep}，KnowTrans 通过微调在数据准备任务之间迁移知识~\cite{ge2025knowtrans}。这些工作一次为一个任务准备数据；\system\ 让一个智能体验证过的特征可被同一数据库上之后的每个会话和其他每个任务复用，并把它们编译成不可能读到种子时间之后的数据。}

\paragraph{\bt{Sharing work in database systems}{数据库系统中的工作共享}}
\bi{Databases have long avoided repeated work: multi-query optimization and shared execution evaluate the common work of concurrent queries once~\cite{sellis1988mqo,harizopoulos2005qpipe,giannikis2012shareddb}, recycling keeps intermediate results and invalidates those affected by updates~\cite{ivanova2010recycling}, and caches reuse results through semantic descriptions~\cite{dar1996semantic}, update-driven invalidation~\cite{garrod2008ferdinand}, input-dependent keys~\cite{gunda2010nectar}, leases that merge concurrent misses~\cite{nishtala2013memcache}, and transactional consistency~\cite{ports2010txcache}. Materialized views are maintained incrementally~\cite{gupta1995maintenance,blakeley1986efficiently}, deferred off the update path~\cite{colby1996deferred}, or refreshed when referenced~\cite{zhou2007lazy}, and build systems verify dependency traces~\cite{mokhov2018build,hammer2014adapton}. These techniques share the results of queries, which repeat in applications~\cite{ma2018querybot}; agents repeat knowledge instead, and their SQL rarely repeats (Table~\ref{tab:workload-characterization}). \system\ shares the knowledge behind the queries, and it reuses check results under a reuse rule proved sound (Lemma~\ref{lem:reuse}).}
{数据库一向避免重复工作：多查询优化与共享执行对并发查询的公共工作只计算一次~\cite{sellis1988mqo,harizopoulos2005qpipe,giannikis2012shareddb}，中间结果回收保留中间结果并使受更新影响的结果失效~\cite{ivanova2010recycling}，缓存借助语义描述~\cite{dar1996semantic}、更新驱动失效~\cite{garrod2008ferdinand}、依赖输入的键~\cite{gunda2010nectar}、合并并发未命中的租约~\cite{nishtala2013memcache}和事务一致性~\cite{ports2010txcache}复用结果。物化视图可以增量维护~\cite{gupta1995maintenance,blakeley1986efficiently}、移出更新路径~\cite{colby1996deferred}或在被引用时刷新~\cite{zhou2007lazy}，构建系统核验依赖轨迹~\cite{mokhov2018build,hammer2014adapton}。这些技术共享的是查询的结果，而查询在应用中会重复~\cite{ma2018querybot}；智能体重复的则是知识，它们的 SQL 很少重复（表~\ref{tab:workload-characterization}）。\system\ 共享查询背后的知识，并以被证明可靠的复用规则复用检查结果（引理~\ref{lem:reuse}）。}

\paragraph{\bt{Constraints and data validation}{约束与数据验证}}
\bi{Summarizability research identifies disjointness and completeness as conditions for correct aggregation~\cite{lenz1997summarizability,mazon2009summarizability,horner2004additivity}, integrity checking specializes verification to the updates that can violate a constraint~\cite{nicolas1982integrity,ceri1990constraint}, and data-validation systems and pipeline tests check declared constraints on tables~\cite{schelter2018deequ,breck2019validation,dbt2026tests}. \system\ derives such checks from each shared definition and pays for them once for all agents, so that keeping shared knowledge valid costs far less than the exploration it saves.}
{汇总性研究指出不相交与完整是聚合正确的条件~\cite{lenz1997summarizability,mazon2009summarizability,horner2004additivity}，完整性检查把验证限定在可能违反约束的更新上~\cite{nicolas1982integrity,ceri1990constraint}，数据验证系统与管道测试在表上检查声明的约束~\cite{schelter2018deequ,breck2019validation,dbt2026tests}。\system\ 从每个共享定义推出这样的检查，并为所有智能体只付一次代价，使保持共享知识有效的代价远小于它省下的探索。}
