\section{\bt{Discussion and Conclusion}{讨论与结论}}
\label{sec:limitations}
\bi{\emph{Scope.} \system\ shares metric definitions over star and snowflake schemas with a date dimension or a date column, which covers the aggregate questions that make up most of an analytics workload; tables joined twice in different roles and many-to-many bridges are outside the implementation. Learning sessions pass through one set of publication checks, and reconciling the meanings that different teams give one name is left to people.}
{\emph{适用范围。}\system\ 共享以日期维度或日期列给出日期的星型与雪花型模式上的指标定义，覆盖了分析负载中占多数的聚合问题；同一张表以不同角色连接两次、多对多的桥接表不在实现范围内。学习会话经过同一组发布前检查，不同团队对同一名称给出的含义由人来调和。}

\bi{Data agents spend their time and tokens rediscovering what other agents already found, and memory kept per agent does not change that. \system\ moves the memory to the database and shares it: one agent explores, and every other agent answers with one SQL. The work that keeps the shared knowledge valid and fast, checks, repairs, and optimizations, is done once for all agents, so the saving grows with every agent that arrives and survives the changes of the data underneath.}
{数据智能体把时间和 token 花在重新发现其他智能体早已发现的东西上，而按智能体保存的记忆改变不了这一点。\system\ 把记忆移到数据库一侧并加以共享：一个智能体探索，其他每个智能体用一条 SQL 作答。让共享知识保持有效、保持高效的检查、修复与优化，都为所有智能体只做一次，因此节省随每个新到的智能体增长，并经得起底层数据的变化。}
