\section{\bt{Conclusion}{结论}}
\bi{Data agents repeat knowledge rather than queries, and sharing the metric definitions they learn makes them more accurate and consistent. Shared definitions, however, are long-lived state over a changing database, and their SQL stays correct only while unstated data properties hold. \system\ makes those properties explicit as executable conditions derived from each definition, keeps their check results by dependency version, binds every declared use to check results that hold on the query's own snapshot, and repairs a broken definition only with a unique fix that passes a regression test against the agent's own SQL, invalidating it otherwise. On libraries learned by three LLMs and on TPC-DS with template-derived definitions, maintained definitions serve no wrong answer under the covered changes; same-snapshot validation removes answers on condition-violating data under concurrent writers; repair invalidates the definition when the agent's SQL cannot tell populations apart; and end to end, maintained definitions keep agents as accurate as retrieved trajectories when the data is unchanged and more accurate when it changes, and they do so with fewer turns, fewer tokens, and shorter tasks than agents that explore alone. Changes to the meaning of values, undeclared uses, and repairs that need human judgment mark the next steps.}
{数据智能体重复的是知识而非查询，共享它们学到的指标定义能让答案更准确、口径更一致。但共享定义是变化数据库上的长期状态，其 SQL 只在一些未写明的数据性质成立时才保持正确。\system\ 把这些性质显式化为从每个定义推出的可执行条件，按依赖版本维护检查结果，把每次声明了修订的使用绑定到在查询自身快照上成立的检查结果，并只用通过回归测试（以智能体自己的 SQL 为对照）的唯一修复来修复被破坏的定义，否则使定义失效。在 3 个大模型学到的定义库和模板定义的 TPC-DS 上，维护后的定义在条件覆盖的变化下不给出错误答案；同快照验证在并发写入下消除了在违反条件的数据上作答；智能体的 SQL 无法区分总体时修复使定义失效；端到端实验中，维护后的定义在数据不变时与检索到的轨迹一样准确，在数据变化时更准确，而且比独自探索的智能体轮数更少、token 更少、任务更短。取值含义的变化、未声明的使用以及需要人工判断的修复，是下一步的方向。}
