\begin{abstract}
\bi{Data agents answer analytical questions and build features for models by exploring the database: they list tables, probe values, and test joins over many LLM turns before they settle on SQL. This exploration is where their time and tokens go, and agents on the same database repeat it in every session. Agent memory does not remove the repetition, because it keeps text about an agent's work, which the agent must still turn into SQL over tables it inspects again. We argue that the memory of data agents belongs with the database and is shared by every agent that queries it. We present \system, a shared memory layer between data agents and a SQL database. It learns metric and feature definitions from the agents' own sessions, publishes a definition only after checks on the data, compiles feature definitions so that they cannot read data recorded after the seed time, and pays for checking, maintaining, and optimizing each definition once for all agents, so that sharing stays cheaper than exploring as the data change. On RelBench under periodic retraining, against four published memories run as their papers define them, \system\ uses \RbStackMavraTokSave\% and \RbTrialMavraTokSave\% fewer tokens than agents without memory on two databases and \RbStackMavraVsBest\% and \RbTrialMavraVsBest\% fewer than the best published memory, and its agents finish \RbStackMavraSpeed$\times$ and \RbTrialMavraSpeed$\times$ faster. On TPC-DS, with \PpAgents\ agents asking metric questions, it uses \PpMavraTokSaveNone\% fewer tokens than no memory, and after a restatement its agents answer \PpMavraChangeAcc\% correctly, agents without memory \PpNoneChangeAcc\%.}
{数据智能体通过探索数据库来回答分析问题、为模型构建特征：在多轮大模型调用中列出表、探查取值、检验连接，最后确定 SQL。时间和 token 都花在这种探索上，而同一数据库上的智能体在每个会话里重复它。智能体记忆并不能消除这种重复，因为它保存的是关于智能体工作的文字，智能体仍要在重新查看的表上把它变成 SQL。我们认为，数据智能体的记忆应当放在数据库一侧，由查询它的所有智能体共享。本文提出 \system，一个位于数据智能体与 SQL 数据库之间的共享记忆层。它从智能体自己的会话中学习指标定义与特征定义，只在定义通过数据上的检查后才发布，把特征定义编译成不可能读到种子时间之后记录的数据，并为所有智能体对每个定义只检查、维护和优化一次，使共享在数据变化时依然比探索便宜。在 RelBench 的定期重训设置下，与四个按其论文方式运行的已发表记忆相比，\system\ 在两个数据库上比无记忆的智能体少用 \RbStackMavraTokSave\% 与 \RbTrialMavraTokSave\% 的 token，比最好的已发表记忆少用 \RbStackMavraVsBest\% 与 \RbTrialMavraVsBest\%，其智能体快 \RbStackMavraSpeed\ 倍与 \RbTrialMavraSpeed\ 倍。在 TPC-DS 上，\PpAgents\ 个智能体提出指标问题时，它比无记忆少用 \PpMavraTokSaveNone\% 的 token；一次更正之后，其智能体答对 \PpMavraChangeAcc\%，无记忆的智能体为 \PpNoneChangeAcc\%。}
\end{abstract}
