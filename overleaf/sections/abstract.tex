\begin{abstract}
\bi{Data agents answer analytical questions by exploring the database: they list tables, probe values, and test joins over many LLM turns before they settle on SQL. Agents on the same database repeat this exploration in every session, and agent memory does not remove the repetition, because each agent keeps only its own experience: every new agent explores again. We argue that the memory of data agents belongs with the database and is shared by every agent that queries it, so that one agent's exploration saves the time and tokens of all the others. Sharing on a database raises two problems that per-agent memory does not face: what is shared must answer other agents' questions, and it must stay correct while the data changes underneath it, or sharing hands one wrong answer to every agent. We present \system, a shared memory layer between data agents and a SQL database. It publishes metric definitions learned from successful sessions after checking the SQL that other agents will read, attaches executable conditions that we prove sufficient for the definition's aggregate, and checks, repairs, and optimizes each definition once for all agents. When \PpAgents\ agents arrive at one database, \system\ uses \PpMavraTokSaveNone\% fewer tokens than agents without memory and its agents finish \PpMavraSpeedupNone$\times$ faster; against single-agent memory built with the same mechanism, it uses \PpMavraTokSavePrivate\% fewer tokens and is \PpMavraSpeedupPrivate$\times$ faster, while answering \PpMavraAcc\% of the questions correctly, against \PpNoneAcc\% and \PpPrivateAcc\%. Once a metric is learned, each agent answers with \PpMavraLateTokXNone$\times$ fewer tokens and \PpMavraLateSpeedupNone$\times$ faster than exploring alone. When updates break shared knowledge, \system\ repairs it once for all agents and keeps \DsCondModeled--\GeCondModeled\% of answers correct, against \GeTrajModeled--\DsTrajModeled\% for shared examples.}
{数据智能体通过探索数据库来回答分析问题：在多轮大模型调用中列出表、探查取值、检验连接，最后确定 SQL。同一数据库上的智能体在每个会话里重复这种探索，而智能体记忆并不能消除这种重复，因为每个智能体只保存自己的经验：每个新来的智能体都要重新探索。我们认为，数据智能体的记忆应当放在数据库一侧，由查询它的所有智能体共享，使一个智能体的探索为其他所有智能体省下时间和 token。在数据库上共享带来单智能体记忆不会遇到的两个问题：共享的内容必须能回答其他智能体的问题；而且必须在数据变化时保持正确，否则共享会把同一个错误答案交给每个智能体。本文提出 \system，一个位于数据智能体与 SQL 数据库之间的共享记忆层。它从成功的会话中学习指标定义，在检查其他智能体将要读到的 SQL 之后发布；为每个定义附上可执行条件，我们证明这些条件足以保证定义的聚合正确；并为所有智能体一次性地检查、修复和优化每个定义。当 \PpAgents\ 个智能体陆续使用同一数据库时，\system\ 比无记忆的智能体少用 \PpMavraTokSaveNone\% 的 token，其智能体快 \PpMavraSpeedupNone\ 倍；与用同一机制构建的单智能体记忆相比，少用 \PpMavraTokSavePrivate\% 的 token、快 \PpMavraSpeedupPrivate\ 倍；同时答对 \PpMavraAcc\% 的问题，后两者分别为 \PpNoneAcc\% 与 \PpPrivateAcc\%。指标学会之后，每个智能体每题比独自探索少用 \PpMavraLateTokXNone\ 倍 token、快 \PpMavraLateSpeedupNone\ 倍。当更新破坏共享的知识时，\system\ 为所有智能体一次性修复，保持 \DsCondModeled--\GeCondModeled\% 的答案正确，共享示例为 \GeTrajModeled--\DsTrajModeled\%。}
\end{abstract}
