\begin{abstract}
\bi{Data agents answer analytical questions by exploring the database: they list tables, probe values, and test joins over many LLM turns before they settle on SQL. This exploration is where their time and tokens go, and agents on the same database repeat it in every session. Agent memory does not remove the repetition, because each agent keeps only its own experience, so the cost grows with the number of agents. We argue that the memory of data agents belongs with the database and is shared by every agent that queries it: one agent explores, and every other agent answers with one SQL. We present \system, a shared memory layer between data agents and a SQL database. It learns metric definitions from the agents' own sessions, separates them from question parameters so that one learned definition answers questions no agent has asked yet, and pays for checking, maintaining, and optimizing each definition once for all agents, so that sharing stays cheaper than exploring as the data changes. When \PpAgents\ agents arrive at a TPC-DS database, \system\ uses \PpMavraTokSaveNone\% fewer tokens than agents without memory and its agents finish \PpMavraSpeedupNone$\times$ faster; the saving grows with every agent that arrives, and once a metric is learned an agent answers with \PpMavraLateSteps\ LLM calls instead of \PpNoneLateSteps, \PpMavraLateTokXNone$\times$ fewer tokens, and \PpMavraLateSpeedupNone$\times$ faster. Single-agent memory built with the same mechanism saves little, because few agents ask about what they themselves learned: \system\ uses \PpMavraTokSavePrivate\% fewer tokens than it. Maintenance is paid once rather than per agent, one optimization speeds up the SQL of every agent, and the shared answers stay correct after updates: after a restatement \system's agents answer \PpMavraChangeAcc\% correctly, agents without memory \PpNoneChangeAcc\%.}
{数据智能体通过探索数据库来回答分析问题：在多轮大模型调用中列出表、探查取值、检验连接，最后确定 SQL。时间和 token 都花在这种探索上，而同一数据库上的智能体在每个会话里重复它。智能体记忆并不能消除这种重复，因为每个智能体只保存自己的经验，代价随智能体数量增长。我们认为，数据智能体的记忆应当放在数据库一侧，由查询它的所有智能体共享：一个智能体探索，其他每个智能体用一条 SQL 作答。本文提出 \system，一个位于数据智能体与 SQL 数据库之间的共享记忆层。它从智能体自己的会话中学习指标定义，把定义与题目参数分开，使一次学到的定义能回答尚无智能体问过的问题；并为所有智能体对每个定义只检查、维护和优化一次，使共享在数据变化时依然比探索便宜。当 \PpAgents\ 个智能体陆续使用一个 TPC-DS 数据库时，\system\ 比无记忆的智能体少用 \PpMavraTokSaveNone\% 的 token，其智能体快 \PpMavraSpeedupNone\ 倍；节省随每个新到的智能体增长，指标学会之后，每个智能体每题只需 \PpMavraLateSteps\ 次大模型调用而不是 \PpNoneLateSteps\ 次，少用 \PpMavraLateTokXNone\ 倍 token、快 \PpMavraLateSpeedupNone\ 倍。用同一机制构建的单智能体记忆几乎省不下什么，因为很少有智能体会再问自己学过的指标：\system\ 比它少用 \PpMavraTokSavePrivate\% 的 token。维护只付一次而不是每个智能体付一次，一次优化让每个智能体的 SQL 都更快，共享的答案在数据更新后仍然正确：一次更正之后，\system\ 的智能体答对 \PpMavraChangeAcc\%，无记忆的智能体为 \PpNoneChangeAcc\%。}
\end{abstract}
