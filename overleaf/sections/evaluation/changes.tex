\bi{\emph{After a restatement (Q4).} After the \PpAgents\ agents of the population study, a restatement corrects store sales and keeps the old amounts as non-current rows, and every agent returns with four questions about the metrics that read them. \system's agents keep the saving and the answers: they answer \PpMavraChangeAcc\% correctly at \PpMavraChangeTokK\,k tokens and \PpMavraChangeS\,s per question, because each affected definition was repaired once. Agents without memory explore the changed data again, at \PpNoneChangeTokK\,k tokens and \PpNoneChangeS\,s per question, and answer \PpNoneChangeAcc\%. Example retrieval stays as cheap (\PpTrajChangeTokK\,k tokens) but hands every agent SQL that now counts restated sales twice: its agents answer \PpTrajChangeAcc\%, and every wrong answer is \PpTrajChangeOverMin--\PpTrajChangeOverMax\% too high. A saving that returns wrong answers is no saving, and the difference between the two shared memories lies in what they share: examples of past queries or definitions whose conditions \system\ maintains.}
{\emph{一次更正之后（Q4）。}群体实验的 \PpAgents\ 个智能体之后，一次更正修改门店销售并把旧金额保留为非当前行，每个智能体再回来回答 4 道读到它的指标的题。\system\ 的智能体既保住了节省，也保住了答案：它们每题用 \PpMavraChangeTokK\,k token、\PpMavraChangeS\ 秒，答对 \PpMavraChangeAcc\%，因为每个受影响的定义都只修复了一次。没有记忆的智能体在变化后的数据上重新探索，每题 \PpNoneChangeTokK\,k token、\PpNoneChangeS\ 秒，答对 \PpNoneChangeAcc\%。示例检索同样便宜（每题 \PpTrajChangeTokK\,k token），却把现在会把被更正的销售算两次的 SQL 交给每个智能体：它的智能体答对 \PpTrajChangeAcc\%，每个错误答案都偏高 \PpTrajChangeOverMin--\PpTrajChangeOverMax\%。给出错误答案的节省算不上节省；两种共享记忆的差别在于共享的内容：过去查询的示例，还是由 \system\ 维护其条件的定义。}

\bi{\emph{Eleven changes on two schemas.} End to end, each of eleven data changes is applied after the held-out questions and the affected questions are asked again (Figure~\ref{fig:twoschemas}): four non-breaking updates, five breaking changes that the conditions cover (status-change rows, restatements, duplicate loads, SCD Type 2, reformatted date keys), and two outside them. On held-out questions the two shared memories agree (\DsTrajHoldout--\DsCondHoldout\%, against \DsNoShareHoldout\% without memory); under the covered breaking changes \system\ answers \DsCondModeled\% and example retrieval \DsTrajModeled\% on the synthetic dataset, and \GeCondModeled\% against \GeTrajModeled\% on TPC-H. Replaying fixed libraries under the same changes on TPC-DS, TPC-H, SSB, and the BIRD financial database confirms that \system\ serves no wrong answer under the covered changes, apart from \GnCondWrongModeled\ of \GnCondN\ questions whose filter reads a column no condition covers, and under concurrent writes same-snapshot validation keeps every answer off data that breaks the grain, where checking first and executing later answers on such data in up to \SnPreUnannMax\% of queries.}
{\emph{两种模式上的十一种变化。}端到端实验中，十一种数据变化各自在留出题之后施加，并重问受影响的题（图~\ref{fig:twoschemas}）：4 种正常更新、条件覆盖的 5 种破坏性变化（状态流水、更正保留旧行、重复加载、缓慢变化维类型 2、日期键格式变化），以及 2 种不在覆盖范围内的变化。留出题上两种共享记忆相当（\DsTrajHoldout--\DsCondHoldout\%，无记忆为 \DsNoShareHoldout\%）；在条件覆盖的破坏性变化下，合成数据上 \system\ 答对 \DsCondModeled\%，示例检索 \DsTrajModeled\%；TPC-H 上为 \GeCondModeled\% 对 \GeTrajModeled\%。在 TPC-DS、TPC-H、SSB 与 BIRD financial 数据库上用同样的变化回放固定的定义库，结果证实 \system\ 在条件覆盖的变化下不给出错误答案，只有 \GnCondN\ 道题中的 \GnCondWrongModeled\ 道例外，其过滤读取的列没有条件覆盖；在并发写入下，同快照验证让每个答案都避开破坏粒度的数据，而先检查后执行最多有 \SnPreUnannMax\% 的查询在这样的数据上作答。}
