\bi{\emph{After a restatement (Q4).} Following the population study, a restatement corrects store sales while retaining old amounts as non-current rows. Each of the \PpAgents\ agents returns with four affected questions. With each definition repaired once, \system\ answers \PpMavraChangeAcc\% correctly at \PpMavraChangeTokK\,k tokens per question; agents without memory answer \PpNoneChangeAcc\% at \PpNoneChangeTokK\,k. Example retrieval remains cheap (\PpTrajChangeTokK\,k) but answers \PpTrajChangeAcc\% correctly: its unmaintained SQL double-counts sales, and every wrong answer is \PpTrajChangeOverMin--\PpTrajChangeOverMax\% too high.}
{\emph{一次更正之后（Q4）。}群体实验后，一次更正修改门店销售并将旧金额保留为非当前行。\PpAgents\ 个智能体各回来回答四道受影响的题。每个定义只修复一次后，\system\ 每题用 \PpMavraChangeTokK\,k token、答对 \PpMavraChangeAcc\%；无记忆智能体每题用 \PpNoneChangeTokK\,k token、答对 \PpNoneChangeAcc\%。示例检索仍便宜（\PpTrajChangeTokK\,k），但只答对 \PpTrajChangeAcc\%：未维护的 SQL 重复计入销售，每个错误答案均偏高 \PpTrajChangeOverMin--\PpTrajChangeOverMax\%。}

\bi{\emph{Eleven changes on two schemas.} The end-to-end study repeats affected questions after four non-breaking updates, five targeted structural changes (status rows, restatements, duplicate loads, SCD Type 2, and date-key changes), and two changes outside the conditions (Figure~\ref{fig:twoschemas}). On the targeted changes, \system\ and example retrieval answer \DsCondModeled\% and \DsTrajModeled\% correctly on the synthetic data, and \GeCondModeled\% and \GeTrajModeled\% on TPC-H.}
{\emph{两种模式上的十一种变化。}端到端研究在四种正常更新、五种目标结构变化（状态流水、更正、重复加载、缓慢变化维类型 2 和日期键变化），以及两种条件范围外变化后重问受影响的题（图~\ref{fig:twoschemas}）。在目标结构变化下，\system\ 与示例检索在合成数据上分别答对 \DsCondModeled\% 与 \DsTrajModeled\%，在 TPC-H 上分别答对 \GeCondModeled\% 与 \GeTrajModeled\%。}

Across the five targeted structural scenarios, maintenance blocks \the\numexpr\RsStructuralRefused-\RsStructuralUnneeded\relax\ uses whose original SQL would be incorrect, with \RsStructuralWrong\ incorrect results served. \bi{All three structural-scenario errors come from one TPC-H Q12 definition. Its period uses \code{l\_receiptdate}, but its filter compares \code{l\_shipdate < l\_commitdate}. The date-key change appends rows with null \code{l\_shipdate}; receipt-date coverage still passes, while SQL's null comparison drops those rows. The September total is \RsQSingleObserved\ instead of \RsQSingleGold, the period difference is \RsQDiffObserved\ instead of \RsQDiffGold, and the highest month is \RsQRankObserved\ instead of \RsQRankGold. Extending completeness checks to the auxiliary filter columns \code{l\_shipdate} and \code{l\_commitdate}, alongside the primary date key \code{l\_receiptdate}, would detect this failure. In the concurrent grain-breaking stress test, same-snapshot validation prevents unsafe execution; precheck-then-execute admits up to \SnPreUnannMax\% unsafe queries.}
{三次结构变化情形下的错误均来自同一个 TPC-H Q12 定义。其期间使用 \code{l\_receiptdate}，过滤却比较 \code{l\_shipdate < l\_commitdate}。日期键变化追加了 \code{l\_shipdate} 为空的行；收货日期的覆盖检查仍通过，但 SQL 的空值比较排除了这些行。九月总量为 \RsQSingleObserved\ 而非 \RsQSingleGold，跨期差值为 \RsQDiffObserved\ 而非 \RsQDiffGold，最高月为 \RsQRankObserved\ 而非 \RsQRankGold。在主日期键 \code{l\_receiptdate} 之外，将完整性检查扩展至辅助过滤列 \code{l\_shipdate} 与 \code{l\_commitdate}，即可检测这一失效情形。在破坏粒度的并发压力测试中，同快照验证阻止不安全执行；先检查后执行最多有 \SnPreUnannMax\% 的查询使用失效数据。}
