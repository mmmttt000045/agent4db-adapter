\subsection{\bt{Robustness and Correctness Under Data Changes (Q3)}{数据变化下的鲁棒性与正确性（Q3）}}
\label{sec:changes-eval}
\label{sec:scenarios}
\label{sec:validity}
\bi{Maintained definitions improve final answer accuracy over trajectory retrieval after the targeted structural changes on both schemas. The benefit does not extend consistently to the two outside-coverage changes, which expose the limits of structural validation.}
{在两种模式的目标结构变化后，维护定义比轨迹检索获得更高的最终答案正确率。这一收益并未稳定延伸到两种范围外变化，后者揭示了结构验证的边界。}

\bi{\emph{After a restatement.} Following the population study, a restatement corrects store sales while retaining old amounts as non-current rows. Each of the \PpAgents\ agents returns with four affected questions. With each definition repaired once, \system\ answers \PpMavraChangeAcc\% correctly at \PpMavraChangeTokK\,k tokens per question; agents without memory answer \PpNoneChangeAcc\% at \PpNoneChangeTokK\,k. Trajectory Retrieval remains cheap (\PpTrajChangeTokK\,k) but answers \PpTrajChangeAcc\% correctly: its unmaintained SQL double-counts sales, and every wrong answer is \PpTrajChangeOverMin--\PpTrajChangeOverMax\% too high.}
{\emph{一次更正之后。}群体实验后，一次更正修改门店销售并将旧金额保留为非当前行。\PpAgents\ 个智能体各回来回答四道受影响的题。每个定义只修复一次后，\system\ 每题用 \PpMavraChangeTokK\,k token、答对 \PpMavraChangeAcc\%；无记忆智能体每题用 \PpNoneChangeTokK\,k token、答对 \PpNoneChangeAcc\%。轨迹检索仍便宜（\PpTrajChangeTokK\,k），但只答对 \PpTrajChangeAcc\%：未维护的 SQL 重复计入销售，每个错误答案均偏高 \PpTrajChangeOverMin--\PpTrajChangeOverMax\%。}

\bi{\emph{Eleven changes on two schemas.} Each run learns a library, then applies eleven changes independently to the initial data and library: four non-breaking updates, five targeted structural changes, and two outside-coverage changes (unit scaling and backup copies). Figure~\ref{fig:twoschemas} compares seven methods on synthetic retail and the three evaluated on TPC-H. It measures final answer accuracy, including fallback exploration. Table~\ref{tab:repair-regression} reports the repair-regression comparison introduced in Section~\ref{sec:metric-setup}, with unit and backup changes shown separately. Both displays weight scenarios equally within each group.}
{\emph{两种模式上的十一种变化。}每次运行先学习定义库，再从初始数据与定义库分别施加十一种变化：四种正常更新、五种目标结构变化，以及单位缩放和备份副本两种范围外变化。图~\ref{fig:twoschemas} 比较合成零售数据的七种方法与 TPC-H 已评测的三种方法，衡量包含回退探索在内的最终答案正确率。表~\ref{tab:repair-regression} 报告第~\ref{sec:metric-setup} 节介绍的修复回归对照，并分别列出单位与备份变化。两处结果均对组内情形等权。}

\bi{\emph{From retrieval to maintenance.} Retrieval remains effective after non-breaking updates, and \system\ retains \DsCondBenign\% accuracy on synthetic retail and \GeCondBenign\% on TPC-H. Structural changes provide the sharper test. On synthetic retail, prompted verification improves retrieval from \DsTrajModeled\% to \DsTrajVerifyModeled\%, whereas maintained definitions reach \DsCondModeled\%. The \DsCmpModeledCondVerify-point gap has a 95\% run-bootstrap interval of $\DsCmpModeledCondVerifyLo$ to $\DsCmpModeledCondVerifyHi$ points. TPC-H shows the same direction: \system\ reaches \GeCondModeled\% and retrieval \GeTrajModeled\%. Together, these results show that maintaining the reused definition recovers more correct answers than retrieval or verification prompts in this workload.}
{\emph{从检索到维护。}正常更新后，检索仍然有效，\system\ 在合成零售数据与 TPC-H 上也分别保持 \DsCondBenign\% 和 \GeCondBenign\% 的正确率。结构变化进一步检验了维护的作用：合成数据上，提示核验把轨迹检索的正确率从 \DsTrajModeled\% 提高到 \DsTrajVerifyModeled\%，维护定义则达到 \DsCondModeled\%。两者相差 \DsCmpModeledCondVerify\ 个百分点，按运行自助抽样的 95\% 区间为 $\DsCmpModeledCondVerifyLo$ 至 $\DsCmpModeledCondVerifyHi$ 个百分点。TPC-H 的结果方向一致，\system\ 为 \GeCondModeled\%，轨迹检索为 \GeTrajModeled\%。这些结果表明，在该负载中，维护被复用的定义比检索或核验提示恢复了更多正确答案。}

\bi{\emph{Maintenance granularity.} Definition-Level Maintenance and \system\ attain similar accuracy on synthetic structural changes. The former reaches \DsDefModeled\%; \system\ is \DsCmpModeledDef\ percentage point higher, with a 95\% interval of $\DsCmpModeledDefLo$ to $\DsCmpModeledDefHi$. Since this interval includes zero, accuracy does not distinguish the two here. The remaining question is how much work each performs to maintain that accuracy, which motivates the controlled checking and repair experiments in Section~\ref{sec:cost}.}
{\emph{维护粒度。}整定义重查与 \system\ 在合成数据的结构变化下达到相近的正确率。前者为 \DsDefModeled\%，\system\ 高 \DsCmpModeledDef\ 个百分点，差值的 95\% 区间为 $\DsCmpModeledDefLo$ 至 $\DsCmpModeledDefHi$。区间包含零，因此这里的正确率不足以区分两者。接下来需要比较的是：维持这样的正确率，各自要做多少工作？第~\ref{sec:cost} 节通过受控的检查与修复实验回答这个问题。}

\bi{\emph{Limits of structural conditions.} The outside-coverage group shows no consistent advantage for \system. On synthetic backup copies, prompted verification reaches \DsTrajVerifyMirror\% versus \DsCondMirror\% for \system; on TPC-H, \system\ reaches \GeCondMirror\% on backup copies but only \GeCondUnit\% under unit scaling. Maintaining grain and joins does not resolve every value-semantic change or ambiguous repair. The fixed-library audit below separates incorrect reuse from conservative withdrawal.}
{\emph{结构条件的边界。}范围外变化中，\system\ 没有稳定优势。合成数据的备份副本下，提示核验达到 \DsTrajVerifyMirror\%，\system\ 为 \DsCondMirror\%；TPC-H 上，\system\ 在备份副本下达到 \GeCondMirror\%，单位缩放下却仅为 \GeCondUnit\%。维护粒度与连接不能解决所有值域语义变化或有歧义的修复。下面的固定库审计进一步区分错误复用与保守撤下。}

\bi{\emph{What validation prevents.} Final answer accuracy includes an agent's fallback exploration. To examine the layer itself, Table~\ref{tab:replay-safety} replays fixed libraries on four benchmark databases and records whether each use is served or refused. Across the five targeted structural scenarios, maintenance blocks \the\numexpr\RsStructuralRefused-\RsStructuralUnneeded\relax\ uses whose original SQL would be wrong, while \RsStructuralWrong\ incorrect results are served. It also withholds \RsStructuralUnneeded\ uses whose conditions fail even though their original SQL still returns the reference answer. These conservative refusals send the agent back to exploration.}
{\emph{验证阻止了什么。}最终答案正确率包含智能体回退探索的结果。为单独考察共享层，表~\ref{tab:replay-safety} 在四个基准数据库上回放固定定义库，记录每次使用被执行还是被拒绝。五类目标结构变化中，维护阻止了 \the\numexpr\RsStructuralRefused-\RsStructuralUnneeded\relax\ 次原 SQL 会出错的使用，仍提供了 \RsStructuralWrong\ 个错误结果。另有 \RsStructuralUnneeded\ 次使用的原 SQL 虽然仍能返回参考答案，却因条件失败被撤下；这些保守拒绝会让智能体重新探索。}

\bi{The unit and backup scenarios reveal where structural checks need additional semantic information. In this group, \RsOutsideWrong\ of \RsOutsideN\ uses return incorrect results and \RsOutsideRefused\ are refused. Errors account for 43\% of all uses, or 56\% of the \the\numexpr\RsOutsideCorrect+\RsOutsideWrong\relax\ served answers. Unit scaling changes measurement values while preserving grain and join cardinalities. An appended backup can break grain yet leave several filters that restore uniqueness, without identifying which copy is authoritative. These failures motivate unit-aware value checks and explicit source-of-record constraints.}
{单位变化和备份副本说明结构检查何处还需要语义信息。该组 \RsOutsideN\ 次使用中，\RsOutsideWrong\ 次返回错误结果，\RsOutsideRefused\ 次被拒绝。错误占全部使用的 43\%，占 \the\numexpr\RsOutsideCorrect+\RsOutsideWrong\relax\ 个已服务答案的 56\%。单位缩放改变度量值，却保持粒度和连接基数；追加备份则可能破坏粒度，同时留下多个均能恢复唯一性的过滤，而无法据此确定哪个副本是权威来源。这两类失效分别需要感知量纲的值级检查与显式权威来源约束。}

\bi{All three structural-scenario errors come from one TPC-H Q12 definition. Its period uses \code{l\_receiptdate}, but its filter compares \code{l\_shipdate < l\_commitdate}. The date-key change appends rows with null \code{l\_shipdate}; receipt-date coverage still passes, while SQL's null comparison drops those rows. The September total is \RsQSingleObserved\ instead of \RsQSingleGold, the period difference is \RsQDiffObserved\ instead of \RsQDiffGold, and the highest month is \RsQRankObserved\ instead of \RsQRankGold. Extending completeness checks to the auxiliary filter columns \code{l\_shipdate} and \code{l\_commitdate}, alongside the primary date key \code{l\_receiptdate}, would detect this failure. In the concurrent grain-breaking stress test, same-snapshot validation prevents unsafe execution; precheck-then-execute admits up to \SnPreUnannMax\% unsafe queries.}
{三次结构变化情形下的错误均来自同一个 TPC-H Q12 定义。其期间使用 \code{l\_receiptdate}，过滤却比较 \code{l\_shipdate < l\_commitdate}。日期键变化追加了 \code{l\_shipdate} 为空的行；收货日期的覆盖检查仍通过，但 SQL 的空值比较排除了这些行。九月总量为 \RsQSingleObserved\ 而非 \RsQSingleGold，跨期差值为 \RsQDiffObserved\ 而非 \RsQDiffGold，最高月为 \RsQRankObserved\ 而非 \RsQRankGold。在主日期键 \code{l\_receiptdate} 之外，将完整性检查扩展至辅助过滤列 \code{l\_shipdate} 与 \code{l\_commitdate}，即可检测这一失效情形。在破坏粒度的并发压力测试中，同快照验证阻止不安全执行；先检查后执行最多有 \SnPreUnannMax\% 的查询使用失效数据。}
