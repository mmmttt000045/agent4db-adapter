\subsection{\bt{Amortizing validation and maintenance}{分摊验证与维护开销}}
\label{sec:cost}
\label{sec:opt-eval}
\bi{\emph{Maintenance once, not per agent (Q3).} After the population study's restatement, \system\ repairs each affected definition once, using \PpMavraMaintS\,s of database time per run; private memory repairs per-agent copies in \PpPrivateMaintS\,s. End-to-end maintenance costs \AmMaintBenignS\,s per non-breaking update and \AmMaintRepairS\,s per repaired change. Discarding knowledge on every write costs \ScenRelearnTok\,M relearning tokens per run.}
{\emph{维护只做一次，而不是每个智能体一次（Q3）。}群体实验的数据更正后，\system\ 对每个受影响定义只修复一次，每次运行用 \PpMavraMaintS\ 秒数据库时间；私有记忆逐智能体修复副本，需 \PpPrivateMaintS\ 秒。端到端维护每次正常更新需 \AmMaintBenignS\ 秒、每次修复变化需 \AmMaintRepairS\ 秒。每次写入都丢弃知识，则每次运行需 \ScenRelearnTok\,M token 重新学习。}

\bi{\emph{One optimization speeds up every agent.} We evaluate an optimization pass over the \OptDefs\ learned definitions on the one-million-row retail workload. \OptPublished\ of the \OptDefs\ published definitions received a key-range revision that reduced query execution time by \OptSaveMin--\OptSaveMax\% relative to the previous revision (mean \OptSaveMean\%). For every candidate, the 95\% confidence interval for the mean paired execution-time difference, candidate minus previous revision, lies entirely below zero. Each revision matches its previous revision on \OptPeriods\ periods. Agents reuse the retrieved SQL, so \OptHoldAdopted\ of the \OptHoldTasks\ held-out queries ran the faster form.}
{\emph{一次优化让每个智能体都更快。}我们在 100 万行销售的零售负载上，针对学得的 \OptDefs\ 个定义评估一轮优化。已发布的 \OptDefs\ 个定义中有 \OptPublished\ 个得到键区间版本，相对前一版本使查询执行耗时减少 \OptSaveMin--\OptSaveMax\%（平均减少 \OptSaveMean\%）。对每个候选，配对执行时间差（候选减前一版本）均值的 95\% 置信区间均整体低于零。各版本在 \OptPeriods\ 个期间上均与前一版本返回相同结果。由于智能体复用检索到的 SQL，\OptHoldTasks\ 条留出查询中有 \OptHoldAdopted\ 条用了更快的写法。}

\bi{A separate system-level test published and optimized \PbDefs\ definitions (store revenue, return amount, return rate, and electronics revenue), then re-keyed one month of the date dimension so that only date-key contiguity failed. Maintenance invalidated all \PbDefs\ key-range revisions in this test and restored their previous revisions within \PbFallbackMsMax\,ms each. All \PbAnswers\ answers served afterwards were correct, whereas the key-range SQL would have been wrong by up to \PbStaleErrMax\%.}
{另一项独立的系统层测试发布并优化 \PbDefs\ 个定义（门店营业额、退货金额、退货率与电子品类营业额），随后给日期维度的一个月重新编键，使日期键连续性成为唯一失效的条件。维护使该测试中全部 \PbDefs\ 个键区间版本失效，并在不超过 \PbFallbackMsMax\ 毫秒内恢复各自的前一版本。此后返回的 \PbAnswers\ 个答案全部正确，而键区间 SQL 的误差会高达 \PbStaleErrMax\%。}
