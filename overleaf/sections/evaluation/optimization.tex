\subsection{\bt{Optimization revisions}{优化修订}}
\label{sec:opt-eval}
\bi{\emph{Setup (Q7).} We add one optimization sweep to the end-to-end protocol of Section~\ref{sec:scenarios}, with its first three scored question types, after learning and before the held-out questions, at one million sales rows, and run it once. \emph{Result.} \OptPublished\ of the \OptDefs\ published definitions of the five metrics received a faster revision, each from the key-range rule, so the LLM path was not needed. Their canonical SQL ran \OptSaveMin--\OptSaveMax\% faster (mean \OptSaveMean\%, every 95\% interval below zero; \AmOptSaveMinMs--\AmOptSaveMaxMs\,ms per execution, by any consumer), with equal results on \OptPeriods\ periods per definition and as of learning time. Consumers adopted the new form: \OptHoldAdopted\ of the \OptHoldTasks\ held-out queries used the key-range predicate of the revision they retrieved. Over the held-out questions and the eleven changes, agents answer \OptAcc\ of \OptTasks\ questions, against \OptBaseAcc\ of \OptBaseTasks\ in a run of the same configuration without the sweep; the per-change differences are within the variation between runs. Under late-arriving date keys, date-key completeness invalidates the key-range revisions exactly as it invalidates the join form.}
{\emph{设置（Q7）。}我们在第~\ref{sec:scenarios} 节的端到端流程（取其前三种计分题型）中加入一轮优化，位于学习之后、留出题之前，数据为 100 万行门店销售，运行一次。\emph{结果。}五个指标的 \OptDefs\ 条已发布定义中有 \OptPublished\ 条得到更快的修订，均来自日期键范围规则，因此不需要大模型提议。它们的规范 SQL 快了 \OptSaveMin\%--\OptSaveMax\%（平均 \OptSaveMean\%，95\% 区间全部低于 0；任何使用者每次执行节省 \AmOptSaveMinMs--\AmOptSaveMaxMs\ 毫秒），每条定义在 \OptPeriods\ 个期间上以及按学习时刻结果相同。使用者采用了新写法：\OptHoldTasks\ 条留出题查询中有 \OptHoldAdopted\ 条使用了所检索修订中的日期键范围谓词。在留出题与 11 种变化上，智能体答对 \OptTasks\ 道中的 \OptAcc\ 道，同一配置不做优化的一次运行为 \OptBaseTasks\ 道中的 \OptBaseAcc\ 道，各变化上的差异在运行间的波动范围内。在迟到日期键下，日期键完整性使日期键范围修订失效，与它使连接写法失效完全一样。}

\bi{\emph{Breaking the added premise.} On one million sales rows, a system-level test seeds store revenue, return amount, return rate, and electronics revenue, publishes key-range revisions for all \PbDefs, and then reloads the date dimension so that one month's dates receive new surrogate keys above the largest key, re-pointing the fact tables: every key still exists, joins stay unique, completeness is unchanged, and only contiguity fails. Maintenance invalidated the \PbDefs\ key-range revisions on that premise and reinstated their join-form predecessors, in at most \PbFallbackMsMax\,ms per definition, and all \PbAnswers\ answers served afterwards are correct, whereas the key-range SQL would have answered the quarter and the half-year wrongly for every definition, by up to \PbStaleErrMax\%. The same test confirms that a later premise break undoes the rule for a revision repaired since, and that join completeness invalidates electronics revenue when the test makes \PbOrphanNow\% of sales reference no item, against none at admission.}
{\emph{破坏新增的前提。}一个系统层测试在 100 万行销售数据上放入门店营业额、退货金额、退货率和电子品类营业额，四个定义都得到日期键范围修订；随后重新装载日期维度，一个月的日期换成大于最大键的新代理键，事实表改指向新键：所有键仍然存在，连接仍然唯一，完整性不变，只有日期键连续不再成立。维护使 \PbDefs\ 个日期键范围修订因这一前提失效，并恢复它们连接日期维度的前一修订，每个定义最多用时 \PbFallbackMsMax\ 毫秒；此后给出的 \PbAnswers\ 个答案全部正确，而日期键范围 SQL 会在每个定义的季度和半年上答错，误差最大 \PbStaleErrMax\%。同一测试还确认：对此后经过修复的修订，前提被破坏时撤销改写规则；测试使 \PbOrphanNow\% 的销售引用不存在的商品（准入时为零）时，连接完整性使电子品类营业额失效。}
