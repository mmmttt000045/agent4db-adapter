\bi{\emph{Protocol (Q1).} \PpAgents\ agents arrive one after another at the TPC-DS database, and each asks seven questions drawn at random from the 35 of its workload, so most agents meet a metric only once or twice. Five metrics come from the benchmark's query templates (store sales of the items of one category manager, store sales to registered customers, coupon amount at mid-sized stores, store returns at known stores, and the benchmark's yearly-total measure); each has two learning questions, which state the business definition, and five questions that give only the metric name: a new period, a period difference, the highest month, the largest rise, and the months above the monthly mean. Within a run every method gets the same draw. The memory starts empty and learns from use: when a session answers a learning question correctly without reusing a definition, \system\ extracts a candidate and publishes it after the publication checks. Without memory, an agent starts every question from scratch, including the table descriptions and join paths it looks up. \emph{Single-agent memory} runs exactly \system's learning, checks, and maintenance, but each agent sees only the definitions it learned and the table descriptions and join paths it looked up itself, as in current agent memory systems. Agents and extractor use DeepSeek V4.1 Flash with high reasoning effort, a 20-turn limit, and a 120\,s SQL timeout; reference queries compiled from the templates compute the reference answers. Each method runs \PpRuns\ times over \PpSessions\ sessions in all; a session's tokens include the extraction it triggered, and agent time runs from an agent's first call to its final answer.}
{\emph{设置（Q1）。}\PpAgents\ 个智能体依次来到 TPC-DS 数据库，每个从其负载的 35 道题中随机抽 7 道作答，因此大多数智能体只遇到某个指标一两次。5 个指标取自该基准的查询模板（一位品类经理所管商品的门店销售额、登记顾客的门店销售额、中型门店的优惠券金额、关联得上门店的门店退货金额，以及该基准的年度汇总口径）；每个指标有 2 道给出业务定义的学习题，以及 5 道只给指标名的题：新的期间、跨期差值、最高月、增幅最大的月、高于月平均值的月份。同一次运行中各方法抽到的题相同。记忆从空开始、边用边学：若一个会话答对了学习题、且没有复用已有定义，\system\ 提取候选并在发布前检查之后发布。没有记忆的智能体每道题都从头开始，查过的表描述和连接路径也不保留。\emph{单智能体记忆}完全照搬 \system\ 的学习、检查与维护，但每个智能体只看得到自己学到的定义和自己查过的表描述与连接路径，与现有智能体记忆系统相同。智能体与提取器使用 DeepSeek V4.1 Flash，推理强度为高，最多 20 轮，SQL 超时 120 秒；由模板编译出的参考查询算出参考答案。每种方法运行 \PpRuns\ 次，共 \PpSessions\ 个会话；会话的 token 包括它触发的提取，智能体时间从智能体的第一次调用计到给出最终答案。}

\bi{\emph{What sharing saves.} Figure~\ref{fig:population} shows the total cost as agents arrive. Over \PpAgents\ agents, \system\ spends \PpMavraTotalTokM\,M tokens, \PpMavraTokSaveNone\% fewer than agents without memory (\PpNoneTotalTokM\,M; \PpMavraTokSaveNoneMin--\PpMavraTokSaveNoneMax\% per run), and its agents finish \PpMavraSpeedupNone$\times$ faster, while answering \PpMavraAcc\% of the questions correctly against \PpNoneAcc\%. The saving grows with every agent that arrives: \PpMavraTokSaveNoneNFour\% of the tokens and \PpMavraSpeedupNoneNFour$\times$ in time after four agents, \PpMavraTokSaveNoneNEight\% and \PpMavraSpeedupNoneNEight$\times$ after eight, \PpMavraTokSaveNone\% and \PpMavraSpeedupNone$\times$ after \PpAgents. As the cost model of Section~\ref{sec:alternatives} predicts, it approaches $1-c_r/c_e$, \PpMavraAsymTokSaveNone\% of the tokens, as more agents reuse what the first ones learned. The first sessions that meet a metric explore and publish, \PpMavraLearns\ extractions per run for the five metrics, and from then on agents reuse: \PpMavraReused\% of all questions run a shared definition. Table~\ref{tab:popcost} shows where a reusing agent saves. It answers with \PpMavraLateSteps\ LLM calls and \PpMavraLateTools\ tool calls instead of \PpNoneLateSteps\ and \PpNoneLateTools, because the definition replaces listing tables, probing values, and testing joins; every LLM call it saves is one whose growing context it no longer pays for, so tokens fall \PpMavraLateTokXNone$\times$ and time \PpMavraLateSpeedupNone$\times$, and database time falls from \PpNoneLateDbS\ to \PpMavraLateDbS\,s per question as the probes disappear. LLM calls are what matter: in a separate study of \SlSessions\ sessions, LLM calls take \SlWarmLLMMin--\SlWarmLLMMax\% of the agent time of sessions that use shared memory, so every call saved is time saved.}
{\emph{共享省下了什么。}图~\ref{fig:population} 给出智能体陆续到来时的累计代价。\PpAgents\ 个智能体下来，\system\ 共用 \PpMavraTotalTokM\,M token，比无记忆的智能体（\PpNoneTotalTokM\,M）少 \PpMavraTokSaveNone\%（每次运行 \PpMavraTokSaveNoneMin--\PpMavraTokSaveNoneMax\%），其智能体快 \PpMavraSpeedupNone\ 倍，同时答对 \PpMavraAcc\% 的问题，无记忆为 \PpNoneAcc\%。节省随每个新到的智能体增长：4 个智能体后省下 \PpMavraTokSaveNoneNFour\% 的 token、快 \PpMavraSpeedupNoneNFour\ 倍，8 个后为 \PpMavraTokSaveNoneNEight\% 与 \PpMavraSpeedupNoneNEight\ 倍，\PpAgents\ 个后为 \PpMavraTokSaveNone\% 与 \PpMavraSpeedupNone\ 倍。正如第~\ref{sec:alternatives} 节的代价模型所预测，随着更多智能体复用最先到来者学到的东西，节省趋近 $1-c_r/c_e$，即 \PpMavraAsymTokSaveNone\% 的 token。最先遇到某个指标的会话探索并发布，每次运行为五个指标一共提取 \PpMavraLearns\ 次；此后智能体都复用：\PpMavraReused\% 的问题执行共享的定义。表~\ref{tab:popcost} 给出复用记忆的智能体省在哪里。它每题只需 \PpMavraLateSteps\ 次大模型调用、\PpMavraLateTools\ 次工具调用，而不是 \PpNoneLateSteps\ 次、\PpNoneLateTools\ 次，因为定义取代了列表、探查取值和检验连接；省下的每一次都是一次上下文不断变长的大模型调用，因此 token 少 \PpMavraLateTokXNone\ 倍、时间快 \PpMavraLateSpeedupNone\ 倍；探查消失之后，数据库时间也从每题 \PpNoneLateDbS\ 秒降到 \PpMavraLateDbS\ 秒。关键在于大模型调用次数：另一项对 \SlSessions\ 个会话的研究中，在使用共享记忆的会话里，大模型调用占智能体时间的 \SlWarmLLMMin--\SlWarmLLMMax\%，因此省下的每一次调用都是省下的时间。}


\bi{\emph{Why memory must be shared.} Single-agent memory extracts \PpPrivateLearns\ times per run, every agent learning for itself, yet reuses on only \PpPrivateReused\% of the questions, because an agent that learned a metric seldom asks about it again. Every agent pays for learning and few get the reuse: over \PpAgents\ agents it spends \PpPrivateTotalTokM\,M tokens, and \system\ uses \PpMavraTokSavePrivate\% fewer and is \PpMavraSpeedupPrivate$\times$ faster; its late agents still spend \PpPrivateLateTokK\,k tokens per question.}
{\emph{为什么记忆必须共享。}单智能体记忆每次运行提取 \PpPrivateLearns\ 次，每个智能体都为自己学习，却只在 \PpPrivateReused\% 的问题上复用，因为学会某个指标的智能体很少再问它。每个智能体都为学习付出代价，得到复用的却很少：\PpAgents\ 个智能体共用 \PpPrivateTotalTokM\,M token，\system\ 比它少 \PpMavraTokSavePrivate\%、快 \PpMavraSpeedupPrivate\ 倍；它后来的智能体每题仍要 \PpPrivateLateTokK\,k token。}
