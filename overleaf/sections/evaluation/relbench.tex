\subsection{\bt{Published memories on a public benchmark}{公开基准上与已发表记忆方法的比较}}
\label{sec:relbench-eval}
\bi{\emph{Benchmark and timeline.} We use two databases of RelBench~\cite{robinson2024relbench}: rel-stack (seven tables of a Stack Exchange site; tasks user-engagement, user-badge, post-votes) and rel-trial (fifteen tables of clinical trials; study-outcome, study-adverse, site-success), with RelBench's own task definitions and metrics. We run the setting that makes memory matter, periodic retraining: five cutoffs per database, the last one RelBench's official split, each earlier one moved back by the task's window, with labels regenerated by RelBench's code (those of the last cutoff equal the official tables row by row). Between cutoffs, the rows of the next period are appended to the database. Each task has its own agent, which starts a new session at every cutoff, so a memory can help an agent across cutoffs (its own task, newer data) and across tasks (other agents on the same database).}
{\emph{基准与时间线。} 我们使用 RelBench~\cite{robinson2024relbench} 的两个数据库：rel-stack（一个 Stack Exchange 站点的 7 张表；任务 user-engagement、user-badge、post-votes）与 rel-trial（临床试验的 15 张表；study-outcome、study-adverse、site-success），任务定义与指标均取自 RelBench。我们采用让记忆起作用的设置，即定期重训：每个库 5 个截点，最后一个是 RelBench 的官方划分，之前的每个依次前移一个任务窗口，标签由 RelBench 自己的代码重新生成（最后一个截点的标签与官方表逐行一致）。截点之间把下一期的行追加进数据库。每个任务有自己的智能体，每个截点开始一个新会话，因此记忆既能跨截点帮助一个智能体（同一任务、更新的数据），也能跨任务帮助其他智能体（同一数据库）。}
\bi{\emph{Sessions.} Every method uses the same agent: DeepSeek-V4.1-Flash through DeepSeek's API in thinking mode with low effort, the same model for every memory operation, and the same tools (schema, joins, read-only SQL, \code{validate\_features}, \code{submit}). Feature SQL returns one row per seed and may use only rows dated at or before the seed time; \code{validate\_features} trains a fixed LightGBM~\cite{ke2017lightgbm} on a 50,000-seed training sample and returns the validation score. A session ends after 40 LLM calls, 8 validations, or 2 validations in a row without improvement. From the second cutoff on it also ends once the validation score reaches the goal that a team retraining a model would use, the previous cutoff's model refit on the new data, after one more attempt to improve within 5 LLM calls. Every validation is audited for leakage on 5,000 seeds by recomputing the features on views that hide later rows; leaking validations do not count, and leaking submissions are refused. Test labels are never seen by an agent or a memory.}
{\emph{会话。} 所有方法使用同一个智能体：DeepSeek 官方 API 上的 DeepSeek-V4.1-Flash，思考模式、低强度；每个记忆操作也用同一模型；工具相同（看结构、连接、只读 SQL、\code{validate\_features}、\code{submit}）。特征 SQL 对每个种子返回一行，且只能使用时间不晚于种子时间的行；\code{validate\_features} 在 5 万个训练种子的抽样上训练固定的 LightGBM~\cite{ke2017lightgbm} 并返回验证分数。会话在 40 次 LLM 调用、8 次验证或连续 2 次验证没有提升时结束。从第二个截点起，验证分数达到重训模型的团队会用的目标（上一截点的模型在新数据上重新拟合的分数）时也结束，结束前还可在 5 次 LLM 调用内再尝试改进一次。每次验证都在 5,000 个种子上做泄漏审计：在隐去更晚行的视图上重算特征；泄漏的验证不计分，泄漏的提交被拒绝。任何智能体或记忆都看不到测试标签。}
\bi{\emph{Baselines.} We compare with four published memories, each in the scope its paper defines, with official prompts and code where they exist: AgentSM~\cite{biswal2026agentsm} (preprint), a read-only memory per database built offline from synthesized tasks (100 in total, split by the databases' share of sessions), whose planner retrieves the trajectory of the most similar task, with its schema-linking agent, composite tools, and SQL repair; ACE~\cite{zhang2026ace}, one playbook per agent updated after each session by its official reflector and curator without ground truth; G-Memory~\cite{zhang2025gmemory}, its official code, one memory shared by all agents of a database; and AWM~\cite{wang2025awm}, one workflow memory per agent, induced again after every session from its successful sessions with the official prompt. A method that needs a success signal uses the same one, a validation score better than the entity-table reference. The no-memory agent is the same agent without any memory. The reproduction notes of our artifact list every adaptation.}
{\emph{基线。} 我们与四个已发表的记忆方法比较，每个都按其论文规定的范围使用，有官方提示词与代码的都直接使用：AgentSM~\cite{biswal2026agentsm}（预印本），每个库一份离线建好、评估时只读的记忆，由合成任务构建（总数 100，按各库会话数的比例分配），规划智能体检索最相似任务的轨迹，并带有其模式链接智能体、组合工具与 SQL 修复；ACE~\cite{zhang2026ace}，每个智能体一本手册，每次会话后由官方的反思者与整理者在无真实标签的设置下更新；G-Memory~\cite{zhang2025gmemory}，使用官方代码，一个库的所有智能体共用一份记忆；AWM~\cite{wang2025awm}，每个智能体一份工作流记忆，每次会话后用官方提示词从其成功的会话重新归纳。需要成功信号的方法统一使用“验证分数优于实体表参照”。无记忆组是不带任何记忆的同一个智能体。所有改动逐条列在本文工件的复现说明中。}
\bi{\emph{The workload.} These sessions are agent work, not one-shot text-to-SQL: without memory, a session takes a median of \RbNoneMedLlm\ LLM calls and \RbNoneMedTok\,k tokens, \RbSchemaProbe\% of its tool calls inspect the schema or probe values, and \RbSchemaRepeat\% of the schema calls in later sessions repeat a call that an earlier session on the same database already made.}
{\emph{工作负载。} 这些会话是智能体的工作，而不是一次性的 Text-to-SQL：没有记忆时，一个会话的 LLM 调用中位数为 \RbNoneMedLlm\ 次、token 中位数为 \RbNoneMedTok\,k，\RbSchemaProbe\% 的工具调用在看结构或探查取值，后续会话里 \RbSchemaRepeat\% 的看结构调用重复了同一数据库上更早会话已做过的调用。}

\bi{\emph{Results.} Table~\ref{tab:relbench} shows the totals. From the second cutoff on, \system\ uses \RbStackMavraTokSave\% fewer tokens than agents without memory on rel-stack and \RbTrialMavraTokSave\% fewer on rel-trial, and its agents finish \RbStackMavraSpeed$\times$ and \RbTrialMavraSpeed$\times$ faster. Counting the first cutoff too, where its agents explore like the others and also pay for learning, \system\ still uses \RbStackMavraTokSaveAll\% and \RbTrialMavraTokSaveAll\% fewer tokens than no memory over all sessions.}
{\emph{结果。} 表~\ref{tab:relbench} 给出合计。从第二个截点起，\system\ 在 rel-stack 上比无记忆的智能体少用 \RbStackMavraTokSave\% 的 token，在 rel-trial 上少用 \RbTrialMavraTokSave\%，其智能体分别快 \RbStackMavraSpeed\ 倍与 \RbTrialMavraSpeed\ 倍。与用 token 最少的已发表记忆相比，\system\ 在 rel-stack 上少用 \RbStackMavraVsBest\%，在 rel-trial 上少用 \RbTrialMavraVsBest\%。把第一个截点也算上（此时它的智能体与其他智能体一样要探索，还要为学习付出代价），\system\ 在全部会话上仍比无记忆少用 \RbStackMavraTokSaveAll\% 与 \RbTrialMavraTokSaveAll\% 的 token。}
\bi{\emph{Where the savings come from.} An agent of \system\ starts from its task's program: the complete SQL of the last successful session, checked to run on the new snapshot, reaches the goal at its first validation, and the agent spends its remaining attempt on one improvement. Per session from the second cutoff on, \system's agents make \RbStackMavraExplore\ schema and probe calls on rel-stack, while agents without memory make \RbStackNoneExplore. The other memories hand the agent text about earlier work, namely a playbook (ACE: \RbStackACEExplore), workflows (AWM: \RbStackAWMExplore), or trajectories (AgentSM: \RbStackAgentSMExplore; G-Memory: \RbStackGMemExplore), which the agent still turns into SQL over tables it inspects again.}
{\emph{节省从哪里来。} \system\ 的智能体从本任务的方案出发：上一次成功会话的完整 SQL 在新快照上确认能执行后，第一次验证就达到目标，智能体把剩下的一次尝试用于改进。从第二个截点起，\system\ 的智能体在 rel-stack 上每会话做 \RbStackMavraExplore\ 次看结构与探查调用，无记忆的智能体做 \RbStackNoneExplore\ 次。其他记忆交给智能体的是关于以往工作的文本，即手册（ACE：\RbStackACEExplore\ 次）、工作流（AWM：\RbStackAWMExplore\ 次）或轨迹（AgentSM：\RbStackAgentSMExplore\ 次；G-Memory：\RbStackGMemExplore\ 次），智能体仍要在重新查看的表上把它们变成 SQL。}
