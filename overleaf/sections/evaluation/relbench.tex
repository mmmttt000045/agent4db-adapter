\subsection{\bt{End-to-End Feature Reuse on RelBench}{RelBench 上的端到端特征复用}}
\label{sec:relbench-eval}
\bi{Reusing validated features reduces repeated exploration during retraining while preserving predictive quality across all six RelBench tasks. From the second cutoff onward, \system\ uses \RbStackMavraTokSave\% fewer tokens on rel-stack and \RbTrialMavraTokSave\% fewer on rel-trial than agents without memory.}
{复用已验证特征减少了重训时的重复探索，同时在 RelBench 的全部六项任务上保持预测质量。从第二个截点起，\system\ 相对无记忆智能体在 rel-stack 上少用 \RbStackMavraTokSave\% 的 token，在 rel-trial 上少用 \RbTrialMavraTokSave\%。}
\bi{\emph{Benchmark and timeline.} We use two databases of RelBench~\cite{robinson2024relbench}: rel-stack (seven tables of a Stack Exchange site; tasks user-engagement, user-badge, post-votes) and rel-trial (fifteen tables of clinical trials; study-outcome, study-adverse, site-success), with RelBench's own task definitions and metrics. We evaluate periodic retraining: five cutoffs per database, the last one RelBench's official split, each earlier one moved back by the task's window, with labels regenerated by RelBench's code (those of the last cutoff equal the official tables row by row). Between cutoffs, the rows of the next period are appended to the database. Each task has its own agent, which starts a new session at every cutoff, so a memory can help an agent across cutoffs (its own task, newer data) and across tasks (other agents on the same database).}
{\emph{基准与时间线。} 我们使用 RelBench~\cite{robinson2024relbench} 的两个数据库：rel-stack（一个 Stack Exchange 站点的 7 张表；任务 user-engagement、user-badge、post-votes）与 rel-trial（临床试验的 15 张表；study-outcome、study-adverse、site-success），任务定义与指标均取自 RelBench。我们评估定期重训：每个库 5 个截点，最后一个是 RelBench 的官方划分，之前的每个依次前移一个任务窗口，标签由 RelBench 自己的代码重新生成（最后一个截点的标签与官方表逐行一致）。截点之间把下一期的行追加进数据库。每个任务有自己的智能体，每个截点开始一个新会话，因此记忆既能跨截点帮助一个智能体（同一任务、更新的数据），也能跨任务帮助其他智能体（同一数据库）。}
\bi{\emph{Sessions.} The no-memory and four memory arms use the same agent: \llmmodel{} through DeepSeek's API in thinking mode with low effort, the same model for memory operations under their documented inference settings, and the same tools (schema, joins, read-only SQL, \code{validate\_features}, \code{submit}). Feature SQL returns one row per seed, may use only rows dated at or before the seed time, and runs for at most 600\,s; \code{validate\_features} trains a fixed LightGBM~\cite{ke2017lightgbm} on a 50,000-seed training sample and returns the validation score. A session ends after 40 LLM calls, 8 validations, or 2 validations in a row without improvement. From the second cutoff on, the previous cutoff's model is refit on the new data to set a validation-score target. Once the agent reaches that target, it has one further improvement attempt within 5 LLM calls before the session ends. Every validation is audited for leakage on 5,000 seeds by recomputing the features on views that hide later rows; leaking validations do not count, and leaking submissions are refused. Test labels are never seen by an agent or a memory. A session that ends without a valid solution is scored as the entity-table reference.}
{\emph{会话。} 无记忆组与四个记忆方法使用同一个智能体：DeepSeek 官方 API 上的 \llmmodel{}，思考模式、低强度；记忆操作也用同一模型，推理设置见复现说明；工具相同（看结构、连接、只读 SQL、\code{validate\_features}、\code{submit}）。特征 SQL 对每个种子返回一行，只能使用时间不晚于种子时间的行，每次最多运行 600\,s；\code{validate\_features} 在 5 万个训练种子的抽样上训练固定的 LightGBM~\cite{ke2017lightgbm} 并返回验证分数。会话在 40 次 LLM 调用、8 次验证或连续 2 次验证没有提升时结束。从第二个截点起，以上一截点模型在新数据上重新拟合的验证分数为目标。达到目标后，智能体可在 5 次 LLM 调用内再尝试改进一次，随后结束会话。每次验证都在 5,000 个种子上做泄漏审计：在隐去更晚行的视图上重算特征；泄漏的验证不计分，泄漏的提交被拒绝。任何智能体或记忆都看不到测试标签。没有得到有效方案的会话按实体表参照计分。}
\bi{\emph{Baselines.} We compare with five published methods, using official prompts and code where available. Three are agent memories: ACE~\cite{zhang2026ace}, one playbook per agent updated after each session by its official reflector and curator without ground truth; G-Memory~\cite{zhang2025gmemory}, its official code, one memory shared by all agents of a database; and AWM~\cite{wang2025awm}, one workflow memory per agent, induced again after every session from its successful sessions with the official prompt. Two are data-preparation systems of the database community, which search for each task anew: DeepPrep~\cite{fan2026deepprep}, an LLM agent whose official code explores operator pipelines as a tree with execution feedback (its reasoning loop, prompts, operators, and executor run unchanged on the task's tables with the study's model; it explores on 2,000 seeds, and its solution then runs on all seeds within the same 600\,s per split), and FeatPilot~\cite{liang2025featpilot}, which searches join paths for the features that most improve the model without an LLM (our implementation follows the paper, with every aggregate bounded by the seed time). A method that needs a success signal uses the same one, a validation score better than the entity-table reference. The no-memory agent is the same agent without any memory. Implementation configurations and reproduction instructions are provided in the artifact.}
{\emph{基线。} 我们与五个已发表的方法比较，并在有官方提示词与代码时直接使用。其中三个是智能体记忆：ACE~\cite{zhang2026ace}，每个智能体一本手册，每次会话后由官方的反思者与整理者在无真实标签的设置下更新；G-Memory~\cite{zhang2025gmemory}，使用官方代码，一个库的所有智能体共用一份记忆；AWM~\cite{wang2025awm}，每个智能体一份工作流记忆，每次会话后用官方提示词从其成功的会话重新归纳。另外两个是数据库领域的数据准备系统，每个任务都重新搜索：DeepPrep~\cite{fan2026deepprep}，一个 LLM 智能体，其官方代码以树的形式在执行反馈下探索算子流水线（它的推理循环、提示词、算子与执行器原样运行在任务的表上，使用本研究的模型；它在 2,000 个种子上探索，方案随后在全部种子上运行，每个划分同样最多 600\,s）；FeatPilot~\cite{liang2025featpilot}，不用 LLM，搜索对模型提升最大的连接路径特征（我们按论文实现，每个聚合都受种子时间约束）。需要成功信号的方法统一使用“验证分数优于实体表参照”。无记忆组是不带任何记忆的同一个智能体。实现配置与复现步骤见随文工件。}
\bi{\emph{The workload.} Without memory, a session takes a median of \RbNoneMedLlm\ LLM calls and \RbNoneMedTok\,k tokens, \RbSchemaProbe\% of its tool calls inspect the schema or probe values, and \RbSchemaRepeat\% of the schema calls in later sessions repeat a call that an earlier session on the same database already made.}
{\emph{工作负载。} 没有记忆时，一个会话的 LLM 调用中位数为 \RbNoneMedLlm\ 次、token 中位数为 \RbNoneMedTok\,k，\RbSchemaProbe\% 的工具调用在看结构或探查取值，后续会话里 \RbSchemaRepeat\% 的看结构调用重复了同一数据库上更早会话已做过的调用。}

\bi{\emph{Results.} Table~\ref{tab:relbench} reports reuse costs, per-task test scores, valid-session counts, and tasks retaining baseline predictive quality; Figure~\ref{fig:relbench-cumulative} shows how token costs accumulate. The smaller USD reduction reflects token mix: on rel-stack, cached input falls from 86\% to 67\% of tokens and output rises from 11\% to 15\%; most avoided tokens are inexpensive cached input. Against the agent memory that uses the fewest tokens, \system\ uses \RbStackMavraVsBest\% fewer tokens on rel-stack and \RbTrialMavraVsBest\% fewer on rel-trial. Counting the first cutoff too, where its agents explore like the others and also pay for learning, \system\ still uses \RbStackMavraTokSaveAll\% and \RbTrialMavraTokSaveAll\% fewer tokens than no memory over all sessions. \system\ preserves predictive quality across all six tasks: \RbStackMavraNotWorse/3 on rel-stack and \RbTrialMavraNotWorse/3 on rel-trial meet the evaluation criteria, $\mathrm{AUC}\geq\mathrm{AUC}_0-0.01$ or $\mathrm{MAE}\leq 1.02\,\mathrm{MAE}_0$, where subscript 0 denotes the no-memory baseline.}
{\emph{结果。} 表~\ref{tab:relbench} 报告复用代价、各任务测试分数、有效会话数与保持基线预测质量的任务数；图~\ref{fig:relbench-cumulative} 展示 token 代价如何累积。美元降幅较小源于 token 构成变化：rel-stack 上缓存命中输入占比从 86\% 降至 67\%，输出占比从 11\% 升至 15\%；省下的 token 主要是价格较低的缓存命中输入。与用 token 最少的智能体记忆相比，\system\ 在 rel-stack 上少用 \RbStackMavraVsBest\%，在 rel-trial 上少用 \RbTrialMavraVsBest\%。把第一个截点也算上（此时它的智能体与其他智能体一样要探索，还要为学习付出代价），\system\ 在全部会话上仍比无记忆少用 \RbStackMavraTokSaveAll\% 与 \RbTrialMavraTokSaveAll\% 的 token。\system\ 在全部六项任务上保持预测质量：rel-stack 上的 \RbStackMavraNotWorse/3 项与 rel-trial 上的 \RbTrialMavraNotWorse/3 项均满足评估标准，即 $\mathrm{AUC}\geq\mathrm{AUC}_0-0.01$ 或 $\mathrm{MAE}\leq 1.02\,\mathrm{MAE}_0$，下标 0 表示无记忆基线。}
\bi{\emph{Session outcomes and measurement.} DeepPrep produces no valid solution in \RbStackDeepPrepUnsolved/15 sessions on rel-stack and \RbTrialDeepPrepUnsolved/15 on rel-trial; these receive the reference score. Eleven failures occur when executing the final pipeline on the full seed split exceeds 600\,s (five on rel-stack, six on rel-trial); two rel-stack searches terminate after exceeding the official five-error limit. FeatPilot completes all sessions without LLM calls. The evaluation comprises 210 sessions: seven methods, two databases, and one five-cutoff sequence with three tasks per cutoff. Token volume and LLM/tool call counts are the primary efficiency measures. Table~\ref{tab:relbench} also reports end-to-end wall-clock durations (which include external LLM API latency); full execution and measurement details are documented in the artifact.}
{\emph{会话结果与测量。}DeepPrep 在 rel-stack 的 15 个会话中有 \RbStackDeepPrepUnsolved\ 个、在 rel-trial 中有 \RbTrialDeepPrepUnsolved\ 个没有有效方案，按参照计分。11 次失败是最终流水线在完整种子划分上执行超过 600 秒（rel-stack 5 次、rel-trial 6 次）；另 2 次 rel-stack 搜索因超过官方的五次报错上限而终止。FeatPilot 完成全部会话且不调用 LLM。评估共包含 210 个会话：7 个方法在 2 个数据库上各运行一条五截点序列，每个截点 3 个任务。主要效率指标为 token 用量及 LLM／工具调用数。表~\ref{tab:relbench} 同时报告端到端墙钟耗时（包含外部 LLM API 延迟）；完整的执行与测量细节见工件。}

\bi{\emph{Where the savings come from.} A \system\ agent retrieves its task's validated program alongside compiled entity-level feature definitions available from prior sessions on the same database. The complete program SQL provides an executable starting point, while the definitions support feature selection and refinement. Reuse typically reaches the target at the first validation, leaving the remaining budget for targeted improvement. These results evaluate the combined reuse path. Per session from the second cutoff on, \system's agents make \RbStackMavraExplore\ schema and probe calls on rel-stack, while agents without memory make \RbStackNoneExplore. The other memories hand the agent text about earlier work, namely a playbook (ACE: \RbStackACEExplore), workflows (AWM: \RbStackAWMExplore), or trajectories and insights (G-Memory: \RbStackGMemExplore), which the agent still turns into SQL over tables it inspects again; DeepPrep and FeatPilot keep nothing and search every task and cutoff from the start.}
{\emph{节省从哪里来。} \system\ 的智能体同时检索本任务经过验证的方案，以及同库此前会话提供的、已编译的实体级特征定义。完整方案 SQL 提供可直接执行的起点，特征定义支持特征选择与改进。复用通常在首次验证即达到目标，将剩余预算用于有针对性的改进。这些结果评估两类对象共同提供的复用途径。从第二个截点起，\system\ 的智能体在 rel-stack 上每会话做 \RbStackMavraExplore\ 次看结构与探查调用，无记忆的智能体做 \RbStackNoneExplore\ 次。其他记忆交给智能体的是关于以往工作的文本，即手册（ACE：\RbStackACEExplore\ 次）、工作流（AWM：\RbStackAWMExplore\ 次）或轨迹与洞见（G-Memory：\RbStackGMemExplore\ 次），智能体仍要在重新查看的表上把它们变成 SQL；DeepPrep 与 FeatPilot 什么都不保留，每个任务、每个截点都从头搜索。}
