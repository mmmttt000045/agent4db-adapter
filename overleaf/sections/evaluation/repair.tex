\subsection{\bt{Repair and its boundary}{修复及其边界}}
\label{sec:repair-eval}
\bi{\emph{What the reference decides (Q3).} \system\ regression-tests a repair against the agent's own learning SQL, the reference a deployment is sure to have. Status-change rows leave the learning period untouched, and every affected definition is repaired (\RpStatusCond\ of \RpStatusN\ questions correct). Restatements and SCD Type 2 can also rewrite the learning period; where they do, the agent's SQL now counts the old versions, G8 refuses the fix, and the definition is invalidated rather than answering wrongly (\RpRevisionCond\ of \RpRevisionN\ and \RpDimhistCond\ of \RpDimhistN\ correct). The bottom bar of Figure~\ref{fig:replay} repeats \system\ with the benchmark's gold SQL, written knowing the status, version, and current-flag columns: it answers \RpPairGold\ instead of \RpPairCond\ of the \RpPairN\ questions correctly (\RpRefDiff\ points, 95\% cluster-bootstrap interval \RpRefLo--\RpRefHi), all in restatements (\RpRevisionGold\ of \RpRevisionN) and SCD Type 2 (\RpDimhistGold\ of \RpDimhistN), with \RpPairExtraWrong\ more wrong answers. The reference decides how much repair is automated, not whether wrong answers are served; end to end, the agent re-derives the filter after an invalidation and both configurations are equally accurate (Section~\ref{sec:scenarios}).}
{\emph{参照决定了什么（Q3）。}\system\ 以智能体自己的学习 SQL 对修复作回归测试，这是部署中一定有的参照。状态变更行不触及学习期，受影响的定义全部修复成功（\RpStatusN\ 道题中答对 \RpStatusCond\ 道）。多版本更正与缓慢变化维（类型 2）还可能改写学习期；在这些情况下，智能体的 SQL 如今会把旧版本也算进去，G8 拒绝修复，定义失效而不是提供错误答案（\RpRevisionN\ 道中答对 \RpRevisionCond\ 道，\RpDimhistN\ 道中答对 \RpDimhistCond\ 道）。图~\ref{fig:replay} 最下面一条以基准的标准答案 SQL 重复 \system，这些 SQL 编写时已知道状态、版本和当前标志列：\RpPairN\ 道题中它答对 \RpPairGold\ 道而不是 \RpPairCond\ 道（相差 \RpRefDiff\ 个百分点，按库整群自助 95\% 区间 \RpRefLo--\RpRefHi），差别全部来自多版本更正（\RpRevisionN\ 道中 \RpRevisionGold\ 道）与缓慢变化维（类型 2）（\RpDimhistN\ 道中 \RpDimhistGold\ 道），答错多出 \RpPairExtraWrong\ 道。因此参照决定的是修复有多少能自动完成，而不是会不会提供错误答案；端到端上，定义失效后智能体会自己重新推出过滤，两种配置的正确率相同（第~\ref{sec:scenarios} 节）。}

\bi{\emph{Ambiguous fixes.} The backup-copy change corrects some 2002 return amounts and appends a full backup copy of the returns table, marked by a source column, that keeps the old amounts. Filters on the primary source and on the backup source each restore one row per return without losing returns. Without the uniqueness rule, repair takes the first filter it finds, the backup. The agent's own SQL, which ignores the source column, rejects it, but a gold SQL that already filters on the primary source accepts it, and \system\ then publishes a revision that answers two of four new questions wrongly for both return metrics. With the uniqueness rule, repair finds both filters and invalidates the definitions under either reference. Rerunning the replay of \system\ with the rule changes none of the 3,000 outcomes under the two references, because the status-change, restatement, and SCD Type 2 fixes are unique.}
{\emph{有歧义的修复。}备份副本变化更正了部分 2002 年的退货金额，并追加一整份退货表的备份副本（以来源列标记），副本保留旧金额。按主数据来源过滤和按备份来源过滤，都能使每笔退货恰好一行且不丢退货。没有唯一性规则时，修复取搜索到的第一个过滤，即备份。不涉及来源列的智能体 SQL 会拒绝它，但预先按主数据来源过滤的标准答案 SQL 会接受它，于是 \system\ 发布的修订在两个退货指标的 4 道新题中都答错 2 道。有了唯一性规则，修复会找到两个过滤，在任一参照下都使定义失效。打开该规则后重新回放 \system，两种参照下共 3,000 道题的结果没有任何变化，因为状态变更行、多版本更正与缓慢变化维（类型 2）的修复都是唯一的。}

\bi{\emph{Availability during repair.} Rejecting requests that arrive while a repair runs makes \WrDefOff\ of \WrUses\ simultaneous uses (eight agents, 19 definitions, three runs at 200,000 rows) unavailable under definition-level and \WrCondOff\ under condition-level maintenance, where shared check results invalidate many definitions at once; coalescing them with the running repair removes all of them at the same total waiting time and database work.}
{\emph{修复期间的可用性。}若拒绝修复进行中到达的请求，同时到达的 \WrUses\ 次使用（8 个智能体、19 个定义、20 万行、3 轮）中，定义级维护有 \WrDefOff\ 次不可用，条件级维护有 \WrCondOff\ 次——共享的检查结果使许多定义同时失效；把这些请求与进行中的修复合并后，不可用全部消失，总等待时间与数据库工作量不变。}
