\subsection{\bt{Repair and its boundary}{修复及其边界}}
\label{sec:repair-eval}
\bi{\emph{Where G8 compares (Q3).} The agent's learning SQL is the reference a deployment has, but it was judged correct only on the learning snapshot, so \system\ runs it there together with the replacement. With this test \system\ repairs every affected definition under status-change rows (\RpCurStatusCond\ of \RpCurStatusN\ questions correct) and restatements (\RpCurRevisionCond\ of \RpCurRevisionN), and answers \RpCurDimhistCond\ of \RpCurDimhistN\ SCD Type 2 questions; the other three are invalidated under the gold SQL as well. The bottom bar of Figure~\ref{fig:replay} runs the same test on current data. Wherever a restatement or SCD Type 2 change touches the learning period, the agent's SQL is itself stale there, counting old versions or fanning out, so G8 refuses the correct fix: \RpCurPairOther\ instead of \RpCurPairCond\ of the \RpCurPairN\ questions are answered (\RpCurDiff\ points fewer, 95\% cluster-bootstrap interval \RpCurDiffLo--\RpCurDiffHi), the difference all in invalidated questions. A gold SQL that anticipates the distinguishing columns answers the same \RpGoldPairOther.}
{\emph{G8 在哪里比较（Q3）。}智能体的学习 SQL 是部署中有的参照，但它只在学习时快照上被判过对，所以 \system\ 在那里把它与替代修订一起执行。用这个测试，\system\ 在状态变更行（\RpCurStatusN\ 道题中答对 \RpCurStatusCond\ 道）与多版本更正（\RpCurRevisionN\ 道中 \RpCurRevisionCond\ 道）下修复了每一个受影响的定义，缓慢变化维（类型 2）的 \RpCurDimhistN\ 道题答对 \RpCurDimhistCond\ 道，其余 3 道在标准答案 SQL 下同样失效。图~\ref{fig:replay} 最下面一条在当前数据上做同样的测试。凡多版本更正或缓慢变化维（类型 2）触及学习期之处，智能体的 SQL 在当前数据上本身就过期了——把旧版本也算进去或连接放大——于是 G8 拒绝正确的修复：\RpCurPairN\ 道题中只答对 \RpCurPairOther\ 道而不是 \RpCurPairCond\ 道（少 \RpCurDiff\ 个百分点，按库整群自助 95\% 区间 \RpCurDiffLo--\RpCurDiffHi），差别全部是失效的题。预先写入区分列的标准答案 SQL 同样答对 \RpGoldPairOther\ 道。}

\bi{\emph{Ambiguous fixes.} The backup-copy change corrects some 2002 return amounts and appends a full backup copy of the returns table, marked by a source column, that keeps the old amounts. Filters on the primary source and on the backup source each restore one row per return without losing returns. Without the uniqueness rule, repair takes the first filter it finds, the backup. A reference that ignores the source column rejects it, but a gold SQL that already filters on the primary source accepts it, and \system\ then publishes a revision that answers two of four new questions wrongly for both return metrics. With the uniqueness rule, repair finds both filters and invalidates the definitions under either reference. Rerunning the replay of \system\ with the rule changes none of the 3,000 outcomes under the two references, because the status-change, restatement, and SCD Type 2 fixes are unique.}
{\emph{有歧义的修复。}备份副本变化更正了部分 2002 年的退货金额，并追加一整份退货表的备份副本（以来源列标记），副本保留旧金额。按主数据来源过滤和按备份来源过滤，都能使每笔退货恰好一行且不丢退货。没有唯一性规则时，修复取搜索到的第一个过滤，即备份。不涉及来源列的参照会拒绝它，但预先按主数据来源过滤的标准答案 SQL 会接受它，于是 \system\ 发布的修订在两个退货指标的 4 道新题中都答错 2 道。有了唯一性规则，修复会找到两个过滤，在任一参照下都使定义失效。打开该规则后重新回放 \system，两种参照下共 3,000 道题的结果没有任何变化，因为状态变更行、多版本更正与缓慢变化维（类型 2）的修复都是唯一的。}

\bi{\emph{Availability during repair.} Rejecting requests that arrive while a repair runs makes \WrDefOff\ of \WrUses\ simultaneous uses (eight agents, 19 definitions, three runs at 200,000 rows) unavailable under definition-level and \WrCondOff\ under condition-level maintenance, where shared check results invalidate many definitions at once; coalescing them with the running repair removes all of them at the same total waiting time and database work.}
{\emph{修复期间的可用性。}若拒绝修复进行中到达的请求，同时到达的 \WrUses\ 次使用（8 个智能体、19 个定义、20 万行、3 轮）中，定义级维护有 \WrDefOff\ 次不可用，条件级维护有 \WrCondOff\ 次——共享的检查结果使许多定义同时失效；把这些请求与进行中的修复合并后，不可用全部消失，总等待时间与数据库工作量不变。}
