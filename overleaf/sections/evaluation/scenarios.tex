\bi{\emph{End to end (Q3).} After the held-out questions, each of eleven data changes is applied from the same snapshot and memory, the questions whose metric reads an updated table are asked again, and the change is rolled back. Reference answers reflect the change's business effect, so an agent must filter out status rows, old versions, duplicate loads, or backup copies. The changes fall into four non-breaking updates, five breaking changes that the conditions cover (status-change rows, restatements, duplicate loads, SCD Type 2, reformatted date keys), and two outside them (a unit change and a backup copy). Each method runs five times on the synthetic dataset and \GeRuns\ times on TPC-H, every run learning its own library; we analyze \ScenCells\ synthetic runs with \ScenValidTasks\ scored tasks, and intervals are 95\% bootstrap intervals over whole runs.}
{\emph{端到端（Q3）。}留出题之后，11 种数据变化各自从同一快照和同一记忆开始施加，重问指标读到被更新表的题目，然后回滚。参考答案反映变化的业务效果，因此智能体必须排除状态行、旧版本、重复加载或备份副本。这些变化分为 4 种正常更新、条件覆盖的 5 种破坏性变化（状态流水、更正保留旧行、重复加载、缓慢变化维类型 2、日期键格式变化）和 2 种不在覆盖范围内的变化（金额单位变化、备份副本）。每种方法在合成数据上运行 5 次、在 TPC-H 上运行 \GeRuns\ 次，每次运行学习自己的定义库；合成数据上共分析 \ScenCells\ 次运行、\ScenValidTasks\ 道计分题，区间为按整次运行的 95\% 自助区间。}

\bi{Figure~\ref{fig:scenarios} gives every method under every change on the synthetic dataset, and Figure~\ref{fig:twoschemas} pools the settings on both schemas; they show where sharing methods separate. On held-out questions the two sharing methods agree (\DsTrajHoldout--\DsCondHoldout\%, against \DsNoShareHoldout\% without memory), and after the non-breaking updates \system\ keeps \DsCondBenign\% and retrieval \DsTrajBenign\%. Under the covered breaking changes, \system\ answers \DsCondModeled\% (\DsCondModeledLo--\DsCondModeledHi) and example retrieval \DsTrajModeled\%, \DsCmpModeledTraj\ points apart (\DsCmpModeledTrajLo--\DsCmpModeledTrajHi), and on TPC-H \GeCondModeled\% against \GeTrajModeled\%: retrieved examples replay SQL written for the old grain, so after a restatement every agent that retrieves them counts restated sales twice. Telling the retrieval agent to verify grain, join keys, and date keys itself lifts it only to \DsTrajVerifyModeled\%, at \DsTrajVerifyTurns\ instead of \DsTrajTurns\ turns per question: verification by each agent costs every agent, and still misses the distinguishing filter that a shared repair supplies once. Invalidation on schema change serves stale definitions in \DsSchemaStaleModeled\ tasks, and invalidation on every write stays correct only by relearning after each write, \ScenRelearnTok\,M tokens per run. The full recheck per definition answers \DsDefModeled\%, as \system\ does; the two differ only in maintenance work.}
{图~\ref{fig:scenarios} 给出合成数据上每种方法在每种变化下的结果，图~\ref{fig:twoschemas} 把两种模式上的情形合并；二者显示了各共享方法在哪里拉开差距。留出题上两种共享方法相当（\DsTrajHoldout--\DsCondHoldout\%，无记忆为 \DsNoShareHoldout\%），正常更新之后 \system\ 保持 \DsCondBenign\%，示例检索为 \DsTrajBenign\%。在条件覆盖的破坏性变化下，\system\ 答对 \DsCondModeled\%（\DsCondModeledLo--\DsCondModeledHi），示例检索 \DsTrajModeled\%，相差 \DsCmpModeledTraj\ 个百分点（\DsCmpModeledTrajLo--\DsCmpModeledTrajHi）；TPC-H 上为 \GeCondModeled\% 对 \GeTrajModeled\%：检索到的示例重放为旧粒度写的 SQL，因此更正之后，每个检索到它的智能体都把被更正的销售算两次。让检索智能体自己核对粒度、连接键和日期键，也只把它提高到 \DsTrajVerifyModeled\%，每题 \DsTrajVerifyTurns\ 轮而不是 \DsTrajTurns\ 轮：由每个智能体各自核验，代价落在每个智能体身上，而且仍找不到共享修复一次就能提供的区分过滤。模式变更时失效在 \DsSchemaStaleModeled\ 道题中使用了过期定义；每次写入即失效只靠每次写入后重新学习保持正确，每次运行 \ScenRelearnTok\,M token。整定义重查答对 \DsDefModeled\%，与 \system\ 相同，两者只在维护工作量上不同。}



\bi{\emph{Limits.} The unit change fails no condition, so \system\ cannot detect it; the backup copy satisfies the grain in two ways, so \system\ refuses the ambiguous repair and invalidates (Section~\ref{sec:repair-eval}).}
{\emph{限度。}单位变化不违反任何条件，\system\ 无法发现它；备份副本以两种方式满足粒度，\system\ 拒绝有歧义的修复并使定义失效（第~\ref{sec:repair-eval} 节）。}
