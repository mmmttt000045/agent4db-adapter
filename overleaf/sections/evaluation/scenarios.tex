\subsection{\bt{Data-change scenarios with LLM agents}{大模型智能体的数据变化场景}}
\label{sec:scenarios}
\bi{\emph{Protocol (Q5).} Five metrics (store revenue, store return amount, store return rate, catalog revenue, electronics store revenue) each have two learning questions and five scored questions: a new period, a period difference, the month with the highest value, the month with the largest rise over the previous month, and the number of months above the mean of the twelve monthly values. \system's learning agent answers the learning questions with explicit business definitions, and sessions whose answer matches the reference answer pass extraction and the publication checks. A user agent that has never seen the metrics answers the scored questions given only metric names, first on unchanged data and then once per data-change scenario; each scenario starts from the same snapshot and memory, applies one update (the columns of Figure~\ref{fig:scenarios}), re-asks the questions whose metric reads an updated table, and is rolled back. Reference answers reflect the update's business effect, so an agent must filter out duplicate rows, status rows, backup copies, or old versions.}
{\emph{实验流程（Q5）。}5 个指标（门店营业额、门店退货金额、门店退货率、目录渠道营业额、电子品类门店营业额）各有 2 道学习题和 5 道计分题：新期间、跨期差值、取值最高的月份、比上一个月增加最多的月份、高于 12 个月平均值的月份数。\system\ 的学习智能体在给出显式业务定义的学习题上作答，答案与参考答案一致的会话经提取与发布前检查后发布。从未接触过这些指标的用户端智能体只拿到指标名，先在未变化的数据上回答计分题，再在每个数据变化场景下各答一次；每个场景从相同的快照和记忆出发，施加一次更新（图~\ref{fig:scenarios} 的各列），只重问读到被更新表的指标，结束后回滚。标准答案反映更新的业务效果，因此智能体必须过滤掉重复行、申请状态行、备份副本或旧版本。}

\bi{\emph{Methods and runs.} The methods play three roles (Table~\ref{tab:ladder}). No memory is the lower bound: agents explore alone. Example retrieval and invalidation on schema change are the existing ways to share, agent memory and the metric layer's safeguard, which do not check what they serve. Invalidation on every write and \system\ maintain, the former by relearning after each write; the full recheck per definition is \system\ without check-result reuse and answers within a point of it on every setting, so Figure~\ref{fig:scenarios} leaves it to Figure~\ref{fig:cost}. The \emph{example-retrieval} baseline, in the spirit of AgentSM~\cite{biswal2026agentsm}, receives the same learning tasks under the same publication requirement (a verified answer), stores the question, the SQL that produced the answer, and the arithmetic, and lets the user agent retrieve up to three examples by question similarity, without validity maintenance. Agent and extractor use DeepSeek V4.1 Flash with high reasoning effort, a 20-turn limit, and a 60\,s SQL timeout. Each of the nine methods runs five times, and every run learns its own library. We analyze \ScenCells\ runs with \ScenValidTasks\ scored tasks (\ScenTokensM\,M tokens); intervals are 95\% bootstrap intervals over whole runs, and the comparison with example retrieval was specified before the runs.}
{\emph{方法与运行。}各方法扮演三种角色（表~\ref{tab:ladder}）。无记忆是下界：智能体各自探索。示例检索与模式变更时失效是现有的共享方式，即智能体记忆与指标层的保护手段，它们不检查所提供的内容。每次写入即失效与 \system\ 做维护，前者靠每次写入后重新学习；整定义重查是去掉检查结果复用的 \system，在每种情形下与它相差不到一个百分点，因此图~\ref{fig:scenarios} 把它留给图~\ref{fig:cost}。仿照 AgentSM~\cite{biswal2026agentsm} 的\emph{示例检索}基线获得同样的学习题、同样的发布前提（答案核对正确），保存题面、产生答案的 SQL 与算式，用户端智能体按题面相似度检索最多 3 条，不做有效性维护。智能体与提取器使用 DeepSeek V4.1 Flash，推理强度 high，每题最多 20 轮，SQL 超时 60 秒。9 种方法各运行 5 次，每次各自学习自己的定义库。我们分析 \ScenCells\ 次运行、\ScenValidTasks\ 道计分题（\ScenTokensM\,M token）；区间为按运行整体重抽样的 95\% 自助法区间，与示例检索的比较在运行前确定。}

\bi{\emph{Sharing and non-breaking updates.} Every sharing method carries over what was learned (the first two groups of Figure~\ref{fig:scenarios}): on held-out questions they answer \DsTrajHoldout--\DsCondHoldout\%, against \DsNoShareHoldout\% without memory. After the non-breaking updates \system\ keeps \DsCondBenign\%; invalidating on every write keeps \DsRevokeBenign\% only by relearning after every write, with \ScenRelearnTok\,M LLM tokens per run.}
{\emph{共享与正常更新。}各共享方法都能复用学到的内容（图~\ref{fig:scenarios} 的前两组）：留出题上答对 \DsTrajHoldout--\DsCondHoldout\%，无记忆为 \DsNoShareHoldout\%。正常更新之后 \system\ 保持 \DsCondBenign\%；每次写入即失效要靠每次写入后重新学习才保持 \DsRevokeBenign\%，每次运行用 \ScenRelearnTok\ 百万个大模型 token。}

\bi{\emph{Covered breaking changes.} Here the methods separate. \system\ answers \DsCondModeled\% (\DsCondModeledLo--\DsCondModeledHi) and example retrieval \DsTrajModeled\%, \DsCmpModeledTraj\ points apart (\DsCmpModeledTrajLo--\DsCmpModeledTrajHi). Retrieved examples carry no validity state: under status-change rows they replay SQL that counts some returns twice, and under restatements and duplicate loads they reuse SQL written for the old grain. Invalidation on schema change serves stale definitions in \DsSchemaStaleModeled\ tasks, the hatched bars of its series; the recheck methods serve none, and the full recheck per definition answers \DsDefModeled\%, \DsCmpModeledDef\ point from \system\ (\DsCmpModeledDefLo--\DsCmpModeledDefHi), so it differs from \system\ only in cost (Section~\ref{sec:cost}). Regression as of learning time matters for automation: \system\ publishes \DsCondRepaired\ repairs per run, against \DsCondCurRepaired\ with the regression test on current data, where agents must re-derive the refused filters themselves. Telling the example-retrieval agent to verify grain, join keys, and date keys, the properties \system\ checks for it, moves it to \DsTrajVerifyModeled\% at \DsTrajVerifyTurns\ instead of \DsTrajTurns\ turns, still \DsCmpModeledCondVerify\ points behind \system\ (\DsCmpModeledCondVerifyLo--\DsCmpModeledCondVerifyHi): an agent told what to check must still find the distinguishing column and filter in every session, whereas a maintained definition carries the check result and the repair.}
{\emph{条件覆盖的破坏性变化。}各方法在这里拉开差距。\system\ 答对 \DsCondModeled\%（\DsCondModeledLo--\DsCondModeledHi），示例检索 \DsTrajModeled\%，相差 \DsCmpModeledTraj\ 个百分点（\DsCmpModeledTrajLo--\DsCmpModeledTrajHi）。检索到的示例没有有效性状态：状态流水下它重放会把部分退货算两次的 SQL，更正保留旧行与重复加载下它沿用为旧粒度写的 SQL。只在模式变更时失效在 \DsSchemaStaleModeled\ 道题中提供了过期定义，即其柱上的斜线；各重查方法一道也没有，整定义重查答对 \DsDefModeled\%，与 \system\ 相差 \DsCmpModeledDef\ 个百分点（\DsCmpModeledDefLo--\DsCmpModeledDefHi），因此二者只在代价上不同（第~\ref{sec:cost} 节）。按学习时刻回归决定了自动化程度：\system\ 每次运行发布 \DsCondRepaired\ 个修复，回归测试用当前数据时只有 \DsCondCurRepaired\ 个，被拒绝的过滤要由智能体自己重新推出。让示例检索的智能体核对粒度、连接键与日期键——正是 \system\ 替它检查的性质——使其达到 \DsTrajVerifyModeled\%，每题轮数从 \DsTrajTurns\ 增至 \DsTrajVerifyTurns，仍落后 \system\ \DsCmpModeledCondVerify\ 个百分点（\DsCmpModeledCondVerifyLo--\DsCmpModeledCondVerifyHi）：被告知要检查什么的智能体仍要在每次会话中自己找到区分列和过滤，而维护后的定义带着检查结果和修复。}
