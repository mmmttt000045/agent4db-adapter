\subsection{\bt{Correctness when the data changes}{数据变化时的正确性}}
\label{sec:scenarios}
\input{figures/two-schemas}
\bi{\emph{End to end (Q3).} After the held-out questions, each of eleven data changes is applied from the same snapshot and memory, the questions whose metric reads an updated table are asked again, and the change is rolled back. Reference answers reflect the change's business effect, so an agent must filter out status rows, old versions, duplicate loads, or backup copies. The changes fall into four non-breaking updates, five breaking changes that the conditions cover (status-change rows, restatements, duplicate loads, SCD Type 2, reformatted date keys), and two outside them (a unit change and a backup copy). Each method runs five times on the synthetic dataset and \GeRuns\ times on TPC-H, every run learning its own library; we analyze \ScenCells\ synthetic runs with \ScenValidTasks\ scored tasks, and intervals are 95\% bootstrap intervals over whole runs.}
{\emph{端到端（Q3）。}留出题之后，11 种数据变化各自从同一快照和同一记忆开始施加，重问指标读到被更新表的题目，然后回滚。参考答案反映变化的业务效果，因此智能体必须排除状态行、旧版本、重复加载或备份副本。这些变化分为 4 种正常更新、条件覆盖的 5 种破坏性变化（状态流水、更正保留旧行、重复加载、缓慢变化维类型 2、日期键格式变化）和 2 种不在覆盖范围内的变化（金额单位变化、备份副本）。每种方法在合成数据上运行 5 次、在 TPC-H 上运行 \GeRuns\ 次，每次运行学习自己的定义库；合成数据上共分析 \ScenCells\ 次运行、\ScenValidTasks\ 道计分题，区间为按整次运行的 95\% 自助区间。}

\bi{Figure~\ref{fig:twoschemas} shows where sharing methods separate. On held-out questions the two sharing methods agree (\DsTrajHoldout--\DsCondHoldout\%, against \DsNoShareHoldout\% without memory), and after the non-breaking updates \system\ keeps \DsCondBenign\% and retrieval \DsTrajBenign\%. Under the covered breaking changes, \system\ answers \DsCondModeled\% (\DsCondModeledLo--\DsCondModeledHi) and example retrieval \DsTrajModeled\%, \DsCmpModeledTraj\ points apart (\DsCmpModeledTrajLo--\DsCmpModeledTrajHi), and on TPC-H \GeCondModeled\% against \GeTrajModeled\%: retrieved examples replay SQL written for the old grain, so after a restatement every agent that retrieves them counts restated sales twice. Telling the retrieval agent to verify grain, join keys, and date keys itself lifts it only to \DsTrajVerifyModeled\%, at \DsTrajVerifyTurns\ instead of \DsTrajTurns\ turns per question: verification by each agent costs every agent, and still misses the distinguishing filter that a shared repair supplies once. Invalidation on schema change serves stale definitions in \DsSchemaStaleModeled\ tasks, and invalidation on every write stays correct only by relearning after each write, \ScenRelearnTok\,M tokens per run. The full recheck per definition answers \DsDefModeled\%, as \system\ does; the two differ only in maintenance work.}
{图~\ref{fig:twoschemas} 显示了各共享方法在哪里拉开差距。留出题上两种共享方法相当（\DsTrajHoldout--\DsCondHoldout\%，无记忆为 \DsNoShareHoldout\%），正常更新之后 \system\ 保持 \DsCondBenign\%，示例检索为 \DsTrajBenign\%。在条件覆盖的破坏性变化下，\system\ 答对 \DsCondModeled\%（\DsCondModeledLo--\DsCondModeledHi），示例检索 \DsTrajModeled\%，相差 \DsCmpModeledTraj\ 个百分点（\DsCmpModeledTrajLo--\DsCmpModeledTrajHi）；TPC-H 上为 \GeCondModeled\% 对 \GeTrajModeled\%：检索到的示例重放为旧粒度写的 SQL，因此更正之后，每个检索到它的智能体都把被更正的销售算两次。让检索智能体自己核对粒度、连接键和日期键，也只把它提高到 \DsTrajVerifyModeled\%，每题 \DsTrajVerifyTurns\ 轮而不是 \DsTrajTurns\ 轮：由每个智能体各自核验，代价落在每个智能体身上，而且仍找不到共享修复一次就能提供的区分过滤。模式变更时失效在 \DsSchemaStaleModeled\ 道题中使用了过期定义；每次写入即失效只靠每次写入后重新学习保持正确，每次运行 \ScenRelearnTok\,M token。整定义重查答对 \DsDefModeled\%，与 \system\ 相同，两者只在维护工作量上不同。}

\bi{\emph{Library replay.} \label{sec:validity}To separate maintenance from what agents happened to learn, we replay fixed libraries under every change and answer each affected question with the generated SQL of the revision a method serves: \RpLibs\ libraries learned by three LLMs on the synthetic dataset, \TrSeeded\ definitions derived from the TPC-DS query templates on TPC-DS SF1, and \GnSeeded\ derived from the queries of TPC-H, SSB, and BIRD financial, with the changes generated from a short description of each schema. On every schema \system\ serves no wrong answer under the changes its conditions cover (Figure~\ref{fig:replay}); it answers through a repair under status-change rows, restatements, and SCD Type 2 and invalidates under duplicate loads and reformatted date keys. Invalidation on schema change serves \RpSchemaWrongModeled\ wrong answers on the learned libraries and \TrSchemaWrongModeled\ on TPC-DS; dbt-style table tests avoid them but cannot repair, answering \RpTableCorrect\ questions against \RpCondCorrect. Running the regression test on current data instead of as of learning time refuses correct repairs wherever a restatement touches the learning period, because the agent's learning SQL is itself stale there.}
{\emph{定义库回放。}为了把维护与智能体碰巧学到了什么分开，我们在每种变化下回放固定的定义库，用各方法所提供版本的生成的 SQL 回答每道受影响的题：3 个大模型在合成数据上学到的 \RpLibs\ 个定义库；在 TPC-DS SF1 上，从 TPC-DS 查询模板导出的 \TrSeeded\ 个定义；以及从 TPC-H、SSB 与 BIRD financial 的查询导出的 \GnSeeded\ 个定义，变化按各模式的简短描述生成。在每种模式上，\system\ 在其条件覆盖的变化下都不给出错误答案（图~\ref{fig:replay}）；它在状态流水、更正保留旧行与缓慢变化维下经修复作答，在重复加载与日期键格式变化下使定义失效。模式变更时失效在学到的定义库上给出 \RpSchemaWrongModeled\ 个错误答案，在 TPC-DS 上 \TrSchemaWrongModeled\ 个；dbt 式表级测试避免了这些错误，但不能修复，答对 \RpTableCorrect\ 题，\system\ 为 \RpCondCorrect\ 题。若回归测试在当前数据上而不是按学习时刻比较，凡是更正触及学习期间的地方都会拒绝正确的修复，因为智能体的学习 SQL 在那里本身已经过期。}

\bi{\emph{Concurrent writes.} Under concurrent writers, a check that passed may no longer hold when the query runs: check-then-execute answers on data that violates the declared revision's grain in up to \SnPreUnannMax\% of answered queries, whereas same-snapshot validation does so in none of \SnSnapAnswered, at the same median latency. \emph{Limits.} The unit change fails no condition, so \system\ cannot detect it; the backup copy satisfies the grain in two ways, so \system\ refuses the ambiguous repair and invalidates.}
{\emph{并发写入。}存在并发写入时，通过的检查在查询执行时可能已不成立：先检查后执行在最多 \SnPreUnannMax\% 的已回答查询中，在违反所声明版本粒度条件的数据上作答；同快照验证在 \SnSnapAnswered\ 个已回答查询中一次也没有，中位延迟相同。\emph{限度。}金额单位变化不使任何条件失败，\system\ 无从发现；备份副本有两种方式满足粒度，因此 \system\ 拒绝有歧义的修复并使定义失效。}
