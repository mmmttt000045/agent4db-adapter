\subsection{\bt{Metric Workload Setup and Baselines}{指标负载设置与基线}}
\label{sec:metric-setup}
\bi{The metric studies ask how savings grow with agent count (Q1), where per-question savings arise and what learning costs (Q2), whether agents remain correct after data changes (Q3), and what shared maintenance and optimization cost relative to per-agent work (Q4). Agents answer with one SQL query. The machine has 48 cores, 98\,GiB RAM, and PostgreSQL 18.6. The population study uses TPC-DS SF1 (24 tables, 2.9 million store-sales rows); per-question and data-change studies use synthetic retail data with TPC-DS-style columns (one million store-sales rows, about 396,000 returns and 500,000 catalog sales) and TPC-H SF1.}
{指标研究考察节省如何随智能体数量增长（Q1）、每题省在哪里以及学习的代价（Q2）、数据变化后智能体是否仍能正确作答（Q3），以及共享维护与优化相对逐智能体工作的代价（Q4）。智能体用一条 SQL 作答。机器为 48 核、98\,GiB 内存，运行 PostgreSQL 18.6。群体实验使用 TPC-DS SF1（24 张表、290 万行门店销售）；每题代价与数据变化实验使用列名仿照 TPC-DS 的合成零售数据（100 万行门店销售、约 39.6 万行退货、50 万行目录销售）及 TPC-H SF1。}

\bi{\emph{Workload.} The metric questions separate learning a business definition from using it in a new analysis. Synthetic retail covers five metrics: store revenue, return amount, return rate, catalog revenue, and electronics store revenue. Each metric has two learning questions that state its definition and five scored questions that give only its name. The latter ask for a new period, a period difference, the highest month, the largest monthly rise, or months above the monthly mean. TPC-H applies these forms to five metrics derived from its query templates. TPC-DS uses the same seven forms for five template-derived metrics: store sales for one category manager, registered-customer sales, mid-sized-store coupons, returns at known stores, and yearly totals. Handwritten or template-compiled reference queries compute answers on each question's snapshot.}
{\emph{负载。}指标问题将学习业务定义与在新分析中使用定义分开。合成零售数据包含五个指标：门店营业额、退货金额、退货率、目录渠道营业额和电子品类门店营业额。每个指标用两道明确给出定义的学习题建立记忆，再用五道只给指标名的题计分，分别询问新期间、期间差值、最高月、最大月增量和高于月均值的月份。TPC-H 将这些题型用于从其查询模板导出的五个指标。TPC-DS 对五个模板指标采用相同七种题型：一位品类经理所管商品的门店销售额、登记顾客销售额、中型门店优惠券金额、关联得上门店的退货金额，以及年度汇总口径。人工编写或由模板编译的参考查询，在每道题的快照上计算答案。}

\bi{Metric agents and the extractor use \llmmodel{} with high reasoning effort, at most 20 turns, and a 60\,s SQL timeout, extended to 120\,s on TPC-DS/TPC-H. RelBench uses low effort to bound repeated feature-search cost, while the metric studies prioritize exact answers with high effort; effort is fixed across methods within each study. All methods share the tools, with memory lookup added where applicable. Tokens count input plus output, and agent time spans the first call to the final answer.}
{指标智能体与提取器使用 \llmmodel{}，推理强度为高，最多 20 轮；SQL 超时为 60 秒，在 TPC-DS／TPC-H 上延长至 120 秒。RelBench 用低强度控制反复搜索特征的代价，指标研究则以高强度侧重精确答案；每项研究内各方法保持相同推理档位。各方法共用工具，有记忆时增加查找操作。token 统计输入与输出之和，智能体耗时从首次调用计至最终答案。}

\bi{The studies use different memory scopes to answer different questions. The population study in Section~\ref{sec:population-eval} shares table descriptions, verified joins, check results, and query results per question without memory, per agent with private memory, or globally with \system. The per-question and data-change studies in Sections~\ref{sec:sharing-eval} and~\ref{sec:changes-eval} give even the memoryless baseline shared access to these resources, so their comparison focuses on executable definitions and maintenance.}
{不同研究采用不同记忆作用域，以回答不同问题。第~\ref{sec:population-eval} 节的群体实验中，表描述、验证过的连接、检查结果和查询结果，在无记忆组按题保留，在私有记忆组按智能体保留，在 \system\ 中全局共享。第~\ref{sec:sharing-eval} 和~\ref{sec:changes-eval} 节的每题代价与数据变化实验则让无记忆基线也共享这些资源，将比较集中到可执行定义和维护。}

First, Figure~\ref{fig:twoschemas} compares maintenance strategies: No-Memory, trajectory retrieval (Traj-Retrieve and Traj-PromptVerify), schema- and write-triggered metric invalidation (Metric-Schema and Metric-Relearn), Maint-DefLevel, and \system.
