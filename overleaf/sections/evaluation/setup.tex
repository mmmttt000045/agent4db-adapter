\subsection{\bt{Metric questions: questions and setup}{指标问题：研究问题与设置}}
\label{sec:metric-setup}
\bi{The metric studies ask how savings grow with agent count (Q1), where per-question savings arise and what learning costs (Q2), whether agents remain correct after data changes (Q3), and what shared maintenance and optimization cost relative to per-agent work (Q4). Agents answer with one SQL query. The machine has 48 cores, 98\,GiB RAM, and PostgreSQL 18.6. The population study uses TPC-DS SF1 (24 tables, 2.9 million store-sales rows); per-question and data-change studies use synthetic retail data with TPC-DS-style columns (one million store-sales rows, about 396,000 returns and 500,000 catalog sales) and TPC-H SF1.}
{指标研究考察节省如何随智能体数量增长（Q1）、每题省在哪里以及学习的代价（Q2）、数据变化后智能体是否仍能正确作答（Q3），以及共享维护与优化相对逐智能体工作的代价（Q4）。智能体用一条 SQL 作答。机器为 48 核、98\,GiB 内存，运行 PostgreSQL 18.6。群体实验使用 TPC-DS SF1（24 张表、290 万行门店销售）；每题代价与数据变化实验使用列名仿照 TPC-DS 的合成零售数据（100 万行门店销售、约 39.6 万行退货、50 万行目录销售）及 TPC-H SF1。}

\bi{\emph{Workload.} Five metrics (store revenue, return amount, return rate, catalog revenue, electronics store revenue) each have two learning questions stating the business definition and five scored questions naming only the metric: a new period, a period difference, the highest month, the largest monthly rise, and months above the monthly mean. TPC-DS uses the same seven forms for five template-derived metrics: store sales for one category manager, registered-customer sales, mid-sized-store coupons, returns at known stores, and yearly totals. Reference queries, handwritten or compiled from TPC-DS/TPC-H templates, compute answers on the question's snapshot. Agents and extractor use \llmmodel{} with high reasoning effort, 20 turns, and a 60\,s SQL timeout (120\,s on TPC-DS/TPC-H); methods share tools, with lookup added for memory. Low effort bounds RelBench's repeated feature-search cost; high effort prioritizes exact metric answers, with agent effort fixed across compared arms within each study. In the population study (Section~\ref{sec:population-eval}), table descriptions, verified joins, check results, and query results follow the memory scope: per-question without memory, per-agent with private memory, and global with \system. In Sections~\ref{sec:sharing-eval} and~\ref{sec:changes-eval}, memoryless baselines also share these resources, isolating executable definitions and maintenance. Table~\ref{tab:ladder} lists the metric data-change methods. Tokens count input plus output; agent time spans the first call to the final answer.}
{\emph{负载。}5 个指标（门店营业额、退货金额、退货率、目录渠道营业额、电子品类门店营业额）各有 2 道给出业务定义的学习题，以及 5 道只给指标名的计分题：新期间、期间差值、最高月、最大月增量、高于月均值的月份数。TPC-DS 的五个模板指标以同样七种形式提问：一位品类经理所管商品的门店销售额、登记顾客销售额、中型门店优惠券金额、关联得上门店的退货金额，以及年度汇总口径。参考查询由人工编写或从 TPC-DS／TPC-H 模板编译，在提问所在快照上计算答案。智能体与提取器使用 \llmmodel{}，推理强度为高，最多 20 轮，SQL 超时 60 秒（TPC-DS／TPC-H 为 120 秒）；各方法共用工具，有记忆的方法增加查找工具。低档位控制 RelBench 反复搜索特征的代价，高档位侧重精确指标作答；各研究内部的比较组保持相同的智能体推理档位。群体实验（第~\ref{sec:population-eval} 节）中，表描述、验证过的连接、检查结果和查询结果遵循记忆作用域：无记忆按题保留，私有记忆按智能体保留，\system\ 全局共享。第~\ref{sec:sharing-eval}、\ref{sec:changes-eval} 节的无记忆基线也共享这些资源，以隔离可执行定义与维护的收益。表~\ref{tab:ladder} 列出指标数据变化实验的方法。token 为输入与输出之和；智能体耗时从首次调用计到最终答案。}
