\subsection{\bt{Questions and setup}{问题与设置}}
\bi{The evaluation asks what sharing saves and whether its savings stay correct. (Q1) As agents accumulate on one database, how much time and how many tokens does shared memory save against no memory, single-agent memory, and shared examples? (Q2) What does a reusing agent pay per question, and what does building the memory cost? (Q3) Does shared knowledge stay correct when the data changes, end to end, independently of what agents learned, and under concurrent writes? (Q4) What do maintenance and optimization cost, and who pays? The machine has 48 cores and 98\,GiB RAM and runs PostgreSQL 18.6. The synthetic retail dataset uses TPC-DS-style column names; one million store-sales rows come with about 396,000 returns and 500,000 catalog sales. The population study runs on TPC-DS SF1 (24 tables, 2.9 million store-sales rows); end to end we also use TPC-H SF1, and the library replay adds TPC-DS SF1, SSB SF1, and the BIRD financial database~\cite{li2023bird} of a real bank, with libraries derived from each benchmark's own queries.}
{评估回答共享省下了什么，以及这些节省是否保持正确。（Q1）随着智能体在同一数据库上不断累积，与无记忆、单智能体记忆和共享示例相比，共享记忆省下多少时间和 token？（Q2）复用记忆的智能体每道题付出多少，建立记忆的代价是多少？（Q3）数据变化时共享的知识是否保持正确：端到端、不受智能体学到什么影响时，以及在并发写入下？（Q4）维护与优化的代价是多少，由谁付？实验机有 48 核与 98\,GiB 内存，运行 PostgreSQL 18.6。合成零售数据采用 TPC-DS 风格列名；100 万行门店销售对应约 39.6 万行退货和 50 万行目录销售。群体实验在 TPC-DS SF1 上进行（24 张表，290 万行门店销售）；端到端实验还使用 TPC-H SF1；定义库回放另加 TPC-DS SF1、SSB SF1 和 BIRD 的 financial 库~\cite{li2023bird}（一家银行的真实数据），各定义库由该基准自己的查询导出。}

\bi{\emph{Workload.} Five metrics (store revenue, store return amount, store return rate, catalog revenue, electronics store revenue) each have two learning questions, which state the business definition, and five scored questions that give only the metric name: a new period, a period difference, the month with the highest value, the month with the largest rise, and the number of months above the monthly mean. On TPC-DS the five metrics come from the benchmark's query templates (store sales of the items of one category manager, store sales to registered customers, coupon amount at mid-sized stores, store returns at known stores, and the benchmark's yearly-total measure) and are asked in the same seven forms. A reference query, written by hand or, on TPC-DS and TPC-H, compiled from the template's definition, computes every reference answer on the snapshot the question is asked on. Agents and extractor use DeepSeek V4.1 Flash with high reasoning effort, a 20-turn limit, and a 60\,s SQL timeout (120\,s on TPC-DS and TPC-H); every method gives agents the same tools, and the memory methods add their lookup tool. Table~\ref{tab:ladder} lists the compared methods. Tokens are input plus output tokens; agent time runs from an agent's first call to its final answer.}
{\emph{负载。}5 个指标（门店营业额、门店退货金额、门店退货率、目录渠道营业额、电子品类门店营业额）各有 2 道给出业务定义的学习题，以及 5 道只给指标名的计分题：新的期间、跨期差值、全年最高月、比上月增加最多的月份、高于月平均值的月份数。在 TPC-DS 上，5 个指标取自该基准的查询模板（一位品类经理所管商品的门店销售额、登记顾客的门店销售额、中型门店的优惠券金额、关联得上门店的门店退货金额，以及该基准的年度汇总口径），以同样的 7 种形式提问。参考查询（人工编写；TPC-DS 与 TPC-H 上由模板的定义编译而成）在提问所在的快照上算出每个参考答案。智能体与提取器使用 DeepSeek V4.1 Flash，推理强度为高，最多 20 轮，SQL 超时 60 秒（TPC-DS 与 TPC-H 上为 120 秒）；各方法给智能体相同的工具，有记忆的方法另加各自的查找工具。表~\ref{tab:ladder} 列出被比较的方法。token 指输入与输出 token 之和；智能体时间从智能体的第一次调用计到给出最终答案。}
