\subsection{\bt{Metric questions: questions and setup}{指标问题：研究问题与设置}}
\label{sec:metric-setup}
\bi{The remaining studies use metric questions, where an agent answers with a single SQL query, and controlled data changes. (Q1) As agents accumulate on one database, how much does shared memory save against no memory and single-agent memory, and how does the saving grow with the number of agents? (Q2) Where does a reusing agent save, per question and on another schema, and what does building the memory cost? (Q3) What does sharing itself cost to maintain, against per-agent copies and per-agent verification, and what does one optimization save for all agents? (Q4) Do the savings survive data changes? The machine has 48 cores and 98\,GiB RAM and runs PostgreSQL 18.6. The population study runs on TPC-DS SF1 (24 tables, 2.9 million store-sales rows); the per-question and data-change studies use a synthetic retail dataset with TPC-DS-style column names (one million store-sales rows, about 396,000 returns and 500,000 catalog sales) and TPC-H SF1.}
{其余各项研究使用指标问题（智能体用一条 SQL 作答）与受控的数据变化。（Q1）智能体在同一数据库上陆续累积时，与无记忆和单智能体记忆相比，共享记忆省下多少？节省如何随智能体数量增长？（Q2）复用记忆的智能体按每道题省在哪里，换一种模式是否成立？建立记忆的代价是多少？（Q3）与按智能体分别保存的副本、每个智能体各自核验相比，维护共享本身的代价是多少？一次优化为所有智能体省下多少？（Q4）节省能否经得起数据变化？机器为 48 核、98\,GiB 内存，运行 PostgreSQL 18.6。群体实验在 TPC-DS SF1（24 张表，290 万行门店销售）上运行；按题实验与数据变化实验使用列名仿照 TPC-DS 的合成零售数据（100 万行门店销售，约 39.6 万行退货、50 万行目录销售）与 TPC-H SF1。}

\bi{\emph{Workload.} Five metrics (store revenue, store return amount, store return rate, catalog revenue, electronics store revenue) each have two learning questions, which state the business definition, and five scored questions that give only the metric name: a new period, a period difference, the month with the highest value, the month with the largest rise, and the number of months above the monthly mean. On TPC-DS the five metrics come from the benchmark's query templates (store sales of the items of one category manager, store sales to registered customers, coupon amount at mid-sized stores, store returns at known stores, and the benchmark's yearly-total measure) and are asked in the same seven forms. A reference query, written by hand or, on TPC-DS and TPC-H, compiled from the template's definition, computes every reference answer on the snapshot the question is asked on. Agents and extractor use \llmmodel{} with high reasoning effort, a 20-turn limit, and a 60\,s SQL timeout (120\,s on TPC-DS and TPC-H); every method gives agents the same tools, and the memory methods add their lookup tool. The studies evaluate full-system sharing and the incremental benefit of executable definitions. In the population study (Section~\ref{sec:population-eval}), all methods use the same layer; table descriptions, verified join paths, check results, and query results follow the memory policy: per-question for memoryless agents, per-agent for single-agent memory, and shared across agents for \system. In the per-question and eleven-change studies (Sections~\ref{sec:sharing-eval} and~\ref{sec:changes-eval}), memoryless baselines also share these resources, isolating the additional benefit of executable definitions and their maintenance. Table~\ref{tab:ladder} lists the compared methods. Tokens are input plus output tokens; agent time runs from an agent's first call to its final answer.}
{\emph{负载。}5 个指标（门店营业额、门店退货金额、门店退货率、目录渠道营业额、电子品类门店营业额）各有 2 道给出业务定义的学习题，以及 5 道只给指标名的计分题：新的期间、跨期差值、全年最高月、比上月增加最多的月份、高于月平均值的月份数。在 TPC-DS 上，5 个指标取自该基准的查询模板（一位品类经理所管商品的门店销售额、登记顾客的门店销售额、中型门店的优惠券金额、关联得上门店的门店退货金额，以及该基准的年度汇总口径），以同样的 7 种形式提问。参考查询（人工编写；TPC-DS 与 TPC-H 上由模板的定义编译而成）在提问所在的快照上算出每个参考答案。智能体与提取器使用 \llmmodel{}，推理强度为高，最多 20 轮，SQL 超时 60 秒（TPC-DS 与 TPC-H 上为 120 秒）；各方法给智能体相同的工具，有记忆的方法另加各自的查找工具。这些研究分别评估完整系统共享的收益与可执行定义的增量收益。群体实验（第~\ref{sec:population-eval} 节）中，各方法使用同一层，表描述、验证过的连接路径、检查结果与查询结果遵循相应记忆策略：无记忆按题保留，单智能体记忆按智能体保留，\system\ 则在所有智能体间共享。每题代价与十一种数据变化实验（第~\ref{sec:sharing-eval}、\ref{sec:changes-eval} 节）进一步向无记忆基线开放这些资源的共享，以衡量可执行定义及其维护带来的增量收益。表~\ref{tab:ladder} 列出被比较的方法。token 指输入与输出 token 之和；智能体时间从智能体的第一次调用计到给出最终答案。}

\bi{\emph{Comparison scope.} Table~\ref{tab:ladder} contains controlled baselines for memory scope, retrieval, and maintenance. Example retrieval omits AgentSM's offline synthesis and composite tools and must not be interpreted as that system. The reported experiments do not directly compare with AgentSM or DataLab; the RelBench baselines and metric ablations do not establish superiority over them.}
{\emph{比较范围。}表~\ref{tab:ladder} 包含针对记忆范围、检索和维护的受控基线。示例检索未包含 AgentSM 的离线合成与复合工具，不能被视为该系统。本文所报告实验尚未直接比较 AgentSM 或 DataLab；RelBench 基线与指标消融不能支持优于这两者的结论。}
