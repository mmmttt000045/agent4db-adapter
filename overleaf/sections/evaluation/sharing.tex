\subsection{\bt{Publication and consumer performance}{发布与使用者性能}}
\label{sec:sharing-eval}
\bi{\emph{What admission refuses (Q6).} In the runs of Section~\ref{sec:scenarios}, \PubJudged\ learning trajectories were judged successful; admission published \PubPromoted\ of them as new entries, \PubCorroborated\ corroborated an existing entry, and \PubRefused\ were refused. Over these runs and the three-LLM round of Section~\ref{sec:validity} (\PubAllJudged\ judged-successful trajectories), the canonical replay refused \PubReplayRefused\ candidates into which extraction had introduced an error, and the derivation check refused \PubChainRefused\ whose recorded derivation does not reproduce the answer. Each refusal is an extraction error that would otherwise have reached every consumer. In the worst case, the extractor dropped the category filter of electronics store revenue: the agent had answered \PubExAnswer, and the canonical SQL that later agents would have received returns \PubExCanon, \PubExRatio\ times as much. The producer's own SQL was correct; only checking what consumers will read catches the error.}
{\emph{准入拒绝了什么（Q6）。}在第~\ref{sec:scenarios} 节的运行中，\PubJudged\ 条学习轨迹被判定成功；准入把其中 \PubPromoted\ 条发布为新条目，\PubCorroborated\ 条作为已有条目的佐证，拒绝了 \PubRefused\ 条。在这些运行与第~\ref{sec:validity} 节的三模型一轮中（共 \PubAllJudged\ 条判题成功的轨迹），规范 SQL 重放拒绝了 \PubReplayRefused\ 个在提取时被引入错误的候选，算式检查拒绝了 \PubChainRefused\ 个记录的算式无法复现答案的候选。每一次拒绝都是提取中真实出现的错误，放行就会传到每个使用者。最严重的一例中，提取器丢掉了电子品类门店营业额的类别过滤：智能体答的是 \PubExAnswer，而之后的智能体将拿到的规范 SQL 返回 \PubExCanon，是它的 \PubExRatio\ 倍。生产者自己的 SQL 是对的；只有检查使用者将要读到的内容，才能发现这个错误。}

\bi{\emph{What consumers gain.} Building the memory costs \AmProdTokK\,k tokens and \AmProdS\,s per library for the ten learning sessions, extraction, and admission, once; the copy of the tables that as-of queries read is not counted. On the held-out questions of Section~\ref{sec:scenarios}, timed per agent session from the first tool call to the final answer on unchanged data, a consumer with \system\ takes \AmHoldSCond\,s and \AmHoldTokCondK\,k tokens per task, against \AmHoldSAlone\,s and \AmHoldTokAloneK\,k tokens when it explores alone: \AmHoldSpeedup$\times$ faster, with \AmHoldTokSave\% fewer tokens per task and \AmCorrectTokSave\% fewer per correct answer. Maintenance is paid once per change for all consumers, \AmMaintBenignS\,s of database time per benign change and \AmMaintRepairS\,s per repaired one, whereas the self-verifying retrieval agent pays \AmVerifyExtraS\,s and \AmVerifyExtraTokK\,k tokens more in every task on unchanged data and benign updates and is still less accurate under breaking changes.}
{\emph{使用者得到了什么。}每个定义库的建立代价是 \AmProdTokK\,k token、\AmProdS\ 秒（10 个学习会话、提取与准入），只付一次；供 as-of 查询读取的表副本不计入。在第~\ref{sec:scenarios} 节的留出题上（数据不变，每个智能体会话从第一次工具调用计到给出最终答案），使用 \system\ 的使用者每题用 \AmHoldSCond\ 秒、\AmHoldTokCondK\,k token，独自探索时为 \AmHoldSAlone\ 秒、\AmHoldTokAloneK\,k token：快 \AmHoldSpeedup\ 倍，每题 token 少 \AmHoldTokSave\%，每个正确答案的 token 少 \AmCorrectTokSave\%。维护每次变化只为所有使用者付一次：每次正常变化 \AmMaintBenignS\ 秒数据库时间，每次需要修复的变化 \AmMaintRepairS\ 秒；而自行核验的检索智能体在数据不变和正常更新时每题都多花 \AmVerifyExtraS\ 秒和 \AmVerifyExtraTokK\,k token，在破坏性变化下仍然不如维护准确。}

\bi{\emph{When invalidation returns the work to consumers.} The gain reverses where no repair is possible. Under the duplicate load, the date-key format change, and the backup copy, invalidated definitions send consumers back to the data with a notice that names the failed condition; they then spend \AmInvalTokCondK\,k tokens and \AmInvalSCond\,s per task, against \AmInvalTokAloneK\,k tokens and \AmInvalSAlone\,s for agents that explore alone, and answer \AmInvalAccCond\% against \AmInvalAccAlone\%. The fixes these consumers find are paid for in every task.}
{\emph{失效何时把工作交还给使用者。}在无法修复的地方，收益反转。在重复加载、日期键格式变化和备份副本下，失效的定义把使用者送回数据，并附上指明失败条件的通知；此时使用者每题花 \AmInvalTokCondK\,k token、\AmInvalSCond\ 秒，独自探索的智能体为 \AmInvalTokAloneK\,k token、\AmInvalSAlone\ 秒，正确率 \AmInvalAccCond\% 对 \AmInvalAccAlone\%。这些使用者找到的修正在每道题里都要重新付一次。}
