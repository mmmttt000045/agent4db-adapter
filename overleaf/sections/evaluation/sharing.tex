\subsection{\bt{Per-Question Savings and Learning Overhead (Q2)}{每题节省与学习开销（Q2）}}
\label{sec:sharing-eval}
\bi{Once memory is available, both trajectory retrieval and executable-definition reuse reduce per-question cost on unchanged data (Table~\ref{tab:consumer-cost}). Learning and publication are paid once, so later agents benefit without repeating discovery.}
{记忆建立后，轨迹检索和可执行定义复用都能降低不变数据上的每题代价（表~\ref{tab:consumer-cost}）。学习与发布的代价只付一次，后续智能体即可省去重复发现。}
\input{tables/consumer-cost}
\bi{\emph{Reuse protocol and results.} Each method runs five times on synthetic retail and \GeRuns\ times on TPC-H. Memory methods learn from ten questions (two per metric); new agents then answer 25 held-out questions on unchanged data, given only the metric name. Each run learns its own memory. Table~\ref{tab:consumer-cost} compares no memory, trajectory retrieval, and executable-definition reuse, with shared metadata and tools in all three methods. Against no memory, \system\ is \AmHoldSpeedup$\times$ faster on synthetic retail (\GsHoldSpeedupMin--\GsHoldSpeedupMax$\times$ per run) and \GeHoldSpeedup$\times$ on TPC-H (\GeHoldSpeedupMin--\GeHoldSpeedupMax$\times$). On synthetic retail, its higher accuracy also reduces tokens per correct answer by \AmCorrectTokSave\%.}
{\emph{复用设置与结果。}每种方法在合成零售数据上运行五次、在 TPC-H 上运行 \GeRuns\ 次。有记忆的方法从 10 道题（每个指标两道）学习，新的智能体随后在数据不变时回答 25 道只给指标名的留出题；每次运行学习自己的记忆。表~\ref{tab:consumer-cost} 比较无记忆、轨迹检索与可执行定义复用，三者均共享元数据和底层工具。相对无记忆，\system\ 在合成数据上快 \AmHoldSpeedup\ 倍（每次运行 \GsHoldSpeedupMin--\GsHoldSpeedupMax\ 倍），在 TPC-H 上快 \GeHoldSpeedup\ 倍（\GeHoldSpeedupMin--\GeHoldSpeedupMax\ 倍）；合成数据上更高的正确率还使每个正确答案的 token 减少 \AmCorrectTokSave\%。}

\bi{These savings do not establish a cost advantage over trajectory retrieval. On TPC-H, retrieval uses \GeHoldTokTrajK\,k tokens per question versus \GeHoldTokCondK\,k for \system, and both answer \GeCondHoldout\% correctly. Unchanged-data reuse is effective with either representation; Section~\ref{sec:changes-eval} tests their correctness when the underlying data changes.}
{这些节省并不意味着相对轨迹检索也有代价优势。TPC-H 上，轨迹检索每题用 \GeHoldTokTrajK\,k token，\system\ 用 \GeHoldTokCondK\,k，两者均答对 \GeCondHoldout\%。数据不变时，两种表示均能有效复用；第~\ref{sec:changes-eval} 节进一步检验底层数据变化后的正确性。}

\bi{\emph{Building the memory.} One library costs \AmProdTokK\,k tokens and \AmProdS\,s for the ten learning sessions, extraction, and the publication checks, paid once for all agents. The checks are what make the shared result safe to hand out: over \PubAllJudged\ sessions with a verified answer, the replay of the generated SQL rejected \PubReplayRefused\ candidates into which extraction had introduced an error, and the calculation check \PubChainRefused\ more. In the worst case the extractor dropped the category filter of electronics store revenue: the producing agent had answered \PubExAnswer, and the SQL every later agent would have received returns \PubExCanon, \PubExRatio\ times as much.}
{\emph{建立记忆。}一个定义库的代价是 \AmProdTokK\,k token 和 \AmProdS\ 秒（10 个学习会话、提取与发布前检查），为所有智能体只付一次。正是这些检查使共享出去的结果安全：在 \PubAllJudged\ 个答案核对正确的会话中，生成的 SQL 重放拒绝了 \PubReplayRefused\ 个在提取时被引入错误的候选，算式检查又拒绝了 \PubChainRefused\ 个。最严重的一例中，提取器丢掉了电子品类门店营业额的类别过滤：产生它的智能体答的是 \PubExAnswer，而之后每个智能体将拿到的 SQL 返回 \PubExCanon，是它的 \PubExRatio\ 倍。}
