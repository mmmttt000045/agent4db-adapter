\subsection{\bt{Tool calls and reuse behavior across three cutoffs}{三截点工具调用与复用行为}}
\label{sec:sharing-eval}
\bi{\emph{Three-cutoff trace protocol.} We use RelBench's tasks, label generation, and metrics~\cite{robinson2024relbench}: post-votes (MAE), user-badge and user-engagement (AUC) on rel-stack; site-success and study-adverse (MAE), and study-outcome (AUC) on rel-trial. Ninety sessions cover five methods, two databases, three tasks, and the first three cutoffs of the existing grid: January/April/July 2020 and January 2017--2019, respectively. These precede the official final test split. Sessions restart at each cutoff as new-period rows are appended. Based on validation tuning on rel-amazon/user-churn, the selected policy validates an available task program first, retrieves definitions as needed, and skips extraction only for identical, already-published SQL that passes a fresh audit.}
{\emph{三截点轨迹协议。}使用RelBench任务、标签生成与指标~\cite{robinson2024relbench}：rel-stack上的post-votes（MAE）、user-badge与user-engagement（AUC），rel-trial上的site-success与study-adverse（MAE）、study-outcome（AUC）。90个会话覆盖五种方法、两库、三任务及既有网格的前三截点：分别为2020年1／4／7月与2017--2019年1月，均早于官方最终测试划分。追加新期间数据后，各任务重启会话。根据rel-amazon/user-churn验证数据上的调优，选中策略先验证可用任务程序，按需检索定义，仅对已发布且重新通过审计的相同SQL跳过提炼。}

\bi{\emph{Baselines and execution.} Comparators are no memory, ACE~\cite{zhang2026ace}, AWM~\cite{wang2025awm}, and G-Memory~\cite{zhang2025gmemory}. We adapt official code/prompts to common SQL tools and validation feedback: ACE maintains task playbooks with its reflector/curator, AWM induces task workflows, and G-Memory shares memory within each database. All use the official \code{deepseek-flash} alias (\llmmodel{} on the study date), thinking enabled and low effort. Each validation attempt trains a LightGBM~\cite{ke2017lightgbm} model with a fixed configuration on 50,000 training seeds and audits up to 5,000 seeds for temporal leakage. Limits are 24 planner calls, five validations, two consecutive validation attempts without improvement, and 600\,s per feature statement. At cutoffs 2--3, refitting the previous solution gives the target; after reaching it, one improvement is allowed within three calls. Tests are scored after the sequence and never enter feedback or memory. Failures retain costs and receive the entity-reference score. Total token counts include internal memory-model calls.}
{\emph{基线与执行。}对照为无记忆、ACE~\cite{zhang2026ace}、AWM~\cite{wang2025awm}、G-Memory~\cite{zhang2025gmemory}。官方代码／提示词适配到共用SQL工具与验证反馈：ACE用反思者／整理者维护任务手册，AWM归纳任务工作流，G-Memory在库内共享记忆。统一调用官方\code{deepseek-flash}别名（实验日对应\llmmodel{}），启用思考、低推理强度。每次验证使用50,000个训练种子，按固定配置训练LightGBM~\cite{ke2017lightgbm}模型，对最多5,000种子审计时间泄漏。上限24次规划调用、5次验证、连续2次验证未改进，每条特征语句600秒。截点2--3以上一方案重训分数为目标，达到后可在3次调用内再改进一次。序列结束后才评测试集，测试标签不进入反馈或记忆。失败计成本并使用实体参照分数。总token包含记忆内部模型调用。}

\bi{\emph{SQL-source audit.} Nine of twelve reuse sessions first validate returned task SQL; six keep it verbatim. None directly validates unchanged definition-compiled SQL. Explicit \code{compose\_features} calls are absent, although both lookup tools compile internally. At the first cutoff, user-engagement directly validates eight compiled features; the temporal audit rejects three post-related columns previously admitted on user-badge, and a rewrite passes. Consumer-side temporal audits are therefore essential when transferring features across tasks with different label semantics.}
{\emph{SQL来源审计。}十二个复用会话中九个先验证返回的任务SQL，六个原样保留；没有直接验证原样定义编译SQL的会话。无显式\code{compose\_features}调用，但两种查找工具均在内部编译。首截点user-engagement直接验证八个编译特征，时间审计拒绝三个此前在user-badge获准发布的帖子相关列，改写后通过。因此，跨标签语义不同的任务迁移特征时，消费者侧时间审计至关重要。}
