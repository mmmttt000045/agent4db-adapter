\label{sec:sharing-eval}
\input{figures/consumer-cost}
\bi{\emph{Reusing agents (Q2).} In the end-to-end study of Section~\ref{sec:scenarios}, \system's learning agent builds a library from the ten learning questions, and a new user agent then answers the held-out questions on unchanged data. A reusing agent finds the definition, runs its generated SQL for the question's parameters, and answers, instead of exploring tables, values, and joins. Figure~\ref{fig:consumer} shows what this saves: on the synthetic dataset a question takes \AmHoldSCond\,s and \AmHoldTokCondK\,k tokens with \system\ against \AmHoldSAlone\,s and \AmHoldTokAloneK\,k exploring alone, \AmHoldSpeedup$\times$ faster (\GsHoldSpeedupMin--\GsHoldSpeedupMax$\times$ per run) with \AmHoldTokSave\% fewer tokens, and on TPC-H \GeHoldSpeedup$\times$ faster (\GeHoldSpeedupMin--\GeHoldSpeedupMax$\times$) with \GeHoldTokSave\% fewer tokens. Because reusing agents are also right more often (\DsCondHoldout\% against \DsNoShareHoldout\%), a correct answer costs \AmCorrectTokSave\% fewer tokens (\AmTokPerCorrectCondK\,k against \AmTokPerCorrectAloneK\,k). Retrieved examples save about as much on unchanged data; they differ from \system\ when the data changes (Section~\ref{sec:scenarios}).}
{\emph{复用记忆的智能体（Q2）。}在第~\ref{sec:scenarios} 节的端到端实验中，\system\ 的学习智能体用 10 道学习题建立定义库，之后一个新的用户端智能体在数据不变时回答留出题。复用记忆的智能体查到定义、按题目参数执行其生成的 SQL 并作答，而不必探索表、取值和连接。图~\ref{fig:consumer} 给出这样省下了多少：在合成数据上，使用 \system\ 每题 \AmHoldSCond\ 秒、\AmHoldTokCondK\,k token，独自探索为 \AmHoldSAlone\ 秒、\AmHoldTokAloneK\,k token，快 \AmHoldSpeedup\ 倍（每次运行 \GsHoldSpeedupMin--\GsHoldSpeedupMax\ 倍），token 少 \AmHoldTokSave\%；在 TPC-H 上快 \GeHoldSpeedup\ 倍（\GeHoldSpeedupMin--\GeHoldSpeedupMax\ 倍），token 少 \GeHoldTokSave\%。复用记忆的智能体也更常答对（\DsCondHoldout\%，独自探索为 \DsNoShareHoldout\%），因此每个正确答案少用 \AmCorrectTokSave\% 的 token（\AmTokPerCorrectCondK\,k 对 \AmTokPerCorrectAloneK\,k）。检索到的示例在数据不变时省下的相差无几；它与 \system\ 的区别出现在数据变化时（第~\ref{sec:scenarios} 节）。}

\bi{\emph{Building the memory.} One library costs \AmProdTokK\,k tokens and \AmProdS\,s for the ten learning sessions, extraction, and the publication checks, paid once for all agents. The checks are what make the shared result safe to hand out: over \PubAllJudged\ sessions with a verified answer, the replay of the generated SQL rejected \PubReplayRefused\ candidates into which extraction had introduced an error, and the calculation check \PubChainRefused\ more. In the worst case the extractor dropped the category filter of electronics store revenue: the producing agent had answered \PubExAnswer, and the SQL every later agent would have received returns \PubExCanon, \PubExRatio\ times as much.}
{\emph{建立记忆。}一个定义库的代价是 \AmProdTokK\,k token 和 \AmProdS\ 秒（10 个学习会话、提取与发布前检查），为所有智能体只付一次。正是这些检查使共享出去的结果安全：在 \PubAllJudged\ 个答案核对正确的会话中，生成的 SQL 重放拒绝了 \PubReplayRefused\ 个在提取时被引入错误的候选，算式检查又拒绝了 \PubChainRefused\ 个。最严重的一例中，提取器丢掉了电子品类门店营业额的类别过滤：产生它的智能体答的是 \PubExAnswer，而之后每个智能体将拿到的 SQL 返回 \PubExCanon，是它的 \PubExRatio\ 倍。}
