\subsection{\bt{Per-Question Savings and Learning Overhead (Q2)}{每题节省与学习开销（Q2）}}
\label{sec:sharing-eval}
\bi{Once memory is available, both trajectory retrieval and executable-definition reuse reduce per-question cost on unchanged data (Table~\ref{tab:consumer-cost}). Learning and publication are paid once, so later agents benefit without repeating discovery.}
{记忆建立后，轨迹检索和可执行定义复用都能降低不变数据上的每题代价（表~\ref{tab:consumer-cost}）。学习与发布的代价只付一次，后续智能体即可省去重复发现。}

\bi{\emph{Reuse protocol and results.} Memory methods first learn from ten questions, two per metric. New agents then answer 25 held-out questions on unchanged data, given only the metric name. Each method runs five times on synthetic retail and \GeRuns\ times on TPC-H, learning its own memory in each run. Table~\ref{tab:consumer-cost} compares no memory, trajectory retrieval, and executable-definition reuse, with metadata and tools shared in all three methods.}
{\emph{复用设置与结果。}有记忆的方法先从十道题学习，每个指标两道；新的智能体随后在数据不变时回答 25 道只给指标名的留出题。每种方法在合成零售数据上运行五次，在 TPC-H 上运行 \GeRuns\ 次，每次学习自己的记忆。表~\ref{tab:consumer-cost} 比较无记忆、轨迹检索和可执行定义复用，三者均共享元数据和底层工具。}

\bi{Against no memory, \system's average speedup is \AmHoldSpeedup$\times$ on synthetic retail and \GeHoldSpeedup$\times$ on TPC-H. Across runs, speedups range from \GsHoldSpeedupMin$\times$ to \GsHoldSpeedupMax$\times$ and from \GeHoldSpeedupMin$\times$ to \GeHoldSpeedupMax$\times$, respectively. On synthetic retail, the higher accuracy also reduces tokens per correct answer by \AmCorrectTokSave\%.}
{相对无记忆，\system\ 在合成零售数据上的平均加速为 \AmHoldSpeedup\ 倍，在 TPC-H 上为 \GeHoldSpeedup\ 倍。各次运行的加速范围分别为 \GsHoldSpeedupMin\ 至 \GsHoldSpeedupMax\ 倍、\GeHoldSpeedupMin\ 至 \GeHoldSpeedupMax\ 倍。合成数据上更高的正确率，还使每个正确答案的 token 减少 \AmCorrectTokSave\%。}

\bi{Trajectory retrieval captures much of the benefit on unchanged data. On TPC-H it uses \GeHoldTokTrajK\,k tokens per question, compared with \GeHoldTokCondK\,k for \system, at the same \GeCondHoldout\% accuracy. The next question is therefore how these representations behave when their underlying data changes; Section~\ref{sec:changes-eval} examines that distinction.}
{轨迹检索已经获得了不变数据上复用的主要收益。TPC-H 上，它每题使用 \GeHoldTokTrajK\,k token，\system\ 使用 \GeHoldTokCondK\,k，两者的正确率均为 \GeCondHoldout\%。接下来的问题是：底层数据变化后，这两种表示能否继续支持正确作答？第~\ref{sec:changes-eval} 节检验这一差别。}

\bi{\emph{Learning overhead.} Building one library costs \AmProdTokK\,k tokens and \AmProdS\,s, covering ten learning sessions, extraction, and publication checks. This investment serves all later agents. The checks matter because a correct answer can become an incorrect definition during extraction: among \PubAllJudged\ sessions with verified answers, SQL replay rejected \PubReplayRefused\ such candidates and calculation checks rejected \PubChainRefused\ more. In one example, extraction dropped the category filter for electronics revenue. The resulting SQL would have returned \PubExCanon\ instead of the verified \PubExAnswer, \PubExRatio\ times the verified value, an error every later consumer would otherwise inherit.}
{\emph{学习开销。}建立一个定义库需要 \AmProdTokK\,k token 和 \AmProdS\ 秒，覆盖十个学习会话、提取与发布检查；这笔投入随后服务所有智能体。发布检查的作用在于，正确答案也可能在提取时变成错误定义：在 \PubAllJudged\ 个答案已核实的会话中，SQL 重放拒绝了 \PubReplayRefused\ 个这样的候选，计算链检查又拒绝了 \PubChainRefused\ 个。例如，一次提取丢掉了电子品类收入的类别过滤，使生成的 SQL 返回 \PubExCanon，而非核实过的 \PubExAnswer。结果为核实值的 \PubExRatio\ 倍，若直接发布，这个错误就会传给后续每个使用者。}
