\subsection{\bt{Validity under data changes}{数据变化下的有效性}}
\label{sec:validity}
\bi{\emph{Library replay (Q1).} An earlier round of the end-to-end protocol of Section~\ref{sec:scenarios} with three LLMs (DeepSeek V4.1 Flash, GLM-5.3, and GLM-5.3 Flash) yields \RpLibs\ learned libraries of 3--8 admitted definitions, \RpDefs\ in all. We replay every library under every method on the same data: each method gets its own middleware instance admitted with the library's definitions and learning evidence, each of the \RpChanges\ changes of Figure~\ref{fig:scenarios} is applied from the same initial snapshot, and the scored questions of every affected definition are answered with the canonical SQL of the revision the method serves, \RpCondN\ questions per method. This isolates maintenance from learning and agent behavior. A question is \emph{correct}, \emph{wrong}, or \emph{invalidated}; an invalidation is \emph{correct} if the unmaintained definition would also have answered wrongly, and \emph{false} otherwise.}
{\emph{定义库回放（Q1）。}第~\ref{sec:scenarios} 节的端到端流程此前用三个大模型（DeepSeek V4.1 Flash、GLM-5.3、GLM-5.3 Flash）运行的一轮得到 \RpLibs\ 个学到的定义库，各含 3--8 个已准入定义，共 \RpDefs\ 个。我们在同一份数据上用每种方法回放每个库：每种方法各有一个中间件实例，以该库的定义和学习证据准入；图~\ref{fig:scenarios} 的 \RpChanges\ 种变化都从同一初始快照施加；每个受影响定义的计分题用该方法提供的修订的规范 SQL 作答，每种方法 \RpCondN\ 道题。这把维护与学习、与智能体行为隔离开。每道题的结果为\emph{答对}、\emph{答错}或\emph{失效}；若未经维护的定义同样会答错，则该失效为\emph{正确失效}，否则为\emph{误失效}。}

\bi{Every revalidation method serves wrong answers only under the unit change, which no condition covers, whereas invalidation on schema change serves \RpSchemaWrongModeled\ wrong answers under the covered changes (Figure~\ref{fig:replay}). \system, the full recheck per definition, and the query cache give the same outcome on every question (\RpSameCondDef\%), so their end-to-end differences come from what agents learned. False invalidations are conservative: they arise mostly for return rate, whose ratio can stay right while its grain is broken.}
{各重验证方法只在任何条件都不覆盖的单位变化下给出错误答案，而只在模式变更时失效在条件覆盖的变化下给出 \RpSchemaWrongModeled\ 个错误答案（图~\ref{fig:replay}）。\system、整定义重查与查询缓存在每道题上的结果都相同（\RpSameCondDef\%），因此它们在端到端上的差别来自智能体学到的内容。误失效是保守的：它主要出现在退货率上，粒度已被破坏而比率碰巧仍然正确。}

\bi{\emph{dbt-style table tests}, which declare key uniqueness for every table and referential tests on date and item keys and invalidate every definition that reads a table with a failing test, also serve no wrong answer under the covered changes (\RpTableWrongModeled) but cannot repair: they answer \RpTableCorrect\ questions against \RpCondCorrect\ for \system, and their false invalidations (\RpTableUnneeded\ against \RpCondUnneeded) come from acting on tables rather than on definitions.}
{\emph{dbt 式表级测试}为每张表声明键唯一性、为日期键和商品键声明引用测试，并使读到测试失败的表的所有定义失效；它在条件覆盖的变化下同样不给出错误答案（\RpTableWrongModeled），但不能修复：它答对 \RpTableCorrect\ 题，\system\ 答对 \RpCondCorrect\ 题；它的误失效（\RpTableUnneeded\ 对 \RpCondUnneeded）来自按表而不是按定义行动。}

\bi{\emph{Real TPC-DS data.} The same replay runs on TPC-DS at scale factor 1 (2.9 million store-sales rows) with a library that was not written for this paper: the \TrDefs\ definitions that the derivation of Section~\ref{sec:alternatives} extracts from the 99 query templates and that the structured implementation can express, of which \TrSeeded\ pass admission; each definition's canonical SQL plays the agent's learning SQL. The lower panel of Figure~\ref{fig:replay} matches the synthetic fixture: \system\ serves no wrong answer under the covered changes, repairs every affected definition under status-change rows, restatements, and SCD Type 2 (\TrCondRepairedTasks\ questions answered through a repair), and invalidates the definitions under duplicate loads, the date-key format change, and the backup copy; invalidation on schema change serves \TrSchemaWrongModeled\ wrong answers, and table tests repair nothing.}
{\emph{真实 TPC-DS 数据。}同一回放也在规模因子 1 的 TPC-DS（290 万行门店销售）上运行，定义库不是为本文编写的：第~\ref{sec:alternatives} 节的推导从 99 个查询模板中提取、且结构化实现能够表达的 \TrDefs\ 个定义，其中 \TrSeeded\ 个通过准入；每个定义的规范 SQL 充当智能体的学习 SQL。图~\ref{fig:replay} 下半部分与合成数据一致：\system\ 在条件覆盖的变化下不给出错误答案，在状态流水、更正保留旧行与缓慢变化维（类型 2）下修复了每一个受影响的定义（\TrCondRepairedTasks\ 道题经修复后作答），在重复加载、日期键格式变化与备份副本下使定义失效；只在模式变更时失效给出 \TrSchemaWrongModeled\ 个错误答案，表级测试一个也不能修复。}

\bi{\emph{Three more schemas.} On TPC-H, SSB, and BIRD financial, \GnKept\ of the \GnDerived\ definitions derived from \GnQueries\ benchmark queries have a nonzero learning answer, and all \GnSeeded\ pass admission. The lowest panel of Figure~\ref{fig:replay} repeats the TPC-DS pattern on \GnCondN\ questions per method. \system\ answers \GnCondRepairedTasks\ questions through a repair under status-change rows, restatements, and SCD Type 2, and invalidates the definitions under duplicate loads, the date-key change (a new key format, or dates loaded empty where dates are columns), and the backup copy. Outside the unit change it serves \GnCondWrongModeled\ wrong answers, all from a single TPC-H definition whose period is the receipt date while its filter compares the ship and commit dates: the date-key change empties the ship date, which no condition of that definition reads (Section~\ref{sec:sufficiency}). Invalidation on schema change serves \GnSchemaWrongModeled\ wrong answers; table tests serve none outside the unit change, since their not-null test on the ship date quarantines every line-item definition, but they repair nothing and answer \GnTableCorrect\ questions against \GnCondCorrect\ for \system. The date columns, snowflake joins, repeated column names, and one-to-one joins of these schemas need no schema-specific code. On SSB, whose yyyymmdd keys skip numbers at month boundaries, date-key contiguity fails in \GnSsbContigBad\ of \GnSsbMonths\ months, so the premise check refuses the key-range rule there.}
{\emph{另外三种模式。}在 TPC-H、SSB 与 BIRD financial 上，从 \GnQueries\ 条基准查询导出的 \GnDerived\ 个定义中有 \GnKept\ 个的学习题答案非空、非零，全部 \GnSeeded\ 个通过准入。图~\ref{fig:replay} 最下面的面板在每种方法 \GnCondN\ 题上重现了 TPC-DS 的结果。\system\ 在状态流水、更正保留旧行与缓慢变化维（类型 2）下经修复作答 \GnCondRepairedTasks\ 题，在重复加载、日期键变化（改用另一种键格式，或在以日期列为日历的模式中日期写为空）与备份副本下使定义失效。单位变化之外，它给出 \GnCondWrongModeled\ 个错误答案，全部来自 TPC-H 的同一个定义：其期间按收货日期划分，过滤却比较发货日期与承诺日期；日期键变化清空了发货日期，而该定义的条件都不读这一列（第~\ref{sec:sufficiency} 节）。只在模式变更时失效给出 \GnSchemaWrongModeled\ 个错误答案；表级测试在单位变化之外没有错误答案，因为发货日期上的非空测试隔离了所有订单明细上的定义，但它不能修复，答对 \GnTableCorrect\ 题，\system\ 答对 \GnCondCorrect\ 题。这些模式的日期列、雪花型连接、重名的列与一对一连接都不需要针对模式的代码。SSB 的 yyyymmdd 日期键在月界处跳号，\GnSsbMonths\ 个月中有 \GnSsbContigBad\ 个月不满足日期键连续，因此前提检查在 SSB 上拒绝键范围改写。}
