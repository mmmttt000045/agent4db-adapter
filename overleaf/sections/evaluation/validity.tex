\subsection{\bt{Validity under data changes}{数据变化下的有效性}}
\label{sec:validity}
\bi{\emph{Library replay (Q1).} The earlier three-model scenario run (Section~\ref{sec:scenarios}) left each run with the library its agents learned: \RpLibs\ libraries of 3--8 admitted definitions, \RpDefs\ in all, from three LLMs. We replay every library under every method on the same data. Each method gets its own middleware instance, admitted with the library's definitions and learning evidence; each of the \RpChanges\ changes (the ten scenarios of Figure~\ref{fig:scenarios} plus a backup-copy change, Section~\ref{sec:repair-eval}) is applied from the same initial snapshot; and the scored questions of every affected definition are answered with the canonical SQL of whatever revision the method serves. Two definitions fail admission against the agent's own SQL, leaving \RpCondN\ scored questions per method. This isolates maintenance from learning and from agent behavior. A question is \emph{correct}, \emph{wrong} (the served revision answers incorrectly), or \emph{invalidated}; an invalidation is \emph{correct} if the unmaintained definition would also have answered incorrectly, and \emph{false} otherwise.}
{\emph{定义库回放（Q1）。}此前一轮三模型场景实验（第~\ref{sec:scenarios} 节）在每次运行结束时留下该次运行学到的定义库：\RpLibs\ 个库，各含 3--8 个已准入定义，共 \RpDefs\ 个，来自 3 个大模型。我们在同一份数据上用每种方法回放每个库。每种方法各有一个中间件实例，以该库的定义和学习证据准入；\RpChanges\ 种变化（图~\ref{fig:scenarios} 的 10 个场景，外加一个备份副本变化，见第~\ref{sec:repair-eval} 节）都从同一初始快照施加；每个受影响定义的计分题，用该方法当时提供的修订的规范 SQL 作答。有两个定义未能以智能体自己的 SQL 通过准入，每种方法余下 \RpCondN\ 道计分题。这把维护与学习、与智能体行为隔离开。每道题的结果为\emph{答对}、\emph{答错}（提供的修订答错）或\emph{失效}；若未经维护的定义同样会答错，则该失效为\emph{正确失效}，否则为\emph{误失效}。}

\bi{Figure~\ref{fig:replay} shows the result. Every revalidation method serves wrong answers only under the unit change, which no condition covers; under the covered changes they serve none, whereas schema-change invalidation serves \RpSchemaWrongModeled\ wrong answers there and invalidate-on-write without relearning answers nothing. Condition-level maintenance, definition-level revalidation, and the check-result cache give the same outcome on every question (\RpSameCondDef\%), so differences between them in end-to-end accuracy come from what agents learned, not from maintenance. False invalidations are conservative rather than wrong: they arise mostly for return rate under duplicate loads and the date-key format change, where numerator and denominator change together and the ratio happens to stay right although the grain condition is broken.}
{图~\ref{fig:replay} 给出结果。各重验证方法只在任何条件都不覆盖的单位变化下提供错误答案；在条件覆盖的变化下一个也没有，而按模式变更失效在这些变化下提供了 \RpSchemaWrongModeled\ 个错误答案，不重新学习的写入即失效则一题也答不了。条件级维护、定义级重验证与检查结果缓存在每道题上的结果都相同（\RpSameCondDef\%），因此它们在端到端正确率上的差别来自智能体学到的内容，而不是维护方式。误失效是保守而非错误：它主要出现在重复加载与日期键格式变化下的退货率上，此时分子分母同步变化，比率碰巧仍然正确，但粒度条件确实被破坏了。}

\bi{\emph{Table tests.} The table-test baseline declares the tests a dbt project would: uniqueness of each fact table's business key and of each dimension key, and referential tests from the date and item keys, calibrated to pass on the initial snapshot. After every update it reruns them and invalidates every definition that reads a table with a failing test. It serves no wrong answer under the covered changes either (\RpTableWrongModeled), because every covered break also breaks a declared key, but it cannot repair: on the same questions it answers \RpTableCorrect\ against \RpCondCorrect\ for \system, and the \RpTableOnlyCond\ questions it loses are those \system\ repairs or keeps because the definition's own filter already satisfies the condition. Its false invalidations (\RpTableUnneeded\ against \RpCondUnneeded) come from acting on the table rather than on the definition.}
{\emph{表级测试。}表级测试基线声明的是 dbt 项目会声明的测试：各事实表业务键与各维表键的唯一性，以及日期键、商品键的引用测试，按初始快照校准。每次更新后它重跑全部测试，并使读到测试失败的表的所有定义失效。在条件覆盖的变化下它同样不给出错误答案（\RpTableWrongModeled）——每种条件覆盖的破坏都会破坏某个声明的键——但它不能修复：同一批题目上它答对 \RpTableCorrect\ 题，\system\ 答对 \RpCondCorrect\ 题，它少答对的 \RpTableOnlyCond\ 题，是 \system\ 修复的题目，或因定义自己的过滤已满足条件而保留的题目。它的误失效（\RpTableUnneeded\ 题对 \RpCondUnneeded\ 题）来自按表而不是按定义行动。}

\bi{\emph{Real TPC-DS data.} The same replay runs on TPC-DS at scale factor 1 (2.9 million store-sales rows, all 24 tables as generated by dsdgen) with a library that was not written for this paper: the \TrDefs\ definitions that the derivation of Section~\ref{sec:alternatives} extracts from the 99 query templates and that the structured implementation can express (one aggregate over a sales or returns fact table with one date role, dimension joins from the fact table on primary keys, and single-table definition filters); \TrSeeded\ pass admission and \TrSeedFailed\ have an empty learning period. The eleven changes are applied to the real tables through the same classes, copying complete rows and resolving dates through \code{date\_dim}. Each definition's canonical SQL plays the agent's learning SQL, and gold answers add the distinguishing-column filters. Over \TrCondN\ scored questions per method, the outcomes match the synthetic fixture: \system\ serves no wrong answer under the covered changes, repairs the status-change rows (\TrCondRepairedTasks\ questions), and invalidates the definitions under the other breaking changes, either because the change touches the learning period (restatements, SCD Type 2) or because no unique filter restores the grain; schema-change invalidation serves \TrSchemaWrongModeled\ wrong answers, and table tests make \TrTableNeeded\ correct and \TrTableUnneeded\ false invalidations. With the gold SQL, \system\ also repairs restatements and SCD Type 2 and answers \TrPairGold\ instead of \TrPairCond\ questions correctly, with \TrPairExtraWrong\ more wrong answers.}
{\emph{真实 TPC-DS 数据。}同一回放也在规模因子 1 的 TPC-DS（290 万行门店销售，dsdgen 生成的全部 24 张表）上运行，定义库不是为本文编写的：第~\ref{sec:alternatives} 节的推导从 99 个查询模板中提取、且结构化实现能够表达的 \TrDefs\ 个定义（对一张销售或退货事实表的一个聚合，带一个日期角色、从事实表按维表主键发出的维表连接和单表定义过滤条件）；\TrSeeded\ 个通过准入，\TrSeedFailed\ 个学习期为空。11 种变化按相同的类别施加在真实表上，整行复制、日期经 \code{date\_dim} 换算。每个定义的规范 SQL 充当智能体的学习 SQL，标准答案在其上加上区分列过滤。每种方法 \TrCondN\ 道计分题上的结果与合成数据一致：\system\ 在条件覆盖的变化下不给出错误答案，修复状态变更行（\TrCondRepairedTasks\ 道题），在其余破坏性变化下使定义失效，原因是变化触及学习期（多版本更正、缓慢变化维（类型 2）），或没有唯一的过滤能恢复粒度；按模式变更失效给出 \TrSchemaWrongModeled\ 个错误答案，表级测试产生 \TrTableNeeded\ 道正确失效与 \TrTableUnneeded\ 道误失效。以标准答案 SQL 作对照时，\system\ 还能修复多版本更正与缓慢变化维（类型 2），答对 \TrPairGold\ 道而不是 \TrPairCond\ 道，答错多出 \TrPairExtraWrong\ 道。}
