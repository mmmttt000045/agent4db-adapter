\subsection{\bt{Validity under data changes}{数据变化下的有效性}}
\label{sec:validity}
\bi{\emph{Paired replay (Q1).} The scenario runs of Section~\ref{sec:scenarios} leave each cell with the library its agents learned: \RpLibs\ libraries of 3--8 promoted definitions, \RpDefs\ in all, from three LLMs. We replay every library under every method on the same data. Each method gets its own middleware instance, admitted with the library's definitions and learning evidence; each of the \RpChanges\ changes (the ten scenarios of Table~\ref{tab:scenarios} plus a backup-copy change, Section~\ref{sec:repair-eval}) is applied from the same initial snapshot; and the scored questions of every affected definition are answered with the canonical SQL of whatever revision the method serves. This isolates maintenance from learning and from agent behavior. A question is \emph{correct}, \emph{served wrong} (the served revision answers incorrectly), or \emph{unavailable}; unavailability is \emph{needed} if the unmaintained definition would also have answered incorrectly.}
{\emph{配对回放（Q1）。}第~\ref{sec:scenarios} 节的场景实验在每组结束时留下该组智能体学到的定义库：\RpLibs\ 个库，各含 3--8 个已晋升定义，共 \RpDefs\ 个，来自 3 个大模型。我们在同一份数据上用每种方法回放每个库。每种方法各有一个中间层实例，以该库的定义和学习证据准入；\RpChanges\ 种变化（表~\ref{tab:scenarios} 的 10 个场景，外加一个备份副本变化，见第~\ref{sec:repair-eval} 节）都从同一初始快照施加；每个受影响定义的计分题，用该方法当时提供的修订的规范 SQL 作答。这把维护与学习、与智能体行为隔离开。每道题的结果为\emph{答对}、\emph{提供但答错}（提供的修订答错）或\emph{不可用}；若未经维护的定义同样会答错，则称该不可用为\emph{必要的}。}

\bi{Table~\ref{tab:replay} shows the result. Every revalidation method serves wrong answers only under the unit change, which no condition models; under the modeled changes they serve none, whereas schema-only maintenance serves \RpSchemaWrongModeled\ wrong answers there and revoke-on-write without relearning answers nothing. Condition-level maintenance, definition-level revalidation, and the generic cache give the same outcome on every question (\RpSameCondDef\%), so differences between them in end-to-end accuracy come from what agents learned, not from maintenance. Unavailability that was not needed is conservative rather than wrong: it arises mostly for return rate under duplicate loads and late keys, where numerator and denominator inflate together and the ratio happens to stay right although the grain condition is broken. In the controlled benchmark of Section~\ref{sec:cost}, all revalidation methods likewise record zero stale uses and zero false revocations, whereas schema-only maintenance returns stale definitions after the status-history break, 16--64 uses per pass across sharing levels, and revoke-on-write discards 5--22 still-valid revisions after benign appends.}
{表~\ref{tab:replay} 给出结果。各重验证方法只在任何条件都不刻画的单位变化下提供错误答案；在已建模的变化下一个也没有，而只看结构的维护在这些变化下提供了 \RpSchemaWrongModeled\ 个错误答案，不重新学习的写入即撤销则一题也答不了。条件级维护、定义级重验证与通用缓存在每道题上的结果都相同（\RpSameCondDef\%），因此它们在端到端正确率上的差别来自智能体学到的内容，而不是维护方式。不必要的不可用是保守而非错误：它主要出现在重复装载与迟到键下的退货率上，此时分子分母同步膨胀，比率碰巧仍然正确，但粒度条件确实被破坏了。在第~\ref{sec:cost} 节的受控实验中，各重验证方法同样为零过期使用、零误撤销；只看结构的维护在状态流水破坏后返回过期定义，各共享度下每轮 16--64 次；写入即撤销则在正常追加后丢弃 5--22 个仍然有效的修订。}
